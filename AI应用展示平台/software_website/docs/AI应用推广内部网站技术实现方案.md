# 软件部 AI 应用推广内部网站技术实现方案

## 一、技术路线

本项目一期采用轻量化静态网站方案建设，优先实现 AI 应用成果展示、智能体项目展示、典型案例沉淀、软件部 AI 能力介绍和定制化 Agent 需求入口。

整体技术路线为：

```text
静态前端页面 → 数据配置化渲染 → 内网静态部署 → 统一认证与后台管理 → 需求流转闭环
```

一期先完成可访问、可展示、可维护的网站版本；后续根据使用情况逐步扩展内容管理、权限控制、需求提交和数据统计能力。

## 二、技术栈

一期使用原生前端技术实现：

- HTML5：负责页面结构和内容组织。
- CSS3：负责页面视觉、布局、响应式适配和品牌风格。
- JavaScript：负责数据渲染、项目筛选、页面动效等轻量交互。
- 配置化数据文件：负责维护项目、指标、服务和能力等展示内容。
- 静态资源：存放公司 Logo、图片等页面素材。

当前不引入 Vue、React 等前端框架，也不引入数据库，减少构建、部署和维护成本。页面采用“静态 HTML + 配置化数据 + JavaScript 渲染”的方式，已经具备一定的数据驱动和组件化思路，后续如交互复杂度提升，可平滑迁移到 Vue 或 React。

## 三、页面实现

网站首页按照内部产品展示页方式设计，主要包含以下模块：

- 首页首屏：展示网站定位、公司 Logo、平台说明和需求入口。
- 核心成果：展示项目数量、上线应用、覆盖部门、提效成果等指标。
- 智能体项目：以卡片方式展示项目名称、状态、类型、适用部门和阶段成果。
- 成果与案例：按“业务痛点、解决方案、应用效果”沉淀典型案例。
- 定制化 Agent 服务：说明可定制方向、需求提交、评估流程和联系方式。
- 软件部 AI 能力：展示智能体开发、知识库问答、流程自动化、数据分析、系统集成和安全治理能力。

页面顶部使用 `images/companylogo.png` 作为公司品牌标识，整体视觉参考公司网页的产品服务风格，但内容以软件部 AI 应用成果和团队能力为主。

## 四、文件结构

当前项目采用简单静态文件结构：

```text
software_website
├─ frontend
│  ├─ index.html          页面结构
│  ├─ styles.css          页面样式
│  ├─ script.js           页面交互和数据渲染
│  └─ data
│     └─ site-data.js     页面展示数据
├─ images
│  └─ companylogo.png  公司 Logo
└─ 相关需求和方案文档
```

这种结构便于快速维护，也方便后续整体部署到内网服务器。

## 五、部署方案

开发和演示阶段可通过本地静态服务预览：

```powershell
.\start-intranet-preview.ps1
```

访问形式为：

```text
http://127.0.0.1:5174/index.html
http://开发电脑IP:5174/index.html
```

不建议直接双击打开 HTML 文件访问。若公司加密软件影响本地文件编码识别，直接打开静态 HTML 可能出现乱码；通过 HTTP 服务访问可以减少此类问题。

当前启动脚本使用 PowerShell 内置 HTTP 服务读取文件并返回响应，不再使用 `python -m http.server`。原因是公司加密软件环境下，Python 进程可能读取到 `%TSD-Header-###%` 开头的加密文件内容，导致浏览器显示密文。

该方式仅适合临时演示，不建议长期使用。正式使用建议部署到公司内网服务器，通过固定内网地址访问。

推荐部署方式：

- Nginx 静态站点。
- IIS 静态站点。
- 公司内部门户挂载。
- 公司私有云静态托管。

推荐访问形式：

```text
http://ai-apps.company.local
```

或：

```text
http://内网服务器IP/ai-apps/
```

## 六、访问控制

一期建议采用内网访问控制：

- 仅部署在公司内网环境。
- 不对公网开放。
- 公司 WiFi、同一网段或 VPN 环境下访问。
- 一期暂不考虑登录认证、SSO 或账号权限。
- 页面内容不展示高敏感业务数据。

后续如增加后台管理、详细数据或需求记录，可接入公司统一身份认证，例如 OA、LDAP、AD、SSO 或 VPN 访问控制，并增加角色权限和访问日志。

## 七、内容维护

一期已将部分核心展示内容配置化，例如项目、指标、服务和能力信息集中维护在 `frontend/data/site-data.js` 中。后续可继续扩展配置文件，例如：

```text
data
├─ projects.json
├─ cases.json
├─ metrics.json
└─ contacts.json
```

页面通过 JavaScript 读取数据并渲染，降低维护门槛。再后续可建设轻量后台，支持项目新增、状态更新、成果指标维护和动态发布。

## 八、需求承接

一期可先提供轻量需求入口：

- 邮箱。
- 固定联系人。
- 钉钉群。
- OA 流程链接。
- 表单链接。

需求提交建议包含：需求部门、联系人、业务场景、当前痛点、期望任务、涉及系统、用户范围、期望上线时间、成功指标和敏感数据说明。

后续可接入 OA 或工单系统，形成：

```text
提交需求 → 初步沟通 → 可行性评估 → 优先级判断 → 排期开发 → 试点上线 → 持续迭代
```

## 九、安全要求

网站建设和内容维护需满足以下要求：

- 不对公网开放。
- 涉及敏感内容必须脱敏。
- 不展示客户隐私、员工隐私和经营敏感数据。
- 成果数据使用可核验口径。
- 后续如建设后台，必须增加身份认证和权限控制。

## 十、后续演进

后续可按以下方向迭代：

- 增加项目详情页。
- 增加项目搜索和筛选。
- 增加成果数据看板。
- 增加最新动态发布。
- 增加需求提交表单。
- 增加后台内容管理。
- 接入公司统一身份认证。
- 接入 OA、工单、知识库或项目管理系统。
- 当页面状态管理、权限、表单和路由复杂度提升时，再升级为 Vue 或 React 前端工程。

## 十一、结论

本项目一期采用 HTML、CSS、JavaScript 和配置化数据文件实现，技术简单、上线快、维护成本低，适合先完成内部展示和推广。

正式使用时建议部署到公司内网服务器，避免依赖个人电脑和临时网络环境。后续可逐步演进为具备内容管理、权限控制、需求流转和数据统计能力的内部 AI 应用推广平台。
