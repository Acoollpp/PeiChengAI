# 软件部 AI 应用中心首页四模块信息架构调整方案

## 一、调整目标

当前网站雏形已经形成，但导航和内容模块还存在一定重叠：

- “智能体项目”和“成果案例”边界不够清晰。
- “项目案例”作为一级导航名称略显普通，可进一步提升表达质感。
- “定制服务”“提交需求”“联系软件部 AI 对接人”属于同一类需求承接动作，应合并表达。
- “团队概况”下拉内容需要更聚焦，避免过多细项。

本次调整目标是将首页收敛为四个清晰模块：

```text
首页
AI 应用案例
需求对接
团队概况
```

其中，“AI 应用案例”替代原“项目案例”，用于统一承载智能体项目、项目状态和典型案例等内容；“团队概况”用于承载团队能力和技术方向。

## 二、首页模块

### 2.1 一级导航名称

```text
首页
```

### 2.2 模块定位

首页作为网站入口，用于快速说明网站定位、软件部 AI 应用建设方向、核心成果概况和主要访问入口。

### 2.3 建议展示内容

- 网站名称：软件部 AI 应用中心。
- 网站定位：公司内部 AI 应用展示与需求承接入口。
- 首屏能力图：展示知识、流程、数据、文档等 AI 应用方向。
- 企业使命与核心价值观。
- 核心指标概览：智能体项目、已上线应用、覆盖部门、典型提效。
- 快捷入口：AI 应用案例、需求对接、团队概况。

### 2.4 下拉菜单建议

首页不设置下拉菜单，点击后回到页面首屏。

## 三、AI 应用案例模块

### 3.1 一级导航名称建议

原名称：

```text
项目案例
```

建议调整为：

```text
AI 应用案例
```

备选名称：

- 智能体成果
- AI 成果展厅
- 应用成果库
- 智能体成果库

推荐使用“AI 应用案例”，原因是比“项目案例”更贴近网站主题，也能同时覆盖智能体项目、应用状态和典型案例。

### 3.2 模块定位

该模块用于集中展示软件部已经建设、正在试点和开发中的 AI 应用与智能体项目，是网站最核心的成果展示区域。

“项目”和“案例”不再拆成两个一级模块，而是在同一个模块中按项目状态分类展示。

### 3.3 下拉菜单结构

建议下拉菜单不再使用“智能体项目 / 项目状态 / 典型案例”这种不同维度混合的结构，而是统一按项目状态分类：

```text
AI 应用案例
├─ 已上线
├─ 试点中
└─ 开发中
```

### 3.4 分类说明

| 分类 | 说明 |
|---|---|
| 已上线 | 已正式投入使用，可提供访问入口、使用部门、应用效果和负责人 |
| 试点中 | 正在部分部门试用，可展示试点范围、当前反馈、后续推广计划 |
| 开发中 | 正在建设或联调，可展示目标、进度、预计上线时间和对接人 |

### 3.5 页面内容建议

每个项目卡片建议展示：

- 项目名称。
- 项目状态。
- 应用类型。
- 适用部门。
- 解决问题。
- 阶段成果。
- 是否可申请试用或定制。
- 负责人或对接方式。

### 3.6 典型案例的处理方式

典型案例不再作为单独一级导航或独立模块，而是作为项目详情或项目卡片中的增强内容。

建议展示方式：

```text
项目卡片
├─ 项目简介
├─ 阶段成果
└─ 典型案例摘要
```

或在“已上线”分类中增加“典型案例”标签，用于突出成熟项目。

## 四、需求对接模块

### 4.1 一级导航名称

```text
需求对接
```

### 4.2 模块定位

需求对接模块用于承接其他部门的 AI 应用需求，帮助业务部门明确如何提交需求、提交哪些信息、由谁负责对接。

### 4.3 下拉菜单结构

建议只保留两个功能：

```text
需求对接
├─ 需求提交
└─ 联系我们
```

### 4.4 需求提交

用于引导业务部门提交定制化 Agent 或 AI 应用需求。

建议收集字段：

- 申请部门。
- 联系人。
- 业务场景。
- 当前痛点。
- 希望 AI 完成的任务。
- 涉及系统或数据。
- 用户范围。
- 期望上线时间。
- 预期效果。

### 4.5 联系我们

用于提供软件部 AI 应用对接方式。

建议展示：

- 软件部 AI 对接人。
- 邮箱。
- 电话或内线。
- 钉钉群 / 企业微信 / OA 入口。
- 需求咨询说明。

### 4.6 页面表达建议

该模块不再强调“定制服务”这个概念，而是用更直接的“需求提交”和“联系我们”完成转化。

## 五、团队概况模块

### 5.1 一级导航名称

```text
团队概况
```

### 5.2 模块定位

团队概况模块用于说明软件部为什么能承接 AI 应用建设，重点展示团队能力和技术方向。

### 5.3 下拉菜单结构

建议精简为两个功能：

```text
团队概况
├─ 团队能力
└─ 技术方向
```

### 5.4 团队能力

展示软件部 AI 应用团队的综合交付能力。

建议包含：

- 需求分析能力。
- 产品设计能力。
- 前后端开发能力。
- 智能体开发能力。
- 系统集成能力。
- 上线运维能力。
- 安全治理能力。

### 5.5 技术方向

展示当前重点 AI 技术方向。

建议包含：

- 智能体 Agent。
- 知识库问答 / RAG。
- 流程自动化。
- 数据分析。
- 文档生成。
- 工具调用。
- 权限控制与日志审计。

```text
首页

团队概况
```

下拉结构为：

```text
首页

AI 应用案例
├─ 已上线
├─ 试点中
└─ 开发中

需求对接
├─ 需求提交
└─ 联系我们

团队概况
├─ 团队能力
└─ 技术方向
```

## 七、首页四模块结构

首页页面内容建议对应四个模块：

```text
首页
├─ 首屏介绍
│  ├─ 网站定位
│  ├─ AI 能力示意图
│  ├─ 企业使命与核心价值观
│  └─ 核心指标
│
├─ AI 应用案例
│  ├─ 已上线项目
│  ├─ 试点中项目
│  ├─ 开发中项目
│  └─ 典型案例摘要
│
├─ 需求对接
│  ├─ 需求提交
│  └─ 联系我们
│
└─ 团队概况
   ├─ 团队能力
   └─ 技术方向
```

## 八、后续页面改动建议

后续代码调整时建议按以下顺序实施：

1. 顶部导航改为“首页 / AI 应用案例 / 需求对接 / 团队概况”。
2. “AI 应用案例”下拉改为“已上线 / 试点中 / 开发中”。
3. 将项目列表筛选与下拉菜单分类保持一致。
4. 将典型案例合并到 AI 应用案例模块，不再单独占一级导航。
5. 将需求模块精简为“需求提交 / 联系我们”。
6. 将团队概况模块精简为“团队能力 / 技术方向”。
7. 同步调整首页快捷入口和页面锚点。
