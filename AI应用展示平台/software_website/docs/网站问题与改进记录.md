# 软件部 AI 应用推广内部网站问题与改进记录

## 一、当前问题

### 1. HTML 文件直接打开后乱码

现象：直接双击打开 `frontend/index.html` 时，页面可能出现中文乱码。

初步判断：公司加密软件或本地文件打开策略可能影响静态 HTML 的编码识别。

处理方案：

- 不建议通过双击 HTML 文件访问网站。
- 使用本地或内网 HTTP 服务访问。
- 开发和演示阶段使用以下脚本启动。脚本已改为 PowerShell 内置 HTTP 服务，不再使用 Python 静态服务器，因为在当前公司加密软件环境下，Python 进程可能读到 `%TSD-Header` 开头的加密文件内容。

```powershell
.\start-intranet-preview.ps1
```

访问地址：

```text
http://127.0.0.1:5174/index.html
http://本机内网IP:5174/index.html
```

说明：

- 用户原记录中的 `172.0.0.1` 不是标准本机回环地址；本机地址应使用 `127.0.0.1`，同网段访问应使用电脑实际内网 IP。
- 如果浏览器页面开头显示 `%TSD-Header-###%`，说明 HTTP 服务读到的是加密文件内容，不是普通编码乱码。应停止旧的 Python 服务，重新使用 `start-intranet-preview.ps1` 启动。

### 2. 外接屏正常，笔记本屏乱行

现象：页面在外接显示屏上排版正常，拖到笔记本屏幕后出现换行、挤压或布局错乱。

原因：部分页面布局存在固定宽度、固定列数或较大的最小宽度，不适配不同屏幕宽度和缩放比例。

处理方案：

- 页面布局优先使用百分比、`clamp()`、`minmax()`、`auto-fit` 等响应式写法。
- 首屏、导航、项目卡片、成果卡片、服务卡片改为弹性网格。
- 针对 1380px、1180px、760px 等宽度设置响应式断点。
- 避免核心内容区域依赖固定像素宽度。

### 3. 网站访问权限

当前目标：公司 WiFi 网络环境或同一内网网段可访问，不考虑账号密码、登录认证和公网发布。

访问策略：

- 不使用公网域名。
- 不开放互联网访问。
- 不部署为 `xxx.com` 公开站点。
- 不考虑 ICP 备案。
- 暂不接入统一认证、SSO、OA 登录或权限系统。

后续如改为公网访问或绑定公网域名，应重新评估 ICP 备案、安全合规和访问权限要求。
