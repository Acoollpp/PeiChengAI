# 软件部 AI 应用推广内部网站建设立项书

## 一、项目概况

### 1.1 项目名称

软件部 AI 应用推广内部网站建设项目

### 1.2 项目发起部门

软件部

### 1.3 项目建设周期

建议建设周期为 5 至 7 周，包含需求确认、原型设计、网站开发、内容录入、内网部署和试运行推广。

### 1.4 项目建设方式

项目采用轻量化建设方式，优先完成面向公司内部访问的展示型网站，并预留后续内容维护、权限控制、需求流转和数据统计能力扩展空间。

## 二、立项背景

随着公司内部数字化建设和 AI 应用探索持续推进，软件部已围绕知识问答、流程自动化、数据分析、文档生成、研发辅助等方向开展多个 AI 应用和智能体项目，部分项目已进入开发、试点或上线运行阶段。

目前相关成果主要通过会议汇报、项目群、即时沟通或零散文档进行传播，存在信息分散、推广效率低、成果沉淀不足、业务部门了解不充分等问题。其他部门即使存在 AI 应用需求，也缺少统一入口了解现有能力、参考已有案例并提出定制化 Agent 建设需求。

因此，有必要建设一个公司内网可访问的 AI 应用推广内部网站，作为软件部 AI 应用成果展示、案例沉淀、能力推广和需求承接的统一窗口。

## 三、立项必要性

### 3.1 提升 AI 应用推广效率

通过统一网站集中展示软件部 AI 应用方向、智能体项目、应用成效和典型案例，减少重复介绍和点对点沟通成本，让公司各部门能够快速了解现有 AI 能力。

### 3.2 促进跨部门需求对接

网站提供定制化 Agent 需求入口，引导业务部门按照统一格式描述业务场景、流程痛点、预期目标和涉及系统，便于软件部进行初步评估、优先级判断和后续排期。

### 3.3 沉淀项目成果和能力资产

将已上线、试点中和开发中的 AI 应用项目进行长期沉淀，形成项目清单、能力说明、应用场景、效果数据和典型案例，为后续复用、推广和汇报提供依据。

### 3.4 支撑公司 AI 应用落地

通过展示可落地、可参考、可复用的内部案例，帮助业务部门理解 AI 能解决哪些具体问题，推动 AI 应用从技术探索转化为业务价值。

## 四、项目目标

建设一个仅面向公司内部网络访问的网站，实现以下目标：

1. 集中展示软件部 AI 应用方向、团队能力和阶段成果。
2. 列出正在开发、试点中、已上线和持续迭代的智能体项目。
3. 展示各智能体项目的应用场景、核心功能、适用部门和阶段成果。
4. 沉淀 AI 应用推广成效、典型案例和可复用经验。
5. 为其他部门提供定制化 Agent 需求提交或咨询入口。
6. 形成软件部 AI 应用成果展示、需求承接和内部推广的长期阵地。

## 五、项目定位

本项目定位为公司内部 AI 应用展示与需求承接平台。

网站不作为公网官网，不面向互联网开放；不承载智能体运行平台本身；不替代 OA、工单系统、项目管理系统或知识库系统。网站主要承担成果展示、能力介绍、案例沉淀、需求引导和内部推广作用。

## 六、建设范围

### 6.1 本期建设范围

本期重点建设展示和需求入口能力，包括：

- 首页：展示网站定位、核心成果、重点项目、应用场景和需求入口。
- 智能体项目展示：展示软件部正在开发、试点中和已上线的 AI 应用项目。
- 项目详情：展示单个项目的背景、目标、核心功能、适用场景、阶段成果和接入方式。
- 成果与案例：展示上线项目数量、覆盖部门、使用情况、提效数据、典型案例和部门反馈。
- 定制化 Agent 服务：说明可定制方向、需求提交信息、评估流程和对接方式。
- 软件部 AI 能力介绍：展示智能体开发、知识库问答、流程自动化、数据分析、文档生成、系统集成、安全治理等能力。

### 6.2 暂不纳入本期范围

- 不建设完整项目管理系统。
- 不直接承载智能体运行平台。
- 不替代公司 OA、工单、知识库或研发管理系统。
- 不处理高敏感业务数据。
- 不面向公网发布。

## 七、目标用户

| 用户角色 | 主要用途 |
|---|---|
| 公司管理层 | 了解软件部 AI 应用建设进展、阶段成果和推广价值 |
| 各业务部门 | 查看可用 AI 应用，参考典型案例，提出定制化 Agent 需求 |
| 软件部 | 展示项目成果，沉淀案例资料，统一承接业务需求 |
| 项目相关人员 | 查看项目介绍、状态、负责人、接入方式和更新记录 |

## 八、主要建设内容

### 8.1 首页

首页用于快速说明网站定位和软件部 AI 应用整体情况，建议展示：

- 软件部 AI 应用推广定位。
- 当前智能体项目数量、上线项目数量、覆盖部门数量和典型提效成果。
- 重点推荐项目。
- 常见应用场景入口。
- 定制化 Agent 需求入口。
- 最新项目动态。

### 8.2 智能体项目展示

集中展示软件部正在开发和已经落地的智能体项目，建议包含：

- 项目名称。
- 项目状态：规划中、开发中、试点中、已上线、持续迭代。
- 应用类型：知识问答、流程自动化、数据分析、文档生成、研发辅助等。
- 适用部门。
- 核心功能。
- 阶段成果。
- 负责人或对接人。

### 8.3 项目详情

每个智能体项目单独展示详情，建议包含：

- 项目简介。
- 建设背景。
- 解决的问题。
- 核心功能。
- 适用场景。
- 使用对象。
- 当前状态。
- 阶段成果。
- 使用或接入方式。
- 项目负责人和联系方式。
- 更新记录。

### 8.4 成果与案例

展示软件部 AI 应用建设成果，建议包含：

- 已上线项目数量。
- 覆盖部门数量。
- 使用人数或使用次数。
- 提效数据。
- 典型应用案例。
- 部门反馈。
- 内部汇报或认可情况。

相关数据应以公司内部可核验数据为准，涉及敏感信息时需脱敏展示。

### 8.5 定制化 Agent 需求入口

为其他部门提供 AI 应用需求提交入口，建议收集：

- 需求部门。
- 需求联系人。
- 业务场景。
- 当前流程痛点。
- 希望 AI 完成的任务。
- 涉及系统或数据来源。
- 用户范围。
- 期望上线时间。
- 预期效果或成功指标。
- 是否涉及敏感数据。

软件部收到需求后，可进行初步沟通、可行性评估、优先级判断和后续排期。

### 8.6 软件部 AI 能力介绍

展示软件部在 AI 应用建设方面的能力，包括：

- 智能体开发。
- 知识库问答与 RAG 能力。
- 流程自动化。
- 数据分析。
- 文档生成。
- 研发辅助。
- 企业系统集成。
- 权限、安全、日志和评测治理。

## 九、网站架构

软件部 AI 应用推广内部网站

├─ 首页  
│　├─ 网站定位　# 展示软件部 AI 应用中心的定位和用途  
│　├─ AI 能力示意图　# 展示知识、流程、数据、文档等应用方向  
│　├─ 企业使命与核心价值观　# 展示企业使命和价值观  
│　├─ 核心指标　# 展示智能体项目、上线应用、覆盖部门和典型提效  
│　└─ 快捷入口　# 跳转 AI 应用案例、需求对接、团队概况  
│
├─ AI 应用案例  
│　├─ 已上线　# 展示已正式使用的智能体应用和访问入口  
│　├─ 试点中　# 展示试点范围、反馈情况和推广计划  
│　├─ 开发中　# 展示建设目标、开发进展和预计上线时间  
│　└─ 典型案例　# 按业务痛点、解决方案、应用效果展示案例  
│ 
├─ 需求对接  
│　├─ 需求提交　# 填写部门、场景、痛点、目标、系统和联系人  
│　└─ 联系我们　# 提供软件部 AI 对接人、邮箱、群组或 OA 入口  
│
└─ 团队概况  
　　├─ 团队能力　# 展示需求分析、产品设计、开发交付和运维支持能力  
　　└─ 技术方向　# 展示 Agent、RAG、流程自动化、数据分析、工具调用和安全治理方向  

## 十、实施计划

| 阶段 | 主要工作 | 预计周期 | 交付物 |
|---|---|---:|---|
| 需求确认与内容盘点 | 明确网站目标、访问范围、首批项目清单、内容字段和需求入口方式 | 1 周 | 项目内容清单、页面结构、需求字段 |
| 原型设计 | 完成首页、项目列表、项目详情、成果案例、需求提交页面原型 | 1 周 | 网站原型、页面说明、修改意见 |
| 网站开发与内容录入 | 完成页面开发、内容配置、项目资料录入和基础交互 | 2-3 周 | 可访问网站版本、内容维护说明 |
| 内网部署与试运行 | 完成内网部署、访问控制、部门试用和反馈收集 | 1 周 | 试运行版本、反馈记录 |
| 正式推广与持续维护 | 面向公司内部发布推广通知，持续更新项目和需求记录 | 持续进行 | 推广材料、运营维护台账 |

## 十一、验收标准

### 11.1 功能验收

1. 公司内部网络可正常访问网站。
2. 首页、项目列表、项目详情、成果案例、定制化服务等页面可正常浏览。
3. 智能体项目可按状态或类型进行展示。
4. 业务部门能够找到需求提交或联系入口。
5. 网站内容可由指定人员进行维护和更新。

### 11.2 内容验收

1. 首批智能体项目已完成录入。
2. 每个项目具备名称、简介、状态、适用场景、成果、负责人等关键信息。
3. 成果数据具备明确统计口径。
4. 涉及敏感内容已完成脱敏处理。

### 11.3 安全验收

1. 网站仅限公司内部网络或 VPN 环境访问。
2. 网站不对公网开放。
3. 管理维护入口具备访问控制。
4. 敏感信息不在普通展示页面泄露。
5. 符合公司内部信息安全要求。

## 十二、资源需求

### 12.1 人员资源

| 角色 | 主要职责 |
|---|---|
| 项目负责人 | 统筹项目目标、建设节奏、跨部门协调和验收 |
| 产品或内容负责人 | 梳理网站结构、项目资料、页面文案和展示口径 |
| 前端开发人员 | 完成页面开发、交互实现和适配优化 |
| 部署维护人员 | 完成内网部署、访问控制和后续技术维护 |
| 项目对接人 | 提供各智能体项目介绍、成果数据和更新信息 |

### 12.2 内容资源

- 首批展示的智能体项目清单。
- 各项目简介、负责人、状态、应用场景和接入方式。
- 已上线项目的使用数据、提效数据和典型案例。
- 软件部 AI 能力介绍和服务边界说明。
- 需求提交表单或对接流程说明。

## 十三、风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 项目信息更新不及时 | 网站可信度下降 | 指定内容负责人，建立固定更新机制 |
| 成果数据口径不统一 | 展示价值不清晰 | 建立统一指标口径和数据来源说明 |
| 业务部门需求过于发散 | 软件部承接压力增加 | 建立需求初筛、优先级和排期机制 |
| 涉敏信息展示不当 | 产生信息安全风险 | 上线前进行脱敏审核和权限检查 |
| 网站只展示不转化 | 推广效果有限 | 首页突出需求入口，并建立需求跟进台账 |
| 后续维护成本过高 | 平台难以持续运营 | 本期采用轻量化内容维护，后续按需建设后台 |

## 十四、运营维护机制

### 14.1 角色分工

| 角色 | 职责 |
|---|---|
| 网站负责人 | 统筹网站建设、内容规划和推广节奏 |
| 项目负责人 | 维护对应智能体项目介绍和成果数据 |
| 内容维护人 | 更新页面内容、项目状态和最新动态 |
| 技术维护人 | 负责部署、访问控制、故障处理和功能迭代 |
| 需求对接人 | 跟进业务部门提交的定制化 Agent 需求 |

### 14.2 更新机制

- 项目状态建议每两周更新一次。
- 成果数据建议每月更新一次。
- 重大项目上线、试点完成或形成典型案例时应及时发布动态。
- 定制化需求应形成台账，定期同步处理状态。

## 十五、待确认事项

1. 网站正式名称。
2. 首批展示的智能体项目清单。
3. 每个项目的负责人、对接人和成果数据。
4. 需求提交方式采用表单、邮箱、OA 流程还是工单系统。
5. 网站部署环境和访问控制方式。
6. 是否接入公司统一身份认证。
7. 后续内容维护责任人和更新周期。

## 十六、立项结论

本项目建设目标明确、范围可控、实施周期较短，能够有效提升软件部 AI 应用成果展示、跨部门推广和定制化需求承接效率。项目建成后，将形成公司内部 AI 应用成果展示和业务需求转化的统一入口，为后续智能体项目推广、能力复用和持续运营提供基础支撑。

建议正式立项建设“软件部 AI 应用推广内部网站”，并由软件部牵头推进需求确认、内容盘点、网站开发、内网部署和后续运营维护工作。
