# 领域文档

本文件说明工程技能在探索代码库时如何读取和使用本仓库的领域文档。

## 探索代码前读取

- 读取仓库根目录的 `CONTEXT.md`。
- 如果根目录存在 `CONTEXT-MAP.md`，则按照其中的指引读取与当前任务相关的 `CONTEXT.md`。
- 读取 `docs/adr/` 中与当前改动范围有关的架构决策记录。

如果这些文件或目录尚不存在，静默继续，不将缺失视为错误，也不提前建议创建。`/domain-modeling` 技能会在领域术语或架构决策真正确定后按需创建它们。

## 文件布局

本仓库采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
│       ├── 0001-示例决策.md
│       └── 0002-示例决策.md
└── src/
```

`CONTEXT.md` 保存领域词汇、核心概念及其关系，`docs/adr/` 保存已经作出的架构决策。

## 使用领域词汇

在 Issue 标题、重构建议、假设和测试名称中提到领域概念时，应使用 `CONTEXT.md` 定义的术语，不要改用其明确排除的同义词。

如果需要的概念尚未进入词汇表，应先判断是否使用了项目中不存在的语言；如果确实存在领域缺口，则记录下来，后续通过 `/domain-modeling` 处理。

## 标记 ADR 冲突

如果输出内容与现有 ADR 冲突，必须明确指出，不能静默覆盖。例如：

> 与 ADR-0007 的既有决策冲突，但由于新的约束条件，值得重新讨论。
