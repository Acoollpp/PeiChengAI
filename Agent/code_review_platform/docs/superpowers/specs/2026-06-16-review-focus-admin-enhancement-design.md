# 重点审查方向后台增强设计

## 背景

当前“重点审查方向”后台页面同时上下展示“方向库”和“用户输入统计”。方向库已经可以由管理员维护，也可以从用户输入统计中沉淀条目；但 Electron 客户端暂时只有手写“重点审查方向”的输入框，还没有从方向库选择方向的能力。

本期只增强后台管理和沉淀能力，不改客户端方向选择。方向库继续作为管理员沉淀库，后续在沉淀成熟后再接入客户端选择。

## 目标

1. “重点审查方向”页面改成两个 Tab：`方向库`、`用户输入统计`，点击切换展示。
2. 方向库支持多部门归属。
3. 方向库支持按关键词、部门、启停状态搜索。
4. 用户输入统计增加“是否已使用”状态，由管理员手动标记。
5. 用户输入统计支持按关键词、部门、使用状态搜索。
6. 用户输入统计支持导出 Excel，导出当前筛选结果。
7. 原“沉淀为方向”按钮文案改为“沉淀”。
8. 新增数据库表和字段必须添加中文备注，说明字段用途。

## 非目标

1. 本期不改 Electron 客户端，不提供方向库下拉或选择功能。
2. 本期不做 AI 自动聚类、自动总结或自动写入 Skill。
3. 本期不做复杂工作流状态，例如“待处理 / 已处理 / 已沉淀 / 忽略”等多状态。
4. 本期不改变用户提交审查任务时自由手写重点方向的行为。

## 当前方向库作用

当前方向库的作用是后台沉淀和管理：

- 管理员可以维护正式方向条目。
- 管理员可以从用户手写输入统计中挑选高频内容，沉淀为方向库条目。
- 后端任务记录已经有 `focus_direction_id` 和 `focus_direction_snapshot` 字段，为后续客户端选择方向库预留。
- 但客户端现在不会读取方向库，也不会让普通用户选择方向库条目。

因此，本期完成后，方向库仍是管理员沉淀库；后续客户端接入时，可以读取“全局 + 用户所属部门启用方向”供用户选择。

## 页面设计

页面顶部保留：

- 页面标题：`重点审查方向`
- 页面说明：`管理方向库条目，并将用户常用输入沉淀为可复用方向。`
- `新增方向` 按钮

标题区域下方增加 Tab：

- `方向库`
- `用户输入统计`

两个模块不再上下同时显示，只显示当前选中的 Tab 内容。

### 方向库 Tab

筛选区：

- 关键词输入框：按标题、内容模糊搜索。
- 部门筛选：支持全部、全局、指定部门。
- 状态筛选：全部、启用、停用。
- 搜索和重置按钮。

表格列：

- 标题
- 内容
- 部门
- 状态
- 使用次数
- 操作

部门展示规则：

- 无部门归属：显示 `全局`。
- 一个部门：显示部门名称。
- 多个部门：显示 `部门A、部门B`，必要时用 tooltip 或折叠展示完整列表。

操作：

- `编辑`
- `启用` / `停用`
- `删除`

新增 / 编辑弹窗：

- 标题
- 内容
- 部门多选
- 是否启用

部门归属语义：

- 不选择任何部门表示全局方向，所有部门适用。
- 选择一个或多个部门表示仅归属这些部门。
- 保留“空部门 = 全局方向”的现有语义。

### 用户输入统计 Tab

筛选区：

- 关键词输入框：按用户输入内容模糊搜索。
- 部门筛选：支持全部、全局、指定部门。
- 使用状态筛选：全部、已使用、未使用。
- 搜索和重置按钮。
- `导出 Excel` 按钮。

表格列：

- 内容
- 使用次数
- 涉及部门
- 最新使用时间
- 使用状态
- 操作

使用状态：

- `未使用`
- `已使用`

操作：

- `沉淀`：打开新增方向弹窗，预填标题和内容。
- `标记已使用` / `标记未使用`：管理员手动切换该统计项的使用状态。

“是否已使用”的定义：

- 由管理员手动标记。
- 与“沉淀”操作不自动绑定。
- 管理员可以先导出给 AI 处理，再批量或逐条标记为已使用。

## 后端设计

### 方向库多部门归属

新增关联表 `review_focus_direction_department`，表示方向和部门的多对多关系。

字段建议：

- `id`: 主键。中文备注：`重点审查方向与部门关联记录ID。`
- `direction_id`: 方向 ID。中文备注：`关联的重点审查方向ID。`
- `department_id`: 部门 ID。中文备注：`关联的部门ID，表示该方向适用于该部门。`
- `created_at`: 创建时间。中文备注：`关联记录创建时间。`

约束：

- `direction_id + department_id` 唯一，避免重复关联。
- 删除方向或部门时应符合现有业务语义。部门已有关联时仍不允许直接删除，建议继续停用部门。

兼容迁移：

- 保留现有 `review_focus_direction.department_id` 字段作为弃用兼容字段，本期不删除该字段。
- 迁移时将已有非空 `department_id` 写入新关联表。
- 新接口和新前端以 `review_focus_direction_department` 关联表为准，不再依赖旧 `department_id` 判断方向归属。
- 创建或更新方向时，为兼容旧字段：
  - 未选择部门：旧 `department_id` 写入 `null`。
  - 只选择一个部门：旧 `department_id` 写入该部门 ID。
  - 选择多个部门：旧 `department_id` 写入 `null`。
- 部门删除保护必须检查新关联表，避免已关联方向的部门被删除。

### 用户输入统计使用状态

新增表 `review_focus_direction_usage_state`，记录统计项的人工使用状态。

字段建议：

- `id`: 主键。中文备注：`用户输入统计使用状态记录ID。`
- `normalized_content`: 规范化后的用户输入内容。中文备注：`规范化后的重点审查方向内容，用于和统计聚合结果匹配。`
- `is_used`: 是否已使用。中文备注：`管理员是否已处理或使用该用户输入统计项。`
- `updated_by_user_id`: 更新人 ID。中文备注：`最后一次标记使用状态的管理员用户ID。`
- `updated_at`: 更新时间。中文备注：`使用状态最后更新时间。`
- `created_at`: 创建时间。中文备注：`使用状态记录创建时间。`

约束：

- `normalized_content` 唯一。
- `is_used` 默认 `false`。

统计生成逻辑：

- 继续从 `review_task.focus_direction_snapshot` 聚合。
- 对内容做和现有接口一致的规范化：trim，并将连续空白合并为一个空格。
- 聚合后左关联 `review_focus_direction_usage_state`，返回 `is_used`。
- 若没有状态记录，默认 `is_used = false`。

### 数据库备注要求

本期所有新增表和字段都必须添加中文备注。

Alembic 迁移中应使用数据库 comment 能力：

- 新表使用表备注说明用途。
- 新字段使用字段备注说明用途。
- 索引和约束名称保持可读。

如果受 ORM 或迁移工具限制，必须在迁移脚本中显式执行 comment SQL，确保 PostgreSQL 中能看到中文说明。

## API 设计

### 方向库列表

`GET /api/v1/review-focus-directions`

新增查询参数：

- `search`: 可选，按标题、内容模糊搜索。
- `department_id`: 可选，指定部门 ID。
- `department_scope`: 可选，`all | global | department`。
- `is_active`: 可选，`true | false`。
- `skip`
- `limit`

返回字段调整：

- 保留现有字段。
- 新增 `departments: DepartmentPublic[]` 或 `department_ids: string[]` + `department_names: string[]`。
- 为兼容旧前端，可短期保留 `department_id`、`department_name`，但新页面使用多部门字段。

### 创建方向

`POST /api/v1/review-focus-directions`

请求字段：

- `title`
- `content`
- `department_ids`: 可选数组；创建时省略或传空数组都表示全局。
- `is_active`

### 更新方向

`PATCH /api/v1/review-focus-directions/{direction_id}`

请求字段：

- `title`
- `content`
- `department_ids`
- `is_active`

更新 `department_ids` 时整体替换该方向的部门关联；PATCH 中省略 `department_ids` 表示不修改部门归属，传空数组表示改为全局方向。

### 用户输入统计列表

`GET /api/v1/review-focus-directions/usage-stats`

新增查询参数：

- `search`: 可选，按内容模糊搜索。
- `department_id`: 可选，按涉及部门筛选。
- `department_scope`: 可选，`all | global | department`。
- `is_used`: 可选，`true | false`。

返回字段：

- `content`
- `usage_count`
- `latest_used_at`
- `departments`
- `is_used`

### 标记统计使用状态

新增接口：

`PATCH /api/v1/review-focus-directions/usage-stats/state`

请求字段：

- `content`: 原始统计内容。
- `is_used`: 目标状态。

后端对 `content` 做规范化后写入 `review_focus_direction_usage_state`。

### 导出 Excel

新增接口：

`GET /api/v1/review-focus-directions/usage-stats/export`

查询参数与统计列表一致，导出当前筛选结果。

返回：

- `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- 文件名：`重点审查方向用户输入统计_YYYYMMDD_HHmmss.xlsx`

Excel 字段：

- 内容
- 使用次数
- 涉及部门
- 最新使用时间
- 是否已使用

## 前端设计

### Tab 状态

页面内部维护 `activeTab`：

- 默认 `方向库`。
- 点击 Tab 切换内容。
- 切换 Tab 不丢失各自筛选条件。

### 查询状态

方向库查询 key 包含：

- `search`
- `department_scope`
- `department_id`
- `is_active`
- `skip`
- `limit`

用户输入统计查询 key 包含：

- `search`
- `department_scope`
- `department_id`
- `is_used`

状态变更后需要刷新对应查询：

- 新增 / 编辑 / 删除 / 启停方向：刷新方向库。
- 沉淀：刷新方向库，可保留用户输入统计。
- 标记已使用 / 未使用：刷新用户输入统计。

### 部门多选控件

新增 `DepartmentMultiSelect`，避免破坏已有单部门选择控件的调用方。

要求：

- 支持清空选择，清空表示全局。
- 支持多选部门。
- 显示已选部门名称。
- 表单提交时输出 `department_ids: string[]`。

### 导出 Excel

点击 `导出 Excel`：

- 使用当前统计筛选条件请求导出接口。
- 浏览器下载返回的 Excel 文件。
- 下载失败时显示中文错误提示。

## 错误处理

所有用户可见错误提示使用中文：

- 部门不存在：`部门不存在。`
- 方向不存在：`重点审查方向不存在。`
- 用户输入内容为空：`用户输入内容不能为空。`
- 导出失败：`导出失败，请稍后重试。`
- 标记状态失败：`使用状态更新失败，请稍后重试。`

### 后端测试

新增或更新测试覆盖：

1. 管理员可创建多部门方向。
2. 空 `department_ids` 创建全局方向。
3. 方向库列表可按关键词搜索。
4. 方向库列表可按部门筛选。
5. 方向库列表可按启停状态筛选。

7. 管理员可标记统计项为已使用 / 未使用。

9. 用户输入统计 Excel 导出包含当前筛选结果。
10. 普通用户不能访问方向库管理、统计标记和导出接口。

### 前端测试

新增或更新测试覆盖：

1. 页面默认展示 `方向库` Tab。

3. 方向库筛选条件会传给 API。
4. 用户输入统计筛选条件会传给 API。
5. 新增 / 编辑方向支持多部门选择。

## 验收标准

1. 页面改为两个 Tab，不再上下同时展示两个模块。
2. 方向库可维护全局方向和多部门方向。
3. 方向库可按关键词、部门、启停状态搜索。
4. 用户输入统计有“是否已使用”列。
5. 管理员可手动标记统计项已使用或未使用。
6. 用户输入统计可按关键词、部门、使用状态搜索。
7. 用户输入统计可导出当前筛选结果为 Excel。
8. “沉淀为方向”按钮文案改为“沉淀”。
9. 新增数据库表和字段在 PostgreSQL 中有中文备注。
10. 不改变 Electron 客户端现有重点审查方向手写输入行为。
