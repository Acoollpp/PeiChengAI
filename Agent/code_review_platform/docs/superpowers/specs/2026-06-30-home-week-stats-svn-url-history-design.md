# 首页周统计与客户端 SVN 地址历史设计

## 背景

Web 首页任务统计当前只有今日、昨日、累计三个维度，管理员可见的报告生成数使用柱状图展示，用户多时柱子过多。Electron 客户端任务表单中的 SVN 地址需要降低重复输入成本，最近使用的地址应可快速选择。

## 目标

- Web 任务统计增加本周、上周两个查询维度。
- 将 Web「报告生成数」从柱状图改为圆形比例图，显示每个用户报告数占当前列表总报告数的比例。
- Electron 任务表单 SVN 地址输入框聚焦时显示最近三条成功提交过的 SVN 地址，点击可回填。

## 非目标

- 不改后端统计接口结构，不新增数据库字段。
- 不改反馈统计页。
- 不保存 SVN 账号、密码或版本号历史。
- 不跨设备同步 SVN 地址历史。

## 推荐方案

Web 沿用现有 `GET /api/v1/review-tasks/stats?range=...`，仅扩展前端 `TaskStatsRange` 和按钮配置为 `this_week`、`last_week`。如果后端已支持周维度，前端直接生效；若后端暂不支持，错误处理沿用当前加载失败提示。

「报告生成数」使用 CSS `conic-gradient` 绘制环形比例图，不引入额外图表库。比例基于当前 `reports_by_user` 中大于 0 的记录求和，避免柱状图横向拥挤。

Electron 在渲染层通过 `localStorage` 保存最近三条成功提交过的 SVN 地址。只有 `onSubmit` 成功后写入历史；失败时保留输入但不记录。历史去重后最新优先，输入框聚焦时显示，下拉项点击后回填。

## 备选方案取舍

- 使用图表库：视觉能力更强，但当前项目没有图表依赖，为一个环形图新增依赖不划算。
- Electron 通过主进程文件存储历史：更适合跨窗口或更复杂的持久化，但本需求只需渲染层最近三条，`localStorage` 足够。
- 输入时按关键字过滤历史：可用性更细，但需求只要求点击输入框显示最近三条，本期不增加过滤规则。

## UI 设计

Web 时间维度按钮显示顺序为「本周 / 上周 / 今日 / 昨日 / 累计」，默认仍为累计。报告生成数卡片中每个用户显示一个固定尺寸环形图，中心为百分比，下方显示用户名和报告数量。

Electron SVN 地址输入框保持原位置。输入框聚焦时，下方显示深色弹层，最多三条地址；点击地址后设置输入框值。无历史时不显示弹层。

## 数据与兼容性

Web `ReviewTaskStats.range` 类型扩展为 `this_week | last_week | today | yesterday | all`，响应体其他字段不变。

Electron 历史键名为 `code-review:recent-svn-urls`，值为 JSON 字符串数组。读取失败、结构异常或 `localStorage` 不可用时回退为空数组，不阻断任务提交。

## 测试计划

- Web Playwright：验证任务统计出现本周、上周按钮，点击后请求对应 range；验证报告生成数使用比例图语义，旧柱状容器文案不作为唯一断言。
- Electron Vitest：验证成功提交后保存最近三条 SVN 地址并去重；验证输入框聚焦后显示历史，点击历史项回填；验证提交失败不写历史。

## 验收标准

- 首页任务统计可切换本周和上周。
- 管理员报告生成数不再是一排柱状条，用户多时以圆形比例图展示。
- Electron 用户成功提交任务后，下次聚焦 SVN 地址输入框可选择最近三条地址。
- 相关前端和 Electron 测试通过。
