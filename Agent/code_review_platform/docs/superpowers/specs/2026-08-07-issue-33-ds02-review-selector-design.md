# Issue #33：DS-02 与生产审查项选择器接入设计

## 背景

2.0 工作台已经具备经 Issue #37 验收的审查项选择器视觉与交互基线，并通过 Issue #31、#32 接通了 DS-01 本地材料、多审查项任务和本机执行队列。目前正式共享目录只发布 DS-01、DS-03，生产 Workbench 还以硬编码白名单排除 DS-02；预览 fixture 虽包含 DS-02，但不能成为生产数据来源。

本次在不重新设计页面、不复制选择器、不改变服务端契约的前提下，把 DS-02 正式加入目录，并让现有选择器的全部交互作用于生产任务草稿和真实本机任务载荷。

## 目标

- 正式维护 DS-01、DS-02、DS-03 的稳定 ID、分类、名称、简介、展示详情、排序、启停状态和材料字段定义。
- 生产 Workbench 从正式目录生成选择器数据，启用 DS-02 单选及与 DS-01、DS-03 的组合选择。
- 逐项保存用户额外规则与材料输入，确保确认、取消、关闭、Escape 和重新打开符合事务式草稿语义。
- 把确认后的选择转换成真实 `review_items` 本机载荷；只把 `review_item_ids` 发送服务端。
- 保持 revision 原始文本贯穿预检、任务创建、本机执行和 Skill 提示词。
- 保持预览入口继续通过 fixture adapter 独立运行，生产入口不读取 fixture。

## 非目标

- 不修改 `bms-code-reviewer` Skill 或复制、解析其内部规则。
- 不为 Skill 增加版本绑定，也不增加服务端审查项校验。
- 不根据 revision 或审查项解释、推导、改写证据模式。
- 不修改后端接口、数据库、任务状态机、报告保存与下载逻辑。
- 不重新设计 #37 的选择器，也不新增第二套选择器。

## 正式目录

正式目录仍由 Electron 共享模块维护，目录版本随 DS-02 正式发布递增。三项按 `sortOrder` 升序展示：

| ID | 分类 | 名称 | 排序 | 启用 | 材料字段 |
|---|---|---|---:|---|---|
| DS-01 | 需求与变更 | 变更点审查 | 10 | 是 | 产品开发需求表（Excel）、产品规格书（PDF） |
| DS-02 | 代码质量 | 编码规范审核 | 20 | 是 | 无 |
| DS-03 | 设计与安全 | 状态机审核 | 30 | 是 | 无 |

目录只展示用户理解审查范围所需的目标、执行过程概述、输入约束和材料要求。DS-02 与 DS-03 的具体规则、证据模式、编排和失败策略只由 Skill 维护；平台文字不描述具体规则条款，也不根据旧 revision 选择模式。

## 类型与数据流

共享模块声明稳定 `ReviewItemId` 联合类型，正式目录定义使用该类型；外部输入的 `SelectedReviewItemInput.id` 仍保持 `string`，以便运行时对旧客户端、未知值和未启用项给出明确错误，而不是把兼容性问题隐藏在类型断言中。

生产数据流：

```text
正式 REVIEW_ITEM_CATALOG
  -> productionCatalog（只取 enabled，按 sortOrder 排序）
  -> 现有 ReviewItemSelector
  -> 已确认 ReviewSelection
  -> ProductionReviewWorkbench.createTask
  -> review_items（本机）
  -> useTaskQueue / IPC / task-agent
  -> resolveReviewItemInputs
  -> review_item_ids（服务端）+ reviewItems（本机工作区与 Skill 提示词）
```

`review_items` 中每项只包含自身 ID、非空额外规则和自身目录定义允许的材料。DS-02、DS-03 的材料定义为空，因此正常 UI 不产生材料字段，运行时解析也拒绝夹带任何材料字段。

## 草稿状态模型

主表单中的 `selection` 是已确认状态。每次打开选择器时，组件从该状态深拷贝出独立弹窗草稿：

- 分类选择、搜索、多选、仅看已选、清空、详情切换、额外规则和材料修改只改变弹窗草稿。
- 点击“完成选择”时，深拷贝并替换主表单已确认状态。
- 点击取消按钮、右上角关闭按钮、遮罩或 Escape 时卸载弹窗草稿，不修改主表单。
- 再次打开时重新从当前已确认状态建立草稿，因此能继续编辑上次确认内容；取消二次编辑后，下次打开仍恢复进入前的已确认状态。
- 弹窗关闭后焦点返回触发按钮；Tab 焦点保持在弹窗内。

## 兼容性与旧功能保护

- DS-01 与 DS-03 的 ID、字段、材料路径和载荷结构不变；DS-01 + DS-03 继续作为组合回归场景。
- DS-01 Excel/PDF 在 renderer 与等待队列中只保留原始本地路径，任务真正执行前仍由 `prepareReviewTaskMaterials` 复制到任务工作区。
- `ApiClient.createTask` 继续剥离 `review_items` 和本地材料路径，仅发送 `review_item_ids`；服务端不接收材料。
- 旧客户端不传 `review_items` 时，`task-agent` 继续走旧单 Skill/旧需求表兼容链路。
- 历史任务缺少 `review_item_ids` 时继续展示通用任务标题，不改变状态映射、报告读取、保存或下载。
- `useTaskQueue` 的两个并发槽、等待顺序、取消和失败后从头重试不改变；新增组合载荷只复用现有结构。
- 预览入口继续显式创建 fixture adapter；生产 Workbench 只依赖正式共享目录和真实 `window.codeReview` API。

## 错误处理

- 空选择、重复 ID、未知或停用 ID、超长额外规则、重复/越界材料字段继续由共享解析器拒绝。
- DS-01 缺少必填材料或扩展名错误继续在主表单阻止提交。
- DS-02/DS-03 无材料定义，UI 显示“无需专项材料”，解析器拒绝外部夹带材料。
- 材料文件选择失败仅显示选择器内错误，不提交草稿。
- 预检和真实任务执行失败沿用现有通知、失败状态与重试逻辑。

## 测试接缝

本次按 TDD 从以下公开边界验证行为：

1. 共享目录与 `resolveReviewItemInputs`：正式元数据、DS-02 单选/组合、逐项规则和材料归属。
2. `ReviewItemSelector` 用户交互：分类、搜索、多选、仅看已选、清空、详情、完成/取消/关闭/遮罩/Escape、重开草稿和焦点。
3. `ProductionReviewWorkbench` 用户提交：DS-02 单选、DS-01 + DS-02、DS-02 + DS-03、DS-01 + DS-03，以及传给 `window.codeReview.executeTask` 的真实载荷。
4. 主进程公开任务执行与提示词：revision 原样、DS-02 无材料、服务端只收 ID、本机逐项输入继续交给 Skill。
5. 现有队列与材料测试：两个并发槽、等待、取消、重试、DS-01 执行前复制和旧 payload 兼容。
6. 入口隔离：生产入口不出现 fixture 操作，预览入口仍可独立创建 fixture adapter。

## 视觉与可访问性验收

- 保留 #37 的双栏独立滚动、长名称省略与 `title` 完整提示、长文件名溢出约束、长额外规则 textarea 滚动。
- 保留搜索输入自动聚焦、Tab 焦点陷阱、Escape 关闭、关闭后焦点返回和可见焦点样式。
- 自动化覆盖 DOM 语义与关键样式契约；最终由真实 Electron 界面在目标视口检查文本溢出和双栏滚动。

## 验收标准

- 生产选择器展示按顺序排列的 DS-01、DS-02、DS-03，所有 #37 交互操作真实生产草稿。
- DS-02 可单独提交，也可分别与 DS-01、DS-03 组合，且不产生材料字段。
- 每项额外规则和材料不丢失、不串项；只有“完成选择”修改主表单。
- revision 原样传递，平台不解释证据模式；服务端不接收本地输入材料。
- 所列新旧自动化测试、Electron 类型检查、全量测试和构建通过。
