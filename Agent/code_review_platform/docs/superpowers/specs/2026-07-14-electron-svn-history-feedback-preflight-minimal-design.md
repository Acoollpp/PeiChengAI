# Electron SVN 历史、原生反馈窗口与 SVN 预检最小设计

## 1. 背景与目标

本设计只解决以下三个用户问题：

1. SVN 地址历史列表会遮挡后续版本字段，需要在输入时仅显示匹配项，并在填写结束后收起。
2. “有帮助”反馈弹窗受主客户端内容区域约束，无法移出客户端外，需要改为可自由移动的原生窗口。
3. SVN 路径或版本错误时，任务仍可能继续进入 Codex 并生成错误报告，需要在工作区准备和报告生成前立即失败。

本设计取代 `2026-07-10-electron-svn-history-feedback-window-preflight-design.md` 中关于反馈草稿恢复、稍后提交、跨任务同步和主窗口最小化恢复的设计。版本契约与 SVN 预检方向继续有效。

## 2. 已确认的产品行为

### 2.1 SVN 地址历史

- 历史最多保留 3 条，按最近使用排序。
- SVN 地址为空且输入框获得焦点时，显示全部历史。
- 输入非空内容时，仅显示忽略大小写后包含输入内容的历史项。
- 输入内容与某条历史忽略大小写完全相同时，不再显示历史列表。
- `Escape`、`Tab`、焦点离开历史区域或进入后续版本字段时收起列表。
- 历史列表位于正常文档流，不覆盖旧版本号和新版本号字段。

### 2.2 “有帮助”原生窗口

- 点击“有帮助”打开独立 `BrowserWindow`。
- 窗口是单实例、非模态窗口；设置主窗口为 `parent`，但不设置 `modal` 或全局 `alwaysOnTop`。
- 用户可把窗口拖出主客户端边界，以便同时查看报告。
- 同一任务重复点击“有帮助”时聚焦已有窗口。
- 对另一任务点击“有帮助”时销毁旧窗口并打开新窗口；旧窗口未提交内容直接丢弃。
- 原生关闭按钮和界面内取消按钮都会销毁窗口，未提交内容直接丢弃。
- 勾选项、手工补充文本和提交错误只存在于反馈窗口 renderer 内，不写入主进程草稿，也不恢复。
- 保留既有功能：候选问题勾选、手工补充、勾选时定位报告锚点、提交成功后更新任务反馈状态并打开 PDF。
- “没帮助”按钮继续保留，并通过专用 API 固定提交 `helpful: false` 和 `useful_issues_text: null`。

### 2.3 SVN 预检

- 保留后端版本契约：`old == 0` 表示全量审查；其他情况必须满足 `0 < old < new`，且 `new > 0`。
- Electron 在工作区准备前执行相同的防御性版本校验。
- 使用环境检查实际探测到的 `svnCommand`、相同 PATH/env 和当前操作系统用户的 SVN 认证缓存；预检固定 `shell:false` 直接启动 SVN，不把 URL 参数交给系统 shell。`svnCommand` 可能是绝对路径，也可能是由 PATH 解析的命令名。
- 命令继续使用 `spawn(command, args)` 参数数组，不拼接命令字符串。
- 对新版本执行 `svn info --non-interactive -r <new> <svnUrl>`。
- `old > 0` 时，再对旧版本执行相同检查；`old == 0` 时只检查新版本。
- 每次 `svn info` 独立超时 30 秒，并响应任务取消信号。
- 预检失败时保持现有任务状态枚举，返回明确的用户可读错误；不得执行工作区准备、需求文件上传、Codex 或报告生成。
- 原始 SVN stderr 只用于错误分类和脱敏日志，不直接展示给用户。
- 公司 SVN 经过加密且本机 Mac 无法访问；Mac 自动化测试必须使用注入命令替身，不以真实 SVN 成功为完成条件。真实成功链路只在 Windows 客户端、当前 Windows 用户已具备 SVN 认证缓存的环境中手工验收。

## 3. 非目标

- 不保存或恢复未提交反馈内容。
- 不实现“稍后提交”、隐藏窗口或主窗口最小化后的反馈窗口可见性恢复。
- 不在多个任务之间同步反馈表单状态。
- 不新增反馈草稿数据库、状态机、revision 协议或自动重试队列。
- 不重构全部 SVN 命令链路；既有命令的 Windows `shell:true` 安全债务仍留待后续，但本次新增预检不得继承该债务。
- 不改变服务端反馈接口的数据格式。

## 4. 组件边界

### 4.1 主进程窗口管理器

`src/main/report-feedback-window.ts` 只负责：

- 创建、聚焦、替换和销毁反馈 `BrowserWindow`；
- 保存当前窗口对应的只读上下文：`taskId` 和候选问题列表；
- 校验 IPC sender 必须来自当前反馈窗口；
- 根据 option ID 映射候选文本；
- 把报告定位和提交结果通知主窗口。

它不得保存 `selectedOptionIds`、手工文本或提交错误。

### 4.2 反馈窗口 renderer

反馈 renderer 只负责当前窗口生命周期内的表单状态：

- 启动时读取只读上下文；
- 本地维护选中 option ID 和手工文本；
- 勾选或取消时请求主进程定位或清除报告锚点；
- 提交时一次性发送 `taskId`、`selectedOptionIds` 和 `manualText`；
- 提交失败时保留当前窗口内输入并显示错误；
- 提交成功后由主进程销毁窗口。

### 4.3 主窗口 renderer

主窗口负责：

- 根据当前报告生成稳定的候选项 ID、显示文本和锚点 ID；
- 请求打开或聚焦反馈窗口；
- 接收定位事件并滚动、突出对应报告位置；
- 接收提交成功事件，更新任务反馈状态并打开 PDF；
- 使用专用负反馈 API 提交“没帮助”。

主窗口不保存反馈窗口表单内容。

### 4.4 SVN 预检模块

`src/main/svn-preflight.ts` 是无 UI 的独立模块，负责：

- 规范化和比较版本号；
- 构造 SVN 参数数组；
- 执行带超时和取消的 `svn info`；
- 分类认证失败、路径或版本不存在、网络失败、超时和取消；
- 返回稳定的用户可读错误与脱敏日志摘要。

`task-agent.ts` 只负责把它插入任务执行顺序，不重复实现 SVN 判断。

## 5. 数据与 IPC 契约

反馈上下文：

```ts
interface ReportFeedbackContext {
  taskId: string
  options: Array<{ id: string; text: string; anchorId: string }>
}
```

反馈窗口提交：

```ts
interface SubmitHelpfulReportFeedbackPayload {
  taskId: string
  selectedOptionIds: string[]
  manualText: string
}
```

主进程必须拒绝以下请求：

- sender 不是当前反馈窗口；
- `taskId` 与当前窗口上下文不一致；
- option ID 不在当前上下文中；
- option ID 重复；
- 所有候选与手工文本规范化后均为空。

主进程按候选列表顺序映射文本，将手工文本按行拆分，去空、去重后统一编号，再调用现有服务端反馈接口。

## 6. 错误处理

- 反馈窗口创建或加载失败：主窗口显示“反馈窗口打开失败，请重试。”，不影响报告查看。
- 反馈提交失败：错误只显示在反馈窗口，窗口与当前输入保持不变。
- 反馈已存在：按提交成功处理，关闭反馈窗口、更新主窗口状态并打开 PDF。
- SVN 版本格式或顺序错误：在执行 SVN 命令前失败。
- SVN 认证、路径、版本、网络或超时错误：返回固定中文错误，不把原始 stderr 直接展示给用户。
- 任务取消：终止在途 `svn info`，沿用现有取消流程，不生成报告。

## 7. 测试策略

- 保留 SVN 历史过滤、完全匹配收起、`Escape`、`Tab` 和正常文档流测试。
- 窗口管理器测试覆盖单实例、同任务聚焦、跨任务替换、非模态配置、关闭即销毁和主窗口关闭清理。
- preload 测试断言只暴露读取上下文、定位、提交、取消四类最小能力。
- 反馈组件测试覆盖本地编辑、空内容禁用、option ID 提交、定位、取消丢弃、提交失败保留输入和成功关闭。
- IPC 测试覆盖 sender、taskId、option ID 校验、文本映射、去重编号、负反馈固定 payload 和成功通知。
- SVN 预检测试覆盖合法范围、全量模式、旧新版本检查、30 秒超时、取消、错误分类和 stderr 脱敏。
- `task-agent` 测试证明预检发生在工作区准备之前，失败时后续步骤全部未调用。
- 最终运行 Electron 全量测试、类型检查和生产构建。
- Windows 手工验收使用可访问的公司加密 SVN；Mac 上真实 `svn info` 失败属于环境预期，不作为自动化失败。

## 8. 可维护性约束

- 反馈窗口管理、反馈 UI、IPC 业务和 SVN 预检分别放在独立文件，不在 `TaskPage.tsx` 或 `task-agent.ts` 内堆叠状态机。
- 反馈 renderer 不建立跨窗口同步协议；关闭即释放状态。
- 主进程以只读上下文完成 option ID 映射，避免 renderer 伪造候选文本。
- 所有新增行为先写失败测试，再实现最小代码。
- 不修改与本需求无关的页面、安装器、服务端状态枚举或既有 stash。
