# Issue #35 报告中心真实数据与兼容设计

## 背景

#34 已把 2.0 工作台接入真实任务队列和今日统计，#37 已完成报告中心、报告摘要和任务详情的视觉结构，#36 已提供 Markdown、图片、PDF、逐问题反馈草稿、正式提交和反馈版 PDF 链路。当前生产适配器仍只预读第一份成功报告，报告列表没有独立加载状态；服务端为所有任务返回默认 `issue_count=0`，导致没有逐问题快照的 1.x 历史任务被误显示为零问题；审查项只显示 ID，未知 ID 被直接丢弃；最高严重度尚未从真实报告提取。共享解析器还会把“审查覆盖”之外的任意叶子三级标题当成问题。

## 目标

- 在不重写报告系统的前提下，让 #37 工作台消费真实 `task:list` 与 `task:report` 数据。
- 按 `bms-code-reviewer/assets/report-template.md` 的固定结构识别新版问题、零问题和审查覆盖。
- 展示真实审查项 ID 与正式目录名称，兼容未知 ID 和缺少字段的历史任务。
- 明确区分新版零问题、历史问题数未记录、报告加载失败和新版报告结构解析失败。
- 保留 #36 的 Markdown 图片、PDF、旧报告级反馈、逐问题反馈和反馈版 PDF 全链路。
- 以回归测试证明列表、详情、统计的用户/部门权限范围及新旧任务混合数据兼容性。

## 非目标

- 不修改 `bms-code-reviewer` Skill 内部规则或固定模板。
- 不增加 #29 之外的报告协议，不改变逐问题快照上传结构。
- 不修改 #34 队列、任务状态或今日统计语义。
- 不新增数据库字段或迁移，不改变报告、图片、PDF、反馈附件的存储路径。
- 不修改旧客户端使用的 REST、IPC、preload 方法和字段。

## 设计决策

### 固定模板解析优先，历史模板保持兜底

新版报告通过结构识别：报告中存在二级“审查问题”章节，且问题必须是该章节直属的 `### Pxx [高风险/中风险/低风险/建议] 标题`。问题块从标题延伸到下一个同级标题、二级章节或分隔线，提取 `问题描述`、严重度和“涉及文件及行号”表。`审查覆盖` 及其他章节的三级标题不进入候选集合。

没有新版“审查问题”章节时继续走既有 template_1/template_2 解析，保留历史报告与旧反馈定位。上传仍只发送既有问题原文、描述原文、展示快照和 Markdown 定位字段；新增的严重度和代码位置只用于客户端摘要，不扩展服务端协议。

### 新版计数与历史计数分开解释

- `feedback_protocol_version === 1`：服务端逐问题快照计数具有权威性，`issue_count=0` 明确表示零问题。
- 历史任务：服务端默认 `issue_count=0` 不作为事实。报告尚未加载或历史解析无法确认时显示“问题数未记录”；加载后若旧解析器识别到问题，则显示解析结果，绝不凭默认值伪造零问题或严重度。
- 新版报告结构缺失或格式无效：显示“报告结构解析失败”，保留 Markdown/PDF/反馈副流程入口，且其他报告与任务创建继续可用。

### 服务端只读严重度摘要与报告级按需加载

报告列表需要最高严重度，但最多 100 份历史任务不能通过 N+1 正文请求补齐。后端在既有 `ReviewTaskIssue.issue_text` 上做单查询聚合，向 `ReviewTaskPublic` 增加可空只读 `highest_issue_severity`：仅有明确问题快照时返回 `high / medium / low / suggestion`，没有快照或无法识别时为 `null`。该字段不落库、不迁移，旧客户端会自然忽略；Electron 手写类型与 Web 生成客户端同步新增可选字段。

正文通过 `task:report` 按需读取。为兼容 #36/#37 既有“进入报告中心即可看到首份报告”的行为，列表 ready 后自动选中并异步读取首份状态成功且存在非空 Markdown 路径的报告；列表 ready 不依赖该正文，其余报告不会后台预读，只在用户点击查看时读取。

工作台 view model 增加报告列表状态和每份报告内容状态：

- 列表：`loading / ready / error`，失败时提供“重新加载报告列表”。
- 内容：仅选中报告进入 `loading / ready / error / parse_error`，单份失败时只影响该报告并提供“重新加载此报告”。未选中的报告保持未加载，不显示为失败。

生产适配器收到真实列表后立即显示任务与报告元数据，自动选择首份可读 Markdown 报告作为兼容预览，并只按需读取当前选中报告。成功但缺少 Markdown 路径的任务不进入报告列表、不产生可查看通知，并在任务行明确显示“任务已完成，但未生成可查看的 Markdown 报告”。预览 adapter 继续只使用 fixture，不导入生产 bridge；生产入口不导入 fixture。

### 审查项与标题

view model 保留服务端原始审查项 ID。已知 ID 显示 `ID · 正式目录名称`；未知 ID 只显示原始 ID；空值、`null`、`undefined` 和空数组显示“历史任务未记录审查项”。报告名存在时作为标题；否则使用 SVN 最末路径和 revision 范围，避免用虚构任务名。

### 界面设计

沿用 #37 的紧凑工作台，不改变主导航或双栏结构。新增状态属于信息结构而非装饰：列表顶部状态条、报告索引中的范围文本、预览区的加载/错误块、严重度标签。现有灰白底、青绿色主操作、红/黄风险色与字体体系保持不变。长任务名、长 SVN 路径和多审查项范围继续由现有网格与截断/换行策略承载。

## 错误处理

- 列表请求失败不影响创建任务、环境检查和意见反馈，报告区显示错误和重试。
- 单份 Markdown 加载失败只标记该报告，其他报告仍可切换；PDF 仍可按既有规则打开。
- 新版结构解析失败显示明确状态，不生成问题数或严重度；原始 Markdown 仍可渲染。
- 图片、反馈窗口或 PDF 失败沿用既有 toast，不阻断报告查看。
- 异步列表与选中报告请求使用请求代次和组件存活标记，旧响应不得覆盖新列表或当前选择。

## 兼容性

- 旧入口：任务管理、报告中心、旧 `TaskPage`、Web 管理端均保留。
- 旧字段/接口/IPC：`review_item_ids`、`issue_count`、`task:list`、`task:report`、`report:asset`、`report:open-pdf`、反馈 IPC 原样保留；只增加可空只读响应字段。
- 旧路径：`REPORT_STORAGE_DIR`、报告图片相对路径、PDF 和反馈附件目录不变。
- 历史数据：缺少新字段时以明确历史语义展示；不伪造审查项或零问题。
- 失败隔离：报告列表、单份正文、图片、反馈或 PDF 的失败不会阻断任务创建与其他报告。
- 权限：Electron 继续使用 `mine=true`；后端列表、详情、统计仍复用 `_task_read_scope_filters`。
