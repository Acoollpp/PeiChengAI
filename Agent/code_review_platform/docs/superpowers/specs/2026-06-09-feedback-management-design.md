# 意见管理设计

## 背景

当前代码审查平台由 Web 服务端和 Electron 桌面客户端组成。Web 端已经有登录体系、角色权限、管理后台、文件上传落盘和受权限保护的文件读取能力。管理员菜单中已有 `用户管理`、`任务管理`、`Skill库`、`客户端版本` 等模块，普通用户和管理员可以基于同一个后端接口看到不同范围的数据。

Electron 客户端的任务工作台顶部当前有 `联系管理员` 按钮，会打开管理员联系方式名片。用户最初希望把图中这个按钮改成提交意见入口。由于任务工作台出现在登录后，客户端已经具备服务端地址和访问 token，适合直接调用后端意见接口提交反馈。

本次目标是把登录后依赖“联系管理员”的人工反馈方式，改成平台内的意见提交与处理闭环。用户可以在 Electron 客户端或 Web 意见管理页提交问题描述和可选截图，后端记录提交人、提交时间、描述、截图和解决状态；普通用户只能查看自己提交的意见，管理员可以查看全部意见并维护解决状态。

## 已确认决策

- 所有登录用户都可以看到 `意见管理` 页面。
- `意见管理` 是 Web 前端一级菜单，和 `主页`、`用户管理` 同级。
- 管理员和普通用户访问同一个页面，但看到的数据范围和可执行操作不同。
- `提交意见` 按钮放在意见管理页面标题右侧，位置和用户管理页的 `新增用户` 按钮一致。
- Electron 客户端任务工作台顶部的 `联系管理员` 按钮改为 `提交意见` 按钮。
- Electron 客户端登录后的 `提交意见` 按钮直接打开客户端内提交弹窗，并调用同一个后端意见接口。
- Electron 登录页底部的 `联系管理员` 入口第一版保留，用于未登录或无法登录时的兜底联系渠道。
- 问题描述必填。
- 问题截图选填。
- 截图支持选择图片文件，也支持从剪贴板粘贴截图。
- 状态包含 `待处理`、`处理中`、`已解决`。
- 只有管理员可以修改解决状态。
- 普通用户只能看到自己提交的意见。
- 管理员可以看到所有意见。
- 数据库新表和每个字段都必须写中文描述。
- 文档、提交信息使用中文。

## 目标

1. 新增意见提交能力，让用户在平台内反馈问题。
2. 新增意见管理页面，让用户查看自己提交意见的处理进度。
3. 让管理员集中查看所有意见，并维护解决状态。
4. 保存意见的提交人、提交时间、问题描述、问题截图和解决状态。
5. 对截图访问做权限控制，避免普通用户读取他人截图。
6. 将 Electron 任务工作台顶部的 `联系管理员` 改成 `提交意见`，让客户端用户不离开工作台即可提交问题。
7. 保持第一版功能克制，先完成提交、查看、截图和状态流。

## 非目标

第一版不做以下能力：

- 管理员回复用户。
- 多轮评论。
- 处理人分派。
- 处理备注。
- 站内信、邮件或钉钉通知。
- 删除意见。
- 多张截图或任意附件。
- 专门的 Markdown 编辑器。
- 仅通过上传 Markdown 文件提交意见。
- 未登录状态的意见提交。

问题描述允许用户输入 Markdown 语法，但第一版不提供专门的 Markdown 编辑器，也不做 Markdown 渲染。详情页按纯文本展示描述，避免引入额外渲染依赖和 XSS 风险。后续如果需要 Markdown 预览，应单独增加安全渲染方案。

登录页底部的 `联系管理员` 属于未登录兜底入口。第一版不把它改成意见提交，因为意见接口依赖登录用户身份；如果用户无法登录，仍然需要保留一种不依赖 token 的联系管理员方式。

## 推荐方案

采用“结构化意见 + 可选图片附件”的方案：

- 后端新增 `Feedback` 表和 `FeedbackStatus` 枚举。
- 提交接口使用 `multipart/form-data` 接收问题描述和可选截图。
- 截图保存到独立的意见附件目录，不和审查报告、Skill 包、客户端版本文件混放。
- 列表和详情接口复用当前登录用户权限：普通用户自动限制为本人数据，管理员读取全量数据。
- 管理员通过单独状态接口修改意见状态。
- Web 前端新增通用 `意见管理` 页面，所有登录用户可见。
- Electron 客户端任务工作台把 `联系管理员` 按钮改为 `提交意见`，复用后端 `POST /api/v1/feedback`。

该方案比 Markdown 文件上传更适合第一版。它降低用户提交成本，也让管理员可以按提交人、时间、状态和描述摘要快速浏览。

Electron 客户端采用“客户端内置提交弹窗”而不是“打开 Web 页面”的方式。原因是客户端登录后已经保存 token 和服务端地址，可以直接调用 API；内置弹窗也能支持粘贴截图，避免跳转浏览器和重复登录。

## 权限设计

### 普通用户

普通用户可以：

- 进入 `意见管理` 页面。
- 提交新意见。
- 查看自己提交的意见列表。
- 查看自己意见的详情。
- 查看自己意见的截图。

普通用户不可以：

- 查看他人提交的意见。
- 查看他人意见的截图。
- 修改解决状态。
- 删除意见。

### 管理员

管理员可以：

- 进入 `意见管理` 页面。
- 提交新意见。
- 查看所有用户提交的意见。
- 查看所有意见的截图。
- 将状态修改为 `待处理`、`处理中`、`已解决`。
- 按状态、提交人等条件筛选意见。

管理员第一版不可以：

- 删除意见。
- 编辑用户提交的问题描述。
- 替用户上传或替换截图。

## 数据模型设计

新增枚举 `FeedbackStatus`：

```text
pending      待处理
processing   处理中
resolved     已解决
```

新增数据表 `feedback`。数据库表和字段必须在迁移文件中添加中文 comment。

表描述：

- `feedback`：用户意见反馈表，记录用户提交的问题描述、可选截图和解决状态。

字段设计：

| 字段名 | 类型 | 约束 | 中文描述 |
| --- | --- | --- | --- |
| `id` | UUID | 主键 | 意见ID |
| `user_id` | UUID | 非空，外键到 `user.id`，索引 | 提交人用户ID |
| `description` | Text/String | 非空，最大长度建议 4096 | 问题描述 |
| `screenshot_path` | String | 可空，最大长度 2048 | 问题截图服务器存储路径 |
| `screenshot_name` | String | 可空，最大长度 255 | 问题截图原始文件名 |
| `screenshot_content_type` | String | 可空，最大长度 128 | 问题截图文件类型 |
| `screenshot_size` | Integer | 可空 | 问题截图文件大小，单位字节 |
| `status` | Enum/String | 非空，默认 `pending`，索引 | 解决状态 |
| `created_at` | DateTime(timezone=True) | 非空，默认当前 UTC 时间，索引 | 上传时间 |
| `updated_at` | DateTime(timezone=True) | 非空，默认当前 UTC 时间 | 更新时间 |

索引建议：

- `ix_feedback_user_id_status`：`user_id`、`status` 组合索引，用于普通用户查看自己不同状态的意见。
- `ix_feedback_status_created_at`：`status`、`created_at` 组合索引，用于管理员按状态筛选并按时间排序。
- `created_at` 单列索引，用于默认倒序列表。

模型返回时补充提交人展示字段：

- `user_name`：提交人姓名。
- `svn_username`：提交人 SVN 账号。
- `has_screenshot`：是否存在截图。

这些字段不需要冗余保存到 `feedback` 表，列表查询时通过 `User` 表关联得到。

## 数据库注释要求

迁移文件必须显式写入中文注释：

- 表注释：`用户意见反馈表，记录用户提交的问题描述、可选截图和解决状态。`
- 每个字段按上方“中文描述”列写入注释。

如果当前数据库方言支持 SQLAlchemy/Alembic 的 `comment` 参数，应在 `op.create_table` 的 `sa.Column(..., comment="...")` 和表级 `comment="..."` 中声明。若测试数据库不支持表/字段注释，也必须在迁移文件中保留注释声明，生产数据库执行时应写入真实注释。

## 文件存储设计

新增配置：

```text
FEEDBACK_STORAGE_DIR=/app/feedback-screenshots
```

建议目录结构：

```text
/app/feedback-screenshots/
  <feedback_id>/
    screenshot.png
```

保存规则：

1. 用户提交后先创建 `Feedback` 记录，拿到 `feedback_id`。
2. 如果有截图，校验通过后写入 `<feedback_id>` 独立目录。
3. 更新 `screenshot_path`、`screenshot_name`、`screenshot_content_type`、`screenshot_size`。
4. 如果截图保存失败，回滚数据库事务或删除已创建记录，避免产生无效意见。

截图限制：

- 只允许图片类型：`image/png`、`image/jpeg`、`image/webp`。
- 文件大小上限：5MB。
- 第一版只支持一张截图。
- 服务端不能仅信任文件扩展名，至少要校验 `content_type` 和文件大小。

## 后端 API 设计

新增路由文件：

```text
backend/app/api/routes/feedback.py
```

注册到：

```text
backend/app/api/main.py
```

接口设计：

### 提交意见

```text
POST /api/v1/feedback
```

权限：

- 所有登录用户。

请求：

- `description`：表单字段，必填。
- `screenshot`：文件字段，选填。

响应：

- 返回创建后的 `FeedbackPublic`。

行为：

- `user_id` 使用当前登录用户 ID，不能由前端传入。
- `status` 默认 `pending`。
- `created_at` 和 `updated_at` 使用服务端时间。

### 读取意见列表

```text
GET /api/v1/feedback
```

权限：

- 所有登录用户。

查询参数：

- `skip`：分页偏移。
- `limit`：分页大小。
- `status`：可选状态筛选。
- `user_name`：管理员可用，按提交人姓名模糊搜索。
- `svn_username`：管理员可用，按 SVN 账号模糊搜索。

行为：

- 普通用户自动追加 `Feedback.user_id == current_user.id` 过滤。
- 管理员读取全量数据。
- 普通用户传入提交人筛选参数时忽略或按本人范围处理，不允许扩大数据范围。
- 默认按 `created_at` 倒序。

响应：

- `FeedbacksPublic`，包含 `data` 和 `count`。

### 读取意见详情

```text
GET /api/v1/feedback/{feedback_id}
```

权限：

- 普通用户只能读取自己的意见。
- 管理员可以读取任意意见。

响应：

- `FeedbackPublic`。

### 读取截图

```text
GET /api/v1/feedback/{feedback_id}/screenshot
```

权限：

- 普通用户只能读取自己意见的截图。
- 管理员可以读取任意意见的截图。

行为：

- 无截图返回 404。
- 文件不存在返回 404。
- 返回 `FileResponse`，`media_type` 使用保存的 `screenshot_content_type`。

### 修改状态

```text
PATCH /api/v1/feedback/{feedback_id}/status
```

权限：

- 仅管理员。

请求：

```json
{
  "status": "processing"
}
```

响应：

- 返回更新后的 `FeedbackPublic`。

行为：

- 更新 `status`。
- 更新 `updated_at`。
- 不允许普通用户调用。

## 提交弹窗设计

`提交意见` 按钮打开弹窗，弹窗字段：

- `问题描述`：必填多行文本框。
- `问题截图`：选填图片上传区。

交互要求：

1. 用户可以点击上传区选择图片。
2. 用户可以在弹窗内粘贴剪贴板截图。
3. 选中或粘贴图片后显示缩略图、文件名和大小。
4. 用户可以移除已选截图。
5. 提交中禁用按钮并显示加载状态。
6. 提交成功后关闭弹窗、清空表单、刷新列表并提示成功。
7. 提交失败时保留用户已填写内容，提示错误。

前端校验：

- 描述去除首尾空白后不能为空。
- 截图必须是图片类型。
- 截图不能超过 5MB。

后端仍必须做同样校验，前端校验只用于提升体验。

## Electron 客户端设计

### 入口调整

客户端登录后的任务工作台顶部当前有 `联系管理员` 按钮。第一版将该按钮改为：

```text
提交意见
```

位置保持不变，仍在任务工作台顶部用户标识旁边，避免改变用户已有视觉路径。

登录页底部的 `联系管理员` 按钮第一版保留，继续打开管理员联系方式名片。原因是登录页没有当前用户身份，无法保存“上传人”；如果用户遇到无法登录、Key 失效、服务端地址错误等问题，仍需要离线联系渠道。

### 客户端提交弹窗

任务工作台点击 `提交意见` 后打开客户端内弹窗，字段与 Web 提交弹窗保持一致：

- `问题描述`：必填多行文本框。
- `问题截图`：选填图片。

客户端交互要求：

1. 支持点击选择图片。
2. 支持在弹窗内粘贴剪贴板截图。
3. 第一版只支持一张截图；再次选择或粘贴图片时替换已有截图。
4. 显示截图缩略图、文件名和大小。
5. 支持移除已选截图。
6. 提交中禁用按钮。
7. 提交成功后关闭弹窗并提示 `意见已提交`。
8. 提交失败时保留用户输入，并提示可读错误。

客户端不需要展示完整意见列表；意见列表和状态进度在 Web `意见管理` 页面查看。这样客户端只承担快速提交入口，Web 承担管理和追踪。

### 客户端 API 通路

Electron 客户端应复用当前主进程持有的服务端地址和登录 token，不由渲染进程直接拼接鉴权请求。

建议新增通路：

```text
Renderer SubmitFeedbackDialog
  │
  ├─ window.codeReviewApi.submitFeedback(...)
  ▼
Preload 暴露受控 API
  │
  ├─ ipcRenderer.invoke('feedback:submit', payload)
  ▼
Main ipc.ts
  │
  ├─ 从 authStore 读取 token
  ├─ 从 serverConfig/auth session 读取服务端地址
  ├─ 调用 ApiClient.submitFeedback(...)
  ▼
POST /api/v1/feedback
```

提交截图时，渲染进程可以把图片转换为 `ArrayBuffer` 或安全的文件引用，再通过 IPC 传给主进程。主进程负责构造 `multipart/form-data` 请求。实现时不能让渲染进程直接访问任意本地路径或绕过 preload 的受控接口。

### 客户端错误处理

- 未登录或 token 缺失：提示 `请重新登录后提交意见`。
- 服务端地址缺失：提示 `请先完成服务端配置`。
- 描述为空：提示 `请填写问题描述`。
- 图片格式不支持：提示 `请上传 PNG、JPG 或 WEBP 图片`。
- 图片超过 5MB：提示 `截图不能超过 5MB`。
- 网络错误：提示 `意见提交失败，请检查网络或服务端地址`。
- 服务端返回鉴权失败：提示 `登录状态已失效，请重新登录`。

### 客户端旧组件处理

登录后的任务工作台不再使用 `AdminContactDialog` 作为主反馈入口。相关测试应从“打开管理员联系方式”调整为“打开提交意见弹窗”。

登录页继续使用 `AdminContactDialog`，对应测试保留。

## 状态展示设计

状态中文展示：

- `pending`：`待处理`
- `processing`：`处理中`
- `resolved`：`已解决`

建议颜色：

- `待处理`：次要或灰色标识。
- `处理中`：强调或蓝色标识。
- `已解决`：绿色标识。

管理员修改状态可以使用下拉选择。普通用户只看到状态徽标。

## 错误处理

- 描述为空：前端提示 `请填写问题描述`，后端返回 422 或 400。
- 截图格式不支持：提示 `请上传 PNG、JPG 或 WEBP 图片`。
- 截图超过 5MB：提示 `截图不能超过 5MB`。
- 截图保存失败：后端返回 500，前端提示 `意见提交失败，请稍后重试`。
- 无权限访问他人意见：后端返回 403。
- 无权限修改状态：后端返回 403。
- 截图不存在：后端返回 404。

## 安全和隐私

1. `user_id` 只能由服务端使用当前登录用户写入。
2. 截图读取必须经过后端权限判断，不能通过公开静态目录暴露。
3. 普通用户列表接口必须在后端按当前用户过滤。
4. 管理员状态修改接口必须依赖 `get_current_active_admin`。
5. 文件名不能直接用于服务端路径拼接，应使用 `feedback_id` 生成存储路径。
6. 返回前端的 `screenshot_path` 不应暴露真实服务器路径；前端只需要知道是否有截图，并通过受保护接口读取。
7. `FeedbackPublic` 不返回 `screenshot_path`，只返回 `has_screenshot`、`screenshot_name`、`screenshot_content_type`、`screenshot_size` 等安全展示字段。
