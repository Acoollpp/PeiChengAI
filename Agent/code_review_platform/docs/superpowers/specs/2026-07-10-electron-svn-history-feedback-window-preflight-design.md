# Electron 客户端 SVN 历史框、报告反馈工具窗口与 SVN 预检设计

## 1. 背景

当前 Electron 代码审查客户端存在三个相关体验问题：

1. SVN 地址历史记录使用绝对定位浮层，展开后会覆盖旧版本号和新版本号字段。用户填写完 SVN 地址后准备点击版本号字段时，可能误点历史地址，导致已经填写的 SVN 地址被替换。
2. “有帮助”反馈表单是主渲染页面中的固定定位 DOM，只能在主客户端内容区域内拖动，无法移出主窗口，容易遮挡正在对照的报告内容。
3. SVN 地址或版本错误目前主要由 Codex 和审查 Skill 在执行过程中发现。错误可能被写入报告或在较晚阶段才转为失败，浪费执行时间，也会产生不应存在的错误报告。

本设计在不改变服务端任务创建接口和报告反馈业务语义的前提下，分别优化表单交互、反馈窗口承载方式和任务启动前校验流程。

## 2. 目标

- SVN 历史记录不能覆盖版本号等后续表单字段。
- SVN 历史记录只展示与当前输入匹配的地址，并在用户完成输入或离开该区域时及时收起。
- 报告反馈表单可以拖出主客户端边界，并继续与主报告的滚动和高亮交互。
- SVN 地址或版本不可用时，任务在启动 Codex 前立即失败。
- 预检失败任务保留在任务历史中，并显示明确、经过脱敏的错误原因。
- 三项功能保持独立职责，能够分别测试和维护。

## 3. 非目标

- 不增加服务端 SVN 校验接口。
- 不改变最近 SVN 地址最多保存 3 条的现有规则。
- 不持久化未提交的报告反馈草稿；应用退出后草稿可以丢弃。
- 不允许反馈窗口置顶到其他应用之上。
- 不改变报告反馈只允许提交一次的服务端约束。
- 不改变 Codex 和审查 Skill 的具体审查规则。

## 4. 总体架构

改动拆分为三个独立单元：

1. `TaskForm` 内部负责 SVN 历史地址的读取、匹配、展示、选择和收起。
2. 主进程新增报告反馈工具窗口管理器，独立反馈渲染入口通过受限 preload 和 IPC 与主窗口通信。
3. 主进程新增 SVN 预检模块，`task-agent` 在环境检查成功后、准备工作区之前调用该模块。

任务执行顺序调整为：

```text
创建服务端任务
  -> 检查本机环境
  -> 校验 SVN 参数格式与版本顺序
  -> 访问 SVN 校验路径和版本
  -> 准备任务工作区
  -> 上传可选需求文件
  -> 启动 Codex
  -> 生成并上传报告
```

预检必须早于工作区准备。当前工作区准备过程会通过 `svn log` 解析报告文件名，如果预检放在其后，错误参数仍会触发 SVN 操作，无法满足“立即停止”的要求。

## 5. SVN 地址历史框

### 5.1 展示规则

- SVN 输入框为空并获得焦点时，展示最近使用的最多 3 条地址。
- 输入框非空时，对历史地址执行包含匹配，匹配时忽略大小写。
- 匹配结果保持最近使用顺序，不额外按字符串排序。
- 没有匹配结果时立即收起历史区域。
- 当前输入与某条历史地址完全一致时自动收起，避免完成输入后继续遮挡或干扰。

### 5.2 布局规则

- 历史结果使用正常文档流中的内联区域。
- 展开时后续版本号字段整体向下排列。
- 禁止使用会覆盖后续表单字段的绝对定位浮层。
- 列表宽度与 SVN 输入框一致，长地址允许换行或安全截断，但不能撑破表单宽度。

### 5.3 交互规则

- 只有用户明确点击历史地址项时才回填 SVN 地址。
- 鼠标移动经过历史项不能改变输入值。
- 选择历史项后立即收起列表。
- 按 `Escape`、`Tab`、提交成功或焦点移出 SVN 地址区域时收起。
- 用户点击旧版本号或新版本号字段时，点击目标必须保持为对应版本字段，不能被历史项截获。
- 提交失败时保留当前 SVN 地址和版本号，便于修正后重试。

### 5.4 可访问性

- 输入框保留 `aria-haspopup="listbox"` 和正确的 `aria-expanded`。
- 历史区域使用 `role="listbox"`，历史项使用 `role="option"`。
- `Escape` 可关闭列表并保持输入框焦点。
- `Tab` 按正常表单顺序进入旧版本号字段。

## 6. 报告反馈工具窗口

### 6.1 窗口类型

- 使用独立、非模态的 Electron `BrowserWindow`。
- 窗口以主窗口为 `parent`，保证位于主窗口上方，但不设置全局 `alwaysOnTop`。
- 用户可以自由移动窗口，包括移动到主客户端边界之外。
- 使用原生窗口移动能力，不再依赖主页面中的 Pointer Event 拖拽坐标。
- 窗口采用单实例模型，同一时间最多存在一个反馈工具窗口。

### 6.2 生命周期

- 首次点击“有帮助”时创建窗口，并在主窗口右侧附近显示。
- 重复点击“继续标记”时复用并聚焦现有窗口。
- 主窗口最小化时隐藏反馈窗口，主窗口恢复时重新显示。
- 主窗口关闭时销毁反馈窗口。
- 用户退出登录、切换到不允许反馈的任务、反馈已成功提交或任务状态不再匹配时关闭窗口并结束会话。
- 用户点击关闭按钮或“稍后提交”时关闭或隐藏窗口，但保留当前任务的内存草稿。
- 应用退出后不保存草稿。

### 6.3 独立渲染入口

反馈窗口使用独立 React 渲染入口，只包含：

- 标题和说明。
- 已标记数量。
- 从 Markdown 报告提取的候选问题列表。
- 手动补充文本框。
- “稍后提交”和“提交并打开 PDF”操作。
- 提交错误提示。

反馈窗口不加载任务看板、登录页、完整报告预览或其他主应用界面。

### 6.4 会话数据

主页面打开反馈窗口时提供：

- `taskId`
- 当前任务是否仍允许提交反馈
- 候选问题文本
- 每个候选问题对应的报告锚点 ID
- 当前选择项
- 当前手动补充文本

主进程按 `taskId` 保存内存草稿：

- 已选择的问题文本
- 手动补充文本
- 最后更新时间

切换任务时不能把一个任务的草稿应用到另一个任务。

### 6.5 IPC 边界

反馈窗口使用专用 preload，只暴露以下能力：

- 读取当前反馈会话。
- 监听会话更新或失效。
- 更新当前任务草稿。
- 请求主报告定位并高亮指定锚点。
- 提交当前反馈。
- 关闭或隐藏反馈窗口。

建议使用独立通道，命名保持统一，例如：

```text
report-feedback-window:open
report-feedback-window:session
report-feedback-window:update-draft
report-feedback-window:focus-anchor
report-feedback-window:submit
report-feedback-window:close
report-feedback-window:submitted
report-feedback-window:invalidated
```

专用 preload 不暴露登录、任务执行、更新安装等无关 API。

### 6.6 主报告联动

- 用户在反馈窗口勾选新的候选问题时，反馈窗口发送锚点定位请求。
- 主进程把定位事件转发给主窗口。
- 主窗口中的 `TaskPage` 继续负责滚动 Markdown 报告并高亮对应内容。
- 取消勾选不强制滚动；如果取消的是当前高亮项，则清除高亮。
- 主窗口当前展示的任务与反馈会话任务不一致时，忽略定位请求并使反馈会话失效。

### 6.7 提交行为

- 没有任何候选项或手动内容时禁止提交。
- 提交时复用现有报告反馈服务端接口。
- 提交成功后通知主窗口更新任务的反馈状态，关闭工具窗口并打开 PDF。
- 服务端返回反馈已存在时，按已提交处理，刷新主页面状态并打开 PDF。
- 提交失败时窗口保持打开，草稿不丢失，并显示经过格式化的错误信息。
- 窗口加载失败或无法创建时，主页面显示“反馈窗口打开失败”，不影响报告查看和其他任务操作。

## 7. SVN 预检

### 7.1 模块职责

新增独立 SVN 预检模块，输入包括：

- SVN 地址
- 旧版本号
- 新版本号
- 可选的 `AbortSignal`
- 可替换的命令执行依赖，便于单元测试

输出为成功结果；任何失败通过带错误类别的异常返回，由 `task-agent` 转换为用户可读错误。

### 7.2 参数格式校验

- SVN 地址去除首尾空白后不能为空。
- 旧版本号必须是大于或等于 `0` 的十进制整数。
- 新版本号必须是大于 `0` 的十进制整数。
- 旧版本号不为 `0` 时必须小于或等于新版本号。
- 接受用户输入的可选 `r`/`R` 前缀，但传给 SVN CLI 前统一转换为纯数字。
- `r0` 与 `0` 都表示现有全量审查模式，不访问 SVN 的真实版本 0。

### 7.3 SVN 访问校验

校验顺序：

1. 对新版本执行 `svn info`，确认指定路径在新版本存在且可访问。
2. 旧版本不为 `0` 时，对旧版本执行 `svn info`。
3. 两次校验均成功后才允许准备工作区。

命令应：

- 使用 peg revision URL，避免路径在后续版本删除或重命名时产生歧义。
- 使用非交互执行方式，避免任务后台等待凭据输入。
- 复用当前环境检查中的 SVN 可执行文件定位和进程环境。
- 设置独立超时。
- 在任务取消时终止 SVN 子进程并返回取消结果。

### 7.4 错误分类

至少区分以下错误：

- 参数格式错误。
- 旧版本大于新版本。
- SVN 地址或路径不存在。
- 新版本不存在或路径在新版本不可用。
- 旧版本不存在或路径在旧版本不可用。
- SVN 认证失败。
- SVN 权限不足。
- 网络连接失败。
- SVN 命令超时。
- SVN CLI 启动失败。
- 用户取消任务。

错误消息必须说明失败对象，例如“新版本 r123 在该 SVN 地址下不存在或不可访问”，不能笼统输出错误报告。

原始 SVN stderr 只用于分类和日志，不直接完整展示。进入任务状态前继续执行现有敏感信息清理，避免暴露密码、Token、凭据参数和本地路径。

### 7.5 任务状态

- 服务端任务仍在点击“开始检查”后创建，确保失败任务可审计。
- 环境检查成功后进入 SVN 预检。
- 预检失败时任务状态更新为 `failed`。
- 错误原因写入 `error_message`，并通过现有进度事件立即更新任务看板。
- 预检失败后不得调用工作区准备、需求文件上传、Codex、报告生成或报告上传。
- 失败任务重试时重新执行完整环境检查和 SVN 预检。
- 任务取消优先于预检错误，取消后状态保持 `cancelled`。

## 8. 组件和文件边界

预计涉及的职责边界如下，具体文件名可在实施计划中按现有构建结构微调：

- `renderer/src/components/TaskForm.tsx`
  - 历史地址过滤与内联列表交互。
- `renderer/src/components/TaskPage.tsx`
  - 打开反馈工具窗口、接收报告定位和提交成功事件。
  - 移除主页面内的反馈弹窗拖拽状态。
- 独立反馈窗口 React 入口和组件
  - 展示会话、维护界面状态、发送草稿与提交请求。
- 专用反馈窗口 preload
  - 提供最小 IPC API。
- 主进程反馈窗口管理器
  - BrowserWindow 创建、复用、位置、父子窗口生命周期和会话管理。
- 主进程 IPC 注册
  - 主页面、反馈窗口和服务端反馈接口之间的消息转发。
- 主进程 SVN 预检模块
  - 参数校验、命令执行、超时、取消和错误分类。
- `main/task-agent.ts`
  - 在工作区准备前插入预检阶段。

## 9. 测试策略

### 9.1 TaskForm 单元测试

- 空输入聚焦时展示最近 3 条地址。
- 输入内容后只展示包含匹配项。
- 匹配忽略大小写。
- 无匹配时收起。
- 完全匹配时收起。
- 只有明确点击历史项才改变输入值。
- `Escape`、`Tab`、失焦和提交成功时收起。
- 历史列表在 DOM 结构中位于表单流内，不使用覆盖版本字段的绝对定位样式。
- 点击旧版本号和新版本号不会改变 SVN 地址。

### 9.2 反馈窗口测试

- 主进程只创建一个反馈工具窗口。
- BrowserWindow 正确绑定主窗口且不是全局置顶窗口。
- 重复打开时复用窗口并更新会话。
- 主窗口最小化、恢复、关闭时正确隐藏、显示和销毁工具窗口。
- 不同任务草稿相互隔离。
- 关闭后重新打开可恢复当前任务草稿。
- 候选项勾选会发送正确锚点。
- 主窗口收到锚点后滚动并高亮报告。
- 空反馈不能提交。
- 提交成功会更新主页面、关闭窗口并打开 PDF。
- 提交失败保留草稿并显示错误。
- 会话失效后窗口关闭，不能继续提交旧任务。
- 专用 preload 只暴露允许的 IPC。

### 9.3 SVN 预检测试

- 地址、旧版本和新版本格式校验。
- `r`/`R` 前缀规范化。
- `0` 全量审查模式跳过旧版本 SVN 访问。
- 旧版本大于新版本时不启动 SVN 命令。
- 新版本先于旧版本校验。
- 新旧版本命令参数包含正确 peg revision。
- 路径不存在、版本不存在、认证失败、权限不足、网络失败和 CLI 启动失败的错误映射。
- 超时会终止子进程。
- `AbortSignal` 取消会终止子进程并返回取消状态。

### 9.4 task-agent 测试

- 预检发生在工作区准备前。
- 预检失败时任务更新为 `failed`。
- 预检失败后工作区准备、需求文件上传、Codex、PDF 生成和报告上传均未调用。
- 预检错误经过敏感信息清理。
- 重试任务重新执行预检。
- 预检期间取消任务后状态为 `cancelled`。

### 9.5 真实 Electron 验收

- 窗口化运行主客户端，将反馈窗口拖到主窗口外。
- 验证反馈窗口保持在主窗口上方，但可以被其他应用覆盖。
- 验证主窗口最小化、恢复和关闭时的反馈窗口联动。
- 验证勾选反馈项后主报告正确滚动和高亮。
- 验证历史地址列表不覆盖版本号，填写版本号不会误改 SVN 地址。
- 使用错误地址、错误新版本、错误旧版本、无权限地址和网络中断分别验证任务立即失败且不生成报告。

## 10. 验收标准

- 用户填写 SVN 地址后可以直接点击版本号字段，SVN 地址不会被历史记录误替换。
- 历史记录只显示匹配项，并按设计条件及时收起。
- 反馈工具窗口能够完全移动到主客户端外部。
- 反馈窗口与主报告的定位、高亮、提交和 PDF 打开流程保持可用。
- 错误 SVN 参数不会启动 Codex。
- 预检失败不会生成或上传 Markdown/PDF 报告。
- 失败任务保留在任务历史中，并显示具体、脱敏的错误原因。
- 所有新增自动化测试通过，真实 Electron 窗口行为完成手工验收。
