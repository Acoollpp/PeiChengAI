# Electron 默认菜单与动态报告文件名设计

## 背景

Windows 版 Electron 客户端当前显示默认原生菜单栏，包括 `File`、`Edit`、`View`、`Window`、`Help`。这些菜单来自 Electron 默认应用菜单，和代码审查客户端的业务功能无关，容易造成干扰。

审查报告当前固定命名为 `代码审查报告.md`。多个任务生成后，本地报告文件名缺少版本信息和生成时间，不利于用户定位，也不符合“旧版本号_新版本号_时间戳”的识别习惯。

## 目标

1. 移除 Windows 客户端顶部默认菜单栏。
2. 保留窗口标题、应用图标、窗口控制按钮和页面内容。
3. 新生成报告使用 `r旧版本_r新版本审查报告_YYYYMMDD_HHmmss.md` 命名。
4. 本地报告路径、上传文件名和服务端下载文件名保持一致。
5. 历史任务保持兼容，没有动态报告名时继续回退到原固定名称。

## 非目标

1. 不调整客户端页面布局和业务导航。
2. 不修改报告正文内容。
3. 不迁移历史报告文件实际存储路径。
4. 不改变服务端报告内容读取接口的响应格式。

## 方案选择

采用“客户端生成动态报告名，服务端记录上传文件名用于下载”的方案。

客户端最了解本次 Codex 报告的本地输出路径，因此由客户端根据任务旧版本号、新版本号和当前时间生成 Markdown 文件名。上传报告时使用该文件名作为 multipart 文件名。服务端保存报告内容时可以继续使用现有按任务 ID 存储的方式，但需要保存上传文件名，下载时优先使用该名称。

该方案可以让本地路径、界面提示、上传行为和下载体验一致，同时避免大范围调整服务端存储结构。

## 菜单处理设计

Electron 主进程在 `app.whenReady()` 后、创建窗口前清空应用菜单：

```ts
Menu.setApplicationMenu(null)
```

该调用只影响原生应用菜单，不影响渲染进程页面、窗口标题、图标和系统窗口控制按钮。实现位置放在主进程启动入口，确保开发模式和打包后的 Windows 客户端都使用相同逻辑。

## 报告命名设计

新增共享报告文件名生成函数，输入旧版本号、新版本号和可选时间，输出格式：

```text
r旧版本_r新版本审查报告_YYYYMMDD_HHmmss.md
```

示例：

```text
r123_r456审查报告_20260610_142530.md
```

生成规则：

- 旧版本号和新版本号来自任务的 `old_revision`、`new_revision`。
- 如果版本号已经带 `r` 前缀，生成时仍统一输出单个 `r` 前缀。
- 时间戳使用本地时间，格式固定为 `YYYYMMDD_HHmmss`。
- 文件名只包含 Windows 文件名安全字符。

客户端创建服务端任务后，用返回任务里的版本号生成报告文件名，并将报告路径设置为：

```text
runtime-data/workspaces/<taskId>/<动态报告文件名>
```

图片目录仍保持：

```text
runtime-data/workspaces/<taskId>/images
```

## 上传与下载设计

客户端上传报告时，multipart 文件名使用动态报告文件名。服务端保存报告内容后，将上传文件名记录到任务表的新字段 `report_name`。

下载报告时：

1. 如果任务存在 `report_name`，`FileResponse.filename` 使用该值。
2. 如果任务没有 `report_name`，回退为 `代码审查报告.md`。

这样历史任务无需迁移，新任务下载名和本地报告名一致。

## 错误处理

报告文件名生成不依赖外部服务，不新增用户可见错误。若上传文件名缺失或为空，服务端回退到固定报告名。报告不存在、报告为空等错误继续沿用现有逻辑。

## 测试设计

Electron 客户端测试覆盖：

1. 主进程启动时调用 `Menu.setApplicationMenu(null)`。
2. 报告文件名生成格式为 `r123_r456审查报告_20260610_142530.md`。
3. 已带 `r` 前缀的版本号不会生成重复 `rr`。
4. 任务工作区的 `reportPath` 使用动态报告文件名。
5. 上传报告时 multipart 文件名使用 `basename(reportPath)`。

服务端测试覆盖：

1. 上传报告后记录上传文件名。
2. 下载报告时优先使用 `report_name`。
3. 历史任务没有 `report_name` 时回退为 `代码审查报告.md`。

## 验收标准

1. Windows 客户端窗口不再显示 `File / Edit / View / Window / Help` 默认菜单。
2. 新生成报告名形如 `r123_r456审查报告_20260610_142530.md`。
3. 客户端完成任务后的“报告已生成”提示展示动态报告路径。
4. 从服务端下载新报告时，下载文件名与上传的动态报告名一致。
5. 历史报告仍可正常查看和下载。
