# 部门管理员权限设计

## 背景

代码审查平台当前已有正式部门模型、用户部门归属、任务部门快照、重点审查方向库和任务报告下载能力。现有权限主要分为 `admin` 和 `user`：

- `admin` 拥有平台级管理能力，可管理部门、用户、任务、重点审查方向、Skill 库和客户端版本。
- `user` 只能使用自己的任务、报告和普通功能。

部门管理功能已经完成，下一步需要增加部门管理员权限。部门管理员只管理自己绑定的单个部门，核心目标是查看本部门成员生成的代码审查报告，并维护本部门的审查方向库。现有 `admin` 权限保持超级管理员语义不变。

## 已确认需求

1. 新增部门管理员角色，首版采用 `UserRole.department_admin`。
2. 部门管理员只管理自己账号绑定的单个部门。
3. 现有 `admin` 继续作为超级管理员，权限不削弱。
4. 部门管理员不新增用户，用户仍主要通过 CCH 同步产生，用户首次登录后选择部门归属。
5. 部门管理员可以进入用户管理，但只能只读查看本部门用户。
6. 部门管理员不能新增、编辑、删除用户，不能调整角色。
7. 部门管理员可以查看自己部门成员生成的任务报告，并下载 Markdown 和 PDF。
8. 报告归属按任务创建时保存的 `ReviewTask.department_id` 判断，不按用户当前部门动态变更。
9. 部门管理员可以维护绑定自己部门的审查方向。
10. 多部门共享方向和全局方向由超级管理员维护。
11. 部门管理员可以看到并使用共享方向，但不能维护共享方向。
12. 普通用户权限保持现状。
13. 用户可见提示和错误信息使用中文。

## 非目标

1. 不实现完整 RBAC 权限表、权限点配置或角色权限后台。
2. 不支持一个部门管理员管理多个部门。
3. 不引入方向共享申请、审批或发布流程。
4. 不允许部门管理员管理部门本身。
5. 不允许部门管理员管理 Skill 库、客户端版本或平台级配置。
6. 不改变 CCH 同步创建用户的主流程。
7. 不调整历史任务的部门快照数据。

## 方案选择

### 方案 A：新增 `department_admin` 角色

在现有 `UserRole` 增加 `department_admin`，保留 `admin` 作为超级管理员。后端新增角色判断和范围过滤函数，任务、报告、统计、方向库和用户列表复用统一的权限范围。

这是本次采用的方案。它符合现有代码结构，改动集中，角色语义清晰。

### 方案 B：用户表增加 `is_department_admin`

通过布尔字段表示部门管理员身份。迁移简单，但后续权限组合会分散，角色展示、前端菜单和接口判断容易出现重复逻辑。

### 方案 C：完整 RBAC

新增角色、权限、用户角色映射和后台配置。扩展性最好，但对当前单部门管理员需求过重，首版实现和验证成本偏高。

## 角色模型

### 超级管理员

`UserRole.admin` 表示超级管理员。它保持现有能力：

- 管理全部部门。
- 管理全部用户。
- 查看、下载、删除和统计全部任务报告。
- 维护全局方向、单部门方向和多部门共享方向。
- 管理 Skill 库和客户端版本。

### 部门管理员

`UserRole.department_admin` 表示部门管理员。部门管理员必须绑定一个启用部门，才能管理该部门范围内的数据。

能力：

- 只读查看本部门用户。
- 查看本部门任务和报告。
- 下载本部门任务的 Markdown 报告和 PDF 报告。
- 查看本部门任务统计。
- 新增、编辑和停用绑定自己部门的审查方向。
- 查看和使用全局方向以及包含自己部门的共享方向。

限制：

- 不能新增、编辑或删除用户。
- 不能调整用户角色。
- 不能查看其他部门用户详情。
- 不能删除任务或更新成员任务状态。
- 不能上传或覆盖成员任务报告。
- 不能维护全局方向。
- 不能维护多部门共享方向。
- 不能维护其他部门方向。
- 不能管理部门、Skill 库、客户端版本和平台级配置。

### 普通用户

`UserRole.user` 保持现状：

- 查看和管理自己的任务。
- 查看和下载自己的报告。
- 使用可见的全局方向、自己部门方向和包含自己部门的共享方向。
- 不能进入管理型用户列表。

## 后端权限设计

### 权限辅助函数

建议在 `app/api/deps.py` 或相邻权限模块中形成以下函数：

- `has_platform_admin_privileges(user)`：仅 `role == UserRole.admin`。
- `has_department_admin_privileges(user)`：`role == UserRole.department_admin` 且 `department_id` 不为空。
- `has_management_privileges(user)`：超级管理员或部门管理员。
- `require_platform_admin(user)`：只允许超级管理员。
- `require_management_user(user)`：允许超级管理员和部门管理员。
- `ensure_department_admin_has_department(user)`：部门管理员没有部门时抛出 403。

为了兼容现有代码，`has_admin_privileges()` 可以保留但语义需要明确。如果它继续表示超级管理员，就只返回 `role == admin`。需要管理入口的地方不要直接复用它，应改用新的管理权限函数。

### 任务范围函数

任务、报告和统计使用同一个范围过滤函数：

- 超级管理员：无过滤，读取全量。
- 部门管理员：过滤 `ReviewTask.department_id == current_user.department_id`。
- 普通用户：过滤 `ReviewTask.user_id == current_user.id`。

部门管理员的报告归属按任务创建时的部门快照判断。用户后来换部门不会改变历史任务和报告归属。

## API 设计

### 用户 API

`GET /api/v1/users/`

- 超级管理员：返回全量用户，保留现有搜索和分页。
- 部门管理员：返回 `User.department_id == current_user.department_id` 的用户，保留搜索和分页。
- 普通用户：403。
- 部门管理员未绑定部门：403，提示“当前账号未绑定部门，请联系超级管理员。”

`GET /api/v1/users/{user_id}`

- 用户本人：可读取自己。
- 超级管理员：可读取任意用户。
- 部门管理员：只能读取本部门用户。
- 目标用户不存在时返回 404；目标用户存在但不在当前用户权限范围内时返回 403。

`POST /api/v1/users/`、`PATCH /api/v1/users/{user_id}`、`DELETE /api/v1/users/{user_id}`

- 仅超级管理员可用。
- 部门管理员访问返回 403。

### 任务与报告 API

以下接口统一复用任务范围函数：

- `GET /api/v1/review-tasks`
- `GET /api/v1/review-tasks/{task_id}`
- `GET /api/v1/review-tasks/{task_id}/report`
- `GET /api/v1/review-tasks/{task_id}/download`
- `GET /api/v1/review-tasks/{task_id}/pdf/download`
- `GET /api/v1/review-tasks/stats`

行为：

- 超级管理员查看全量。
- 部门管理员查看本部门任务。
- 普通用户查看本人任务。

以下写操作不因为部门管理员角色扩权：

- `DELETE /api/v1/review-tasks/{task_id}`
- `PATCH /api/v1/review-tasks/{task_id}/status`
- `POST /api/v1/review-tasks/{task_id}/report`
- `POST /api/v1/review-tasks/{task_id}/pdf-report`
- `POST /api/v1/review-tasks/{task_id}/requirement-file`

部门管理员对这些接口返回 403，除非未来另有明确需求。

### 重点审查方向 API

方向库沿用现有多部门绑定能力。

`GET /api/v1/review-focus-directions`

- 超级管理员：返回全量，支持全局、指定部门、多部门方向筛选。
- 部门管理员：返回绑定自己部门的单部门方向；可选择同时展示只读的全局和共享方向，页面上不提供维护操作。
- 普通用户：不能进入管理型方向列表。

`POST /api/v1/review-focus-directions`

- 超级管理员：可创建全局、单部门、多部门共享方向。
- 部门管理员：只能创建绑定自己部门的单部门方向。请求里如果传入其他部门、多个部门或空部门，后端返回 403，避免前端误传时悄悄改变用户意图。
- 普通用户：403。

`PATCH /api/v1/review-focus-directions/{direction_id}`

- 超级管理员：可编辑全量。
- 部门管理员：只能编辑绑定自己部门且只绑定自己部门的方向；可编辑标题、内容、启用状态。
- 部门管理员不能把方向改为全局、其他部门或多部门共享。
- 共享方向只能由超级管理员维护。

`DELETE /api/v1/review-focus-directions/{direction_id}`

- 超级管理员：保持现有停用行为。
- 部门管理员：只能停用绑定自己部门且只绑定自己部门的方向。
- 部门管理员停用共享方向返回 403，提示“共享方向只能由超级管理员维护。”

普通用户方向选择接口继续返回启用的全局方向、自己部门方向和包含自己部门的共享方向。

## 前端设计

### 菜单

超级管理员菜单保持现状：

- 主页
- 部门管理
- 用户管理
- 重点审查方向
- 意见管理
- 任务管理
- Skill 库
- 客户端版本

部门管理员菜单：

- 主页
- 用户管理
- 重点审查方向
- 意见管理
- 任务管理

普通用户菜单保持现状：

- 主页
- 意见管理
- 任务管理

### 路由守卫

新增或调整前端权限工具函数：

- `hasPlatformAdminPrivileges(user)`
- `hasDepartmentAdminPrivileges(user)`
- `hasManagementPrivileges(user)`

`/admin/users` 允许超级管理员和部门管理员进入。页面根据角色切换能力。

重点审查方向页面保留现有路径，并允许超级管理员和部门管理员进入；后端必须做最终权限判断。

`/admin/skills`、`/admin/client-releases`、部门管理页面仍只允许超级管理员。

### 用户管理页面

超级管理员保持现有能力。

部门管理员模式：

- 列表只显示本部门用户。
- 隐藏新增用户入口。
- 隐藏编辑用户入口。
- 隐藏删除用户入口。
- 角色列显示中文角色名称。
- 可保留搜索。
- 如果当前部门管理员未绑定部门，显示中文空态提示“当前账号未绑定部门，请联系超级管理员。”

### 任务报告页面

任务管理页面复用现有 `/tasks/review`：

- 超级管理员看到全量任务。
- 部门管理员看到本部门任务。
- 普通用户看到本人任务。

部门管理员可以查看详情、读取 Markdown 报告、下载 Markdown、下载 PDF。删除、状态更新、报告上传等成员任务写操作不展示。

### 重点审查方向页面

超级管理员保持完整能力。

部门管理员模式：

- 列表展示自己部门可维护的方向。
- 可新增自己部门方向，部门字段由当前用户部门决定。
- 不显示多部门选择控件。
- 不显示全局方向创建入口。
- 不允许编辑共享方向。
- 共享方向可以在选择场景中出现，但管理页不作为可编辑项展示；如果展示，需要明确为只读。
- 用户输入统计中的跨部门筛选和导出能力只对超级管理员开放。

## 错误处理

1. 部门管理员未绑定部门访问管理范围接口：403，“当前账号未绑定部门，请联系超级管理员。”
2. 部门管理员访问其他部门用户、任务、报告、方向：403，“没有足够权限。”
3. 部门管理员维护共享方向：403，“共享方向只能由超级管理员维护。”
4. 部门管理员创建或编辑方向时传入其他部门：403，“只能维护本部门审查方向。”
5. 普通用户访问管理接口：403，“没有足够权限。”
6. 超级管理员访问保持现有行为和错误语义。

## 数据迁移

新增枚举值 `department_admin`。数据库层如果没有约束枚举类型，只需要更新应用模型和 OpenAPI 类型；如果数据库使用枚举约束，需要补充 Alembic 迁移。

历史用户不自动变更角色。部门管理员由超级管理员在用户管理页面手动设置角色并绑定部门。

## 测试计划

### 后端测试

新增或扩展以下测试：

1. `GET /users/`：
   - 超级管理员返回全量。
   - 部门管理员只返回本部门用户。
   - 部门管理员未绑定部门返回 403。
   - 普通用户返回 403。
2. `GET /users/{id}`：
   - 部门管理员可查看本部门用户。
   - 部门管理员查看其他部门用户返回 403。
3. 任务列表和详情：
   - 超级管理员全量。
   - 部门管理员只看到 `ReviewTask.department_id` 为自己部门的任务。
   - 普通用户只看到本人任务。
4. 报告读取和下载：
   - 部门管理员可读取和下载本部门任务 Markdown/PDF。
   - 部门管理员访问其他部门任务报告返回 403。
5. 任务统计：
   - 部门管理员统计只包含本部门任务。
6. 任务写操作：
   - 部门管理员删除、状态更新、上传报告、上传需求附件返回 403。
7. 方向库：
   - 超级管理员可维护全局、单部门、多部门方向。
   - 部门管理员可创建本部门方向。
   - 部门管理员不能创建全局、多部门或其他部门方向。
   - 部门管理员不能编辑或停用共享方向。
   - 普通用户不能访问管理型方向写接口。

### 前端测试

1. 权限工具函数识别 `admin`、`department_admin`、`user`。
2. 侧边栏：
   - 超级管理员显示完整管理菜单。
   - 部门管理员显示用户管理、重点审查方向、意见管理、任务管理。
   - 普通用户不显示用户管理和重点审查方向管理。
3. 用户管理页面：
   - 部门管理员模式隐藏新增、编辑、删除操作。
   - 部门管理员未绑定部门显示中文空态。
4. 方向库页面：
   - 部门管理员隐藏部门多选和全局方向能力。
   - 部门管理员不能触发共享方向编辑操作。
5. 任务页面：
   - 部门管理员可看到报告下载入口。
   - 部门管理员不显示成员任务删除、上传等写操作。

## 验收标准

1. 超级管理员现有功能不回退。
2. 部门管理员只能查看本部门用户，且用户管理只读。
3. 部门管理员能查看、读取和下载本部门任务的 Markdown/PDF 报告。
4. 部门管理员看不到其他部门任务报告。
5. 部门管理员任务统计只包含本部门任务。
6. 部门管理员能维护本部门单部门方向。
7. 部门管理员不能维护全局方向、多部门共享方向或其他部门方向。
8. 普通用户权限保持现状。
9. 所有新增用户可见提示为中文。
