# 任务时间与状态展示设计

## 背景

代码审查任务在服务端 `review_task` 表中已经包含 `started_at` 和 `finished_at` 字段，后端状态更新接口也会在任务开始执行和进入终态时维护这两个时间。当前缺口主要在展示层：

1. Electron 客户端任务看板没有展示任务开始时间和结束时间。
2. Web 前端“代码审查任务管理”表格没有展示开始时间和结束时间。
3. Web 前端任务状态当前按普通字符串输出，显示的是原始英文枚举值，不符合管理后台的状态展示预期。

本次设计聚焦展示补齐，不新增任务调度、状态流转或数据库字段。

## 目标

1. Electron 客户端每个任务卡片展示开始时间和结束时间。
2. Web 前端“代码审查任务管理”表格展示开始时间和结束时间。
3. Web 前端任务状态从原始文本改为中文彩色状态徽标。
4. 前端类型使用已有枚举类型，避免把状态继续当作任意字符串处理。
5. 保持后端数据模型和 API 语义稳定。

## 非目标

1. 不新增数据库字段或 Alembic 迁移。
2. 不重命名 `started_at`、`finished_at` 字段。
3. 不允许管理员在任务管理表格里手工修改任务状态。
4. 不为本地排队任务新增持久化时间字段。
5. 不调整任务状态机和执行流程。

## 方案选择

采用复用现有服务端字段的展示补齐方案。

后端 `ReviewTask` 和 `ReviewTaskPublic` 已经包含：

```py
started_at: datetime | None
finished_at: datetime | None
```

任务首次进入非 `created` 状态时写入 `started_at`，任务进入 `success`、`failed`、`environment_error`、`cancelled` 等终态时写入 `finished_at`。这两个字段已经随任务列表接口返回，因此客户端和 Web 前端只需要补齐类型、格式化和展示。

没有选择新增 `start_time/end_time` 字段，因为会造成重复语义、迁移成本和接口兼容风险。没有选择前端本地估算时间，因为刷新后会丢失，且容易与服务端真实时间不一致。

## 数据流

### 服务端

后端保持现状：

1. `POST /api/v1/review-tasks` 创建任务时，任务状态为 `created`，`started_at` 和 `finished_at` 为空。
2. `PATCH /api/v1/review-tasks/{task_id}/status` 接收到非 `created` 状态时，如果 `started_at` 为空则写入当前 UTC 时间。
3. 状态进入终态时写入 `finished_at`。
4. `POST /api/v1/review-tasks/{task_id}/report` 上传报告并标记成功时，确保 `started_at` 和 `finished_at` 都有值。
5. `GET /api/v1/review-tasks` 返回任务列表时继续包含 `started_at` 和 `finished_at`。

### Electron 客户端

Electron 共享类型 `ReviewTask` 补齐：

```ts
started_at?: string | null
finished_at?: string | null
```

客户端任务看板的数据来源分两类：

1. 服务端任务：通过 `window.codeReview.listTasks()` 拉取，直接使用服务端返回的时间。
2. 本地排队任务：尚未创建服务端任务，开始时间和结束时间为空，展示为 `-`。

本次不引入额外本地时间持久化。任务执行中的最终展示以服务端返回或下一次列表刷新为准。

### Web 前端

Web 前端任务表格使用生成客户端类型中的 `ReviewTaskStatus`，不再把状态声明为普通 `string`。`started_at` 和 `finished_at` 使用 API 返回值，统一通过格式化函数展示。

## Electron UI 设计

任务看板的每张任务卡片在“旧版本 / 新版本”元信息下方增加：

```text
开始时间  2026/6/11 14:03:20
结束时间  -
```

展示规则：

1. 有时间值时使用本机区域时间格式展示。
2. 空值、缺失值或解析失败时显示 `-`。
3. 排队任务通常开始时间和结束时间都为 `-`。
4. 运行中任务可能只有开始时间，结束时间为 `-`。
5. 历史任务尽量展示开始时间和结束时间。

布局继续使用任务卡片内的 `dl.task-meta` 样式。元信息从 2 项扩展到 4 项，不新增弹窗或详情页，保证用户在任务看板上能直接扫描。

## Web UI 设计

“代码审查任务管理”表格新增两列：

```text
用户名称 | SVN账号 | SVN地址 | 版本 | 状态 | 开始时间 | 结束时间 | 错误信息 | 报告 | 操作
```

开始时间和结束时间放在“状态”之后、“错误信息”之前。这样能先看到任务当前状态，再看到状态对应的时间信息。

状态列改为中文彩色徽标：

| 状态值 | 展示文案 | 视觉语义 |
| --- | --- | --- |
| `created` | 已创建 | 灰色 |
| `checking_environment` | 检查环境 | 蓝色 |
| `running_codex` | 审查中 | 蓝色 |
| `uploading_report` | 上传报告 | 蓝色 |
| `success` | 已完成 | 绿色 |
| `failed` | 失败 | 红色 |
| `environment_error` | 环境异常 | 红色 |
| `cancelled` | 已取消 | 灰色 |

未知状态使用原始状态文本和普通 outline 徽标兜底，避免后端未来扩展枚举时页面崩溃。

表格列数增加后继续保留现有截断策略：

1. SVN 地址保持单行截断。
2. 错误信息保持单行截断并使用 `title` 展示完整内容。
3. 报告和删除操作保持图标按钮。

## 异常处理

时间格式化函数需要处理以下输入：

1. `undefined`
2. `null`
3. 空字符串
4. 无法被 `Date` 正确解析的字符串

以上情况统一返回 `-`。时间解析失败不抛出到 React 渲染层。

状态展示函数需要处理未知字符串。未知状态不影响整行渲染，直接展示原始值。

## 测试设计

### Electron

补充 `TaskBoard` 组件测试：

1. 给定包含 `started_at` 和 `finished_at` 的任务，任务卡片展示开始时间和结束时间标签。
2. 给定时间为空的任务，开始时间和结束时间显示 `-`。
3. 运行中任务只包含开始时间时，结束时间显示 `-`。

如格式化函数独立导出，可以增加纯函数测试覆盖合法时间、空值和非法时间。

### Web 前端

补充 `TasksPage` 或拆分后的状态组件测试：

1. 状态 `running_codex` 展示为“审查中”徽标。
2. 状态 `success` 展示为“已完成”徽标。
3. 未知状态展示原始文本。
4. 表格展示“开始时间”和“结束时间”列。
5. 空时间显示 `-`。

### 后端

后端无需新增迁移测试。可复用现有 API 测试确认任务列表响应里保留 `started_at` 和 `finished_at` 字段，避免前端依赖字段被误删。

## 兼容性

1. 旧任务没有开始时间或结束时间时，前端显示 `-`。
2. 前端生成客户端已经包含 `ReviewTaskStatus`、`started_at` 和 `finished_at`，Web 端优先复用已有生成类型。
3. Electron 类型补齐后不影响现有任务执行、报告读取和取消任务逻辑。
4. 本次不改变接口路径、请求体或响应字段名称。
