# 旧版本号 0 触发全量审查设计

## 背景

当前代码审查平台以 SVN 双版本差异审查为核心流程。Electron 客户端要求用户填写 SVN 地址、旧版本号和新版本号；服务端 `ReviewTaskCreate` 对 `old_revision`、`new_revision` 做必填和版本格式校验；创建任务时还会禁止旧版本与新版本相同。客户端随后把两个版本号传给 Codex，提示词要求对应 Skill 按 SVN 获取策略执行 `旧版本 -> 新版本` 的代码变更审查。

用户反馈的实际场景是：某些项目没有可用于对比的旧版本，只需要对目标 SVN revision 的完整代码做一次全量静态审查。这个场景不是“空目录到首次提交”的 diff 审查，而是“审查目标版本完整代码”。如果继续强制填写真实旧版本号，用户无法表达全量审查意图；如果随便填一个版本号，Skill 可能执行错误 diff 并生成误导报告。

为了降低改动范围，本期不新增任务模式字段。平台约定：旧版本号填写 `0` 时表示全量审查。

## 目标

1. 用户在旧版本号填写 `0` 或 `r0` 时，可以发起目标版本的全量代码审查。
2. 差异审查继续保持现有体验：旧版本号和新版本号都必填，且旧版本不能等于新版本。
3. 全量审查不执行 `svn diff -r 0:新版本`，避免把 `0` 当作真实 SVN revision。
4. Codex 提示词明确告诉 Skill：`r0 -> r新版本` 是平台约定的全量审查，不是 SVN 双版本 diff。
5. 报告名称、报告正文和任务展示尽量避免把全量审查误写成“旧版本对新版本差异”。
6. 更新 `通用-代码审查-模版一` 和 `通用-代码审查-模版二`，让两个平台模板都支持旧版本号 `0` 的全量审查语义。

## 非目标

1. 不新增 `review_mode`、`target_revision` 等数据库字段。
2. 不把新版本号改成可选；本期全量审查仍必须填写目标版本号。
3. 不支持直接审查 SVN HEAD 而不传 revision。
4. 不改造任务列表筛选、统计或权限逻辑。
5. 不改变历史任务数据；历史任务仍按已有旧/新版本字段展示。
6. 不新增第三种审查类型，例如 Git 全量审查或本地目录全量审查。

## 方案选择

采用“旧版本号 `0` 作为全量审查开关”的简化方案。

备选方案是新增显式 `review_mode = diff | full`。该方案语义更干净，但需要修改数据库模型、API schema、客户端表单、任务列表和报告命名链路，改动面较大。当前用户希望快速解决初始代码无法审查的问题，因此先使用 `0` 作为兼容性开关。

这个方案的关键约束是：所有会消费版本号的链路都必须知道 `old_revision = r0` 的特殊语义。尤其是 Codex 提示词和 Skill 获取策略，不能把 `r0` 传入 SVN diff。

## 平台行为

### 输入规则

Electron 表单继续展示：

- SVN 地址
- 旧版本号
- 新版本号

旧版本号输入框增加提示文案：`填 0 表示全量审查新版本代码`。

用户输入示例：

```text
SVN 地址：https://svn.example.com/project/trunk
旧版本号：0
新版本号：12345
```

提交后服务端统一规范化为：

```text
old_revision = r0
new_revision = r12345
```

### 服务端校验

`_normalize_revision` 继续支持数字和 `r数字` 格式，`0` 会规范化为 `r0`。

创建任务时的版本校验调整为：

1. `old_revision == r0` 时允许创建任务。
2. `old_revision != r0` 时，继续要求旧版本和新版本不同。
3. `new_revision == r0` 不允许创建任务，因为全量审查必须锁定一个真实目标版本。

错误信息使用中文，便于 Electron 客户端直接展示，例如：

- `新版本号不能为 0`
- `旧版本号和新版本号不能相同`

数据库字段仍保持非空字符串，不需要迁移。

### Codex 提示词

`buildReviewPrompt` 根据 `oldRevision` 是否为 `r0` 生成不同提示。

差异审查保持现有结构：

```text
- 旧版本号：r12
- 新版本号：r14
请严格按该 Skill 的输入模块、SVN 获取策略、规则模块、输出模块执行代码变更审查。
```

全量审查增加强约束：

```text
- 旧版本号：r0（平台全量审查占位，不是 SVN 真实旧版本）
- 新版本号：r12345

本次为全量代码静态审查。旧版本号 r0 仅表示平台约定的全量审查开关。
禁止执行 svn diff -r 0:12345。
必须获取 r12345 对应的完整代码，并基于完整代码执行静态审查。
报告中不得写成本次变更引入，应写成全量静态审查发现。
```

错误处理规范保留。全量审查时如果无法导出或读取目标版本完整代码，使用 `SVN_ERROR`，并说明尝试过的获取方式。

### 报告命名

`buildReviewReportFileName` 增加全量审查分支。

差异审查保持现有格式：

```text
r12_r14审查报告_20260629_103000.md
```

全量审查使用：

```text
全量审查_r12345_20260629_103000.md
```

这样避免生成 `r0_r12345审查报告`，减少用户误解。

### 任务展示

Electron 任务卡片和管理后台任务列表可以先继续显示版本字段，但全量审查应做最小文案优化：

- 当 `old_revision === r0` 时，版本范围显示为 `全量审查 r12345`。
- 其他情况继续显示 `r旧版本 -> r新版本`。

这个展示逻辑只影响 UI 文案，不改变 API 返回结构。

## Skill 更新

平台当前有两个审查模板，分别绑定：

- `通用-代码审查-模版一`
- `通用-代码审查-模版二`

两者都需要更新，因为用户可能选择任一模板发起全量审查。

### 模板一

更新位置：

- `SKILL.md`
- `references/10-输入模块/10-输入收集规则.md`
- `references/10-输入模块/20-SVN获取策略.md`
- `references/30-输出模块/10-报告模板规则.md`
- `references/30-输出模块/30-代码差异图生成规则.md`
- `references/30-输出模块/代码审查报告-模版一.md`

关键规则：

1. 旧版本号为 `0` 或 `r0` 时，识别为全量审查模式。
2. 全量审查必须使用新版本号作为目标 revision。
3. 全量审查禁止执行 `svn diff -r 0:新版本`。
4. 优先使用 `svn export -r 新版本 项目路径 临时目录` 获取完整代码。
5. 如果目标是本地工作副本，可先确认工作副本 revision 是否匹配新版本；无法确认时在报告中说明材料来源限制。
6. 报告审查方式写为 `全量代码静态审查，目标版本 r新版本`。
7. 报告结论不能使用“本次变更引入”“旧版本对新版本”这类 diff 语义，改用“全量审查发现”“目标版本存在”。
8. 代码差异图规则在全量审查下改为生成风险代码片段图、检查结果图或调用链说明图，不强制左右版本对比。

模板一的规则仍以完整报告和重点风险说明为主。全量审查没有 diff 最大文件时，重点文件范围改为：

- 项目入口、初始化、协议解析、状态机、持久化读写、定时器链路。
- 需求表、重点审查方向或部门规则点名的文件。
- `.c/.h` 中命名和路径显示为核心模块的文件。

### 模板二

更新位置：

- `SKILL.md`
- `references/10-输入模块/10-输入收集规则.md`
- `references/10-输入模块/20-SVN与封装文件处理.md`
- `references/20-规则模块/10-户用自检工具接入.md`
- `references/20-规则模块/11-高压自检工具接入.md`
- `references/30-输出模块/10-报告模板.md`
- `references/30-输出模块/20-变更图规则.md`
- `references/30-输出模块/代码审查报告-模版二.md`

关键规则：

1. 旧版本号为 `0` 或 `r0` 时，识别为全量审查模式。
2. `SVN 最新变更` 规则不能套用到全量审查；全量审查直接锁定新版本完整代码。
3. 户用和高压自检工具仍必须显式传入目标 revision，也就是新版本号。
4. “变更识别”章节改为说明审查范围：`全量代码，目标版本 r新版本`。
5. “对应变更图”在全量审查下可以是风险代码片段图或自检结果图，不要求旧/新版本左右对比。

模板二保持简易报告定位，不引入模板一的大量规则库维护能力。

## 数据流

1. 用户在 Electron 表单填写旧版本号 `0`、新版本号 `12345`。
2. Electron 创建服务端任务。
3. 服务端规范化版本号为 `r0`、`r12345`，校验新版本不是 `r0` 后保存任务。
4. Electron 根据服务端返回任务准备工作区和报告路径。
5. 报告文件名生成 `全量审查_r12345_时间.md`。
6. `buildReviewPrompt` 识别 `r0`，写入全量审查提示。
7. Codex 调用所选 Skill。
8. Skill 识别 `r0`，导出或读取 `r12345` 完整代码并生成全量静态审查报告。
9. Electron 上传 Markdown 和 PDF 报告。
10. 服务端任务列表和 Electron 任务看板显示 `全量审查 r12345`。

## 错误处理

1. 新版本号填写 `0` 或 `r0`：服务端返回 400，提示 `新版本号不能为 0`。
2. 普通差异审查中旧版本号等于新版本号：服务端返回 400，提示 `旧版本号和新版本号不能相同`。
3. 全量审查导出目标版本失败：Codex 输出 `[CODEX_ERROR::SVN_ERROR]`，说明 SVN URL、目标 revision、已尝试命令和失败原因。
4. Skill 未更新或未识别 `r0`：平台 Prompt 中的强约束应降低误执行概率；实现时仍需测试两个模板都不会调用 `svn diff -r 0:new`。
5. 报告生成失败：沿用现有 `REPORT_ERROR` 处理。

## 测试策略

### 服务端

覆盖 `review_tasks` 创建接口：

- `old_revision=0, new_revision=123` 创建成功，返回 `r0`、`r123`。
- `old_revision=r0, new_revision=r123` 创建成功。
- `old_revision=0, new_revision=0` 返回 400。
- `old_revision=12, new_revision=12` 返回 400。
- `old_revision=12, new_revision=13` 仍创建成功。

### Electron 主进程与共享工具

覆盖：

- 全量审查报告文件名为 `全量审查_r目标版本_时间.md`。
- 差异审查报告文件名保持原格式。
- `buildReviewPrompt` 在 `oldRevision=r0` 时包含“全量代码静态审查”和“禁止执行 svn diff -r 0”。
- `buildReviewPrompt` 在普通版本区间时不包含全量审查特殊提示。
- 任务执行流程将全量审查任务传入自定义报告名。

### Electron 渲染层

覆盖：

- 旧版本号输入框展示 `填 0 表示全量审查新版本代码` 提示。
- 提交 `0` 和 `123` 时 payload 仍包含 `old_revision: "0"`、`new_revision: "123"`。
- 任务卡片 `old_revision=r0` 时显示 `全量审查 r123`。
- 普通任务继续显示旧版本和新版本。

### 管理后台

覆盖：

- 管理任务列表 `old_revision=r0` 时显示 `全量审查 r123`。
- 普通任务继续显示 `r旧版本 -> r新版本`。

### Skill 验证

为两个 Skill 做一次人工或自动化冒烟验证：

- 输入旧版本 `0`、新版本 `12345`。
- 检查执行记录或输出说明中没有 `svn diff -r 0:12345`。
- 报告审查方式为全量代码静态审查。
- 报告结论没有把问题描述为“本次变更引入”。
- 报告能落盘到指定输出路径。

## 风险与缓解

### `0` 语义隐式

风险：用户或维护者不知道 `0` 是平台约定。

缓解：在客户端输入提示、Prompt、Skill 输入规则和设计文档中同时声明；任务展示也尽量显示 `全量审查`。

### Skill 仍按 diff 规则执行

风险：如果只改平台不改 Skill，Codex 可能仍按旧规则执行 `svn diff -r 0:new`。

缓解：平台 Prompt 和两个 Skill 获取策略都增加禁止规则，并在测试中检查关键提示文本和冒烟执行结果。

### 全量审查范围过大

风险：完整工程代码量较大，Codex 无法逐文件深入。

缓解：Skill 规则要求先识别入口、初始化、协议、状态机、持久化、定时器和部门重点方向，报告中明确审查覆盖范围和未覆盖限制。

### 报告图规则不匹配

风险：原规则强制左右差异图，全量审查没有旧版可对比。

缓解：全量审查下改为风险代码片段图、检查结果图或调用链说明图；差异审查仍使用旧/新版本左右对比图。

## 上线顺序

1. 修改服务端校验和测试。
2. 修改 Electron 报告命名、Prompt、表单提示、任务展示和测试。
3. 更新两个 Skill 的输入、SVN 获取、输出和图示规则。
4. 本地完成服务端、Electron 单元测试。
5. 用两个模板各跑一次 `old_revision=0` 的全量审查冒烟。
6. 打包或发布客户端前，确认客户端内置或同步的 Skill 已是更新后的版本。

## 验收标准

1. 用户填写旧版本号 `0`、新版本号 `12345` 能成功创建并执行审查任务。
2. 服务端保存任务为 `old_revision=r0`、`new_revision=r12345`。
3. Codex Prompt 明确说明本次为全量审查，禁止执行 `svn diff -r 0:12345`。
4. 报告文件名为 `全量审查_r12345_时间.md`。
5. 两个 Skill 都能识别 `r0` 全量审查并输出报告。
6. 报告正文使用全量静态审查语义，不把问题写成差异审查结论。
7. 普通差异审查行为和报告命名不回归。
