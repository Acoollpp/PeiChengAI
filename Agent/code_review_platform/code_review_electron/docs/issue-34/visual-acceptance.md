# Issue #34 工作台视觉验收

## 运行方式

```bash
npm run capture:workbench
```

脚本启动隔离的 Vite 验收入口，不访问服务端、数据库、SVN、Codex 或本地正式材料。生产 harness 直接渲染 `ProductionReviewWorkbench`，只在 Electron bridge 边界注入可控响应；生产入口与 harness 均不引用 fixture adapter。

## 视口

- 1440x900
- 1280x800
- 1024x768

## 自动断言

- 统计失败时显示明确错误与重试入口，创建表单、本机空队列和执行区域仍可用。
- 服务端今日运行、失败和完成计数来自统计 bridge，本机等待数来自当前 renderer 队列。
- 两个任务占用本机执行槽位，第三个任务显示为本机等待第 1 位。
- 长用户名、部门名、审查项名称、额外规则和材料文件名不造成横向溢出或控件重叠。
- 选择器打开后搜索框获得可见焦点，Escape 关闭后焦点返回触发按钮。
- 创建表单错误、禁用状态、任务列表、空报告区、报告中心和意见反馈区均保持既有布局。

## 结果

三个视口的全部脚本断言通过。人工复核 `production-stats-error-*` 与 `production-multi-task-*` 截图，错误说明、重试按钮、四列计数、三条任务和取消入口均未发生重叠或不可读截断。

`docs/issue-34/screenshots/` 只保留本 Issue 新增的统计失败和三任务队列场景，共 6 张截图。#37/#33 的既有布局与选择器场景仍执行全部自动断言，截图只写入运行期临时目录并在结束后清理；历史验收截图未修改。
