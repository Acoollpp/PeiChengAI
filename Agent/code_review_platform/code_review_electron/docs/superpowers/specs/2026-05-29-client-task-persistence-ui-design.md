# 客户端任务持久化与工作台 UI 优化设计

## 背景

当前 Electron 客户端的任务看板只使用前端运行时状态保存任务，应用重启或重新登录后任务列表会清空。工作台界面使用背景图和半透明面板，内容密度偏高；Markdown 预览只支持基础标题、列表、段落和行内代码，报告中的表格没有渲染为表格。任务看板中的 Codex 输出长短不一，会撑开任务卡片并造成整体布局高度变化。

## 目标

1. 登录同一账号后，从服务端恢复该账号历史审查任务。
2. 将工作台背景改为纯黑，并优化左右布局、面板间距和文字层级。
3. Markdown 预览补齐表格渲染，并改成固定报告面板内的内部滚动正文。
4. 任务看板卡片高度稳定，Codex 输出在卡片内部滚动或截断展示。

## 非目标

1. 不新增离线任务数据库或本地任务同步机制。
2. 不修改服务端任务生命周期语义。
3. 不重做登录页、权限模型或报告生成流程。

## 方案

### 任务数据来源

客户端以服务端任务列表为准。用户进入工作台后，主进程使用当前登录 token 调用服务端 `GET /api/v1/review-tasks`，渲染进程通过 IPC 获取任务列表并填充看板。

新建任务时，渲染进程继续创建一个本地 pending 任务卡片，用于立即反馈。服务端创建任务并开始执行后，进度事件携带真实任务 ID，前端用真实 ID 替换 pending ID。任务完成或失败后保留当前状态；必要时再次拉取服务端列表，确保与服务端一致。

### Markdown 预览

保留现有轻量 Markdown 渲染器，但扩展 pipe table 解析能力。渲染器识别连续的表格头、分隔行和数据行，输出 `<table>`、`<thead>`、`<tbody>`、`<tr>`、`<th>`、`<td>`。表格外层或表格自身允许横向滚动，避免宽表撑开页面。

右侧报告区改为固定高度面板：工具栏固定在顶部，正文区域使用 `overflow: auto` 内部滚动。长代码、长路径和宽表格只影响报告正文滚动区域。

### 工作台视觉

工作台背景改为纯黑，移除背景图片和装饰渐变。整体视觉采用工具型深色界面：左侧为固定宽度任务操作栏，右侧为报告阅读区；面板使用低透明深灰、细边框和明确间距。减少大面积模糊效果，提升文字对比度和可读性。

### 任务看板

任务看板中的每张任务卡片使用稳定尺寸约束。任务基础信息保持可扫读：任务 ID、状态、SVN 地址、版本号、当前进度。Codex 输出放入固定高度日志区域，只展示最近几条并在内部滚动。长文本使用换行和截断策略，避免撑开卡片和页面。

## 接口与组件变更

1. `ApiClient` 增加任务列表请求方法。
2. 主进程 IPC 增加 `task:list` handler，读取 token 后返回当前用户任务。
3. preload 和渲染层 API 增加 `listTasks()`。
4. `TaskPage` 初始化时加载任务列表，并在执行任务成功后维护真实任务 ID 和状态。
5. `MarkdownPreview` 继续使用 `renderMarkdown`，样式层补充表格、代码和内部滚动展示。
6. `TaskBoard` 和 CSS 增加固定高度、日志内部滚动和长文本处理。

## 错误处理

任务列表加载失败时，不阻断新建任务；界面显示一条可读错误信息，并保留空看板状态。未登录时 IPC 返回认证错误，渲染层按现有登录流程处理。Markdown 表格格式不完整时按普通段落渲染，避免误渲染破坏报告内容。

## 测试与验证

1. 为 Markdown 表格渲染增加单元测试。
2. 为任务列表 API/IPC 增加测试，覆盖已登录返回任务、未登录报错。
3. 运行 Electron 客户端 `npm test` 和 `npm run typecheck`。
4. 启动客户端或预览界面，检查纯黑背景、报告内部滚动、表格展示、任务看板稳定高度。
