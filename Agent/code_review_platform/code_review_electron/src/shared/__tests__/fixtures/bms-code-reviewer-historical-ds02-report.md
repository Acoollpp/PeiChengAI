## 三、审查问题

### DS-02-001 [高] FAULT 分支条件由比较表达式误改为赋值表达式

**所属审查项：** DS-02 · 编码规范审核
**规则章节：** 建议-用括号明确表达式的操作顺序，避免过分依赖默认优先级

**涉及文件及行号：**

| 文件 | 行号 | 位置说明 |
|------|------|----------|
| `bms_state.c` | 37 | `BmsState_Handle` 的 `BMS_STATE_FAULT` 状态判断 |
| `bms_state.h` | 19 | `BMS_EVENT_RESET` 枚举值定义 |

**问题描述：** r2 将 `BMS_STATE_FAULT` 分支中的 `if (event == BMS_EVENT_RESET)` 修改为 `if (event = BMS_EVENT_RESET)`。该条件表达式会先把 `BMS_EVENT_RESET` 赋给形参 `event`，而 `BMS_EVENT_RESET` 在枚举中为非零值，因此当 `current_state` 为 `BMS_STATE_FAULT` 时，该 `if` 分支会恒为真。
**影响风险：** FAULT 状态下任意事件都可能把 `current_state` 置为 `BMS_STATE_IDLE`，导致故障状态被非 RESET 事件清除。该问题由本次变更引入，具备可验证的状态机安全风险。
**整改建议：** 将条件恢复为明确的比较表达式 `if (event == BMS_EVENT_RESET)`，并结合编译告警或静态检查禁止条件表达式中的非预期赋值。

### DS-02-002 [中] 新增 SLEEP 状态分支的 if 缺少 else 分支

**所属审查项：** DS-02 · 编码规范审核
**规则章节：** 规则-if语句必须加上else分支（卫语句例外，其他场景均需要）；switch语句必须有default分支。

**涉及文件及行号：**

| 文件 | 行号 | 位置说明 |
|------|------|----------|
| `bms_state.c` | 31 | `BmsState_Handle` 中新增的 `BMS_STATE_SLEEP` 分支条件判断 |

**问题描述：** r2 新增的 `case BMS_STATE_SLEEP` 只处理 `(event == BMS_EVENT_START) && (pack_voltage_mv < BMS_MAX_PACK_VOLTAGE_MV)` 场景，`if` 后没有 `else` 分支，也不是直接退出的卫语句。规范要求非卫语句场景的 `if` 必须补充 `else`；确实无操作时也应写空 `else` 表明已考虑该路径。
**影响风险：** 当 `current_state` 为 `BMS_STATE_SLEEP` 且事件不是 `BMS_EVENT_START`，或包电压不低于阈值时，代码未显式说明应保持睡眠、进入故障或执行其他动作，状态机分支意图不闭环。
**整改建议：** 为 SLEEP 分支补充 `else`。如果确实无需动作，按规范保留空 `else`；如果需要兜底处理，则在 `else` 中明确维持状态或处理异常事件。

### DS-02-003 [低] 新增控制语句未采用 Allman 大括号风格

**所属审查项：** DS-02 · 编码规范审核
**规则章节：** 规则-大括号风格

**涉及文件及行号：**

| 文件 | 行号 | 位置说明 |
|------|------|----------|
| `bms_state.c` | 19 | r2 新增的 `else if (event == BMS_EVENT_STOP)` 分支 |
| `bms_state.c` | 32 | r2 新增的 `BMS_STATE_SLEEP` 分支内 `if` 条件结束行 |

**问题描述：** 规范要求采用 Allman 风格，左右括号都单独一行。r2 新增的 `} else if (event == BMS_EVENT_STOP) {` 以及 SLEEP 分支内条件结束行将左大括号放在控制语句同行，未满足强制大括号风格要求。
**影响风险：** 新增代码与公司强制编码风格不一致，降低同一状态机函数内代码风格统一性和可读性。
**整改建议：** 将本次新增控制语句调整为 Allman 风格，例如 `else if (...)` 后换行放置 `{`，SLEEP 分支的 `if` 条件结束后也单独换行放置 `{`。
