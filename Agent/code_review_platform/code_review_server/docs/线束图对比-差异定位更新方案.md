# 线束图对比差异定位更新方案

## 1. 更新背景

线束图对比平台已经能够识别出大部分文字差异，但部分差异在图纸上的显示位置不准确，主要表现为：

- 同一段文字在图纸中出现多次时，多个差异被定位到同一个位置。
- OCR 没有识别到的差异没有图上标记。
- 竖向或带 PDF 旋转属性的图纸，文字坐标与显示图片坐标不一致。
- 历史任务中的旧坐标已经被错误定位逻辑覆盖，直接刷新页面无法恢复正确位置。

本次更新重点解决差异坐标转换、重复文字分配和历史任务刷新三个问题。

## 2. 当前整体对比流程

平台采用“两阶段定位”方案：

1. **文字语义对比**
   - 读取旧图纸和新图纸的 PDF 文字层。
   - 对扫描图或文字层不完整的页面使用 OCR。
   - 对文字进行空格、全角半角等规范化。
   - 忽略印章、签字、日期、审核栏、图纸版次等非业务差异。
   - 对沛城型号、沛城料号、线材型号、工艺步骤等业务字段进行对比。

2. **图像显示定位**
   - 将 PDF 页面渲染为 PNG。
   - 对渲染后的图片再次进行 OCR，获取接近最终显示效果的文字框。
   - 将语义差异与渲染 OCR 文字框进行匹配。
   - 语义差异列表中点击某一项时，只显示该项对应的旧图和新图标记。

最终报告仍然采用：

- 旧图：红色差异标记。
- 新图：蓝色差异标记。
- 标记默认隐藏。
- 点击差异列表后显示对应标记，并定位到对应图纸位置。

## 3. 本次问题的根因

### 3.1 PDF 旋转坐标转换方向错误

PDF 的文字坐标通常使用未旋转坐标系，而 `get_pixmap()` 输出的是页面显示方向的图片。

原来的处理方式直接使用 PDF 的旋转角度进行坐标转换。当页面自身带有 `270°` 旋转属性时，实际应当使用反向旋转，但旧逻辑使用了同方向旋转，导致：

- 流程步骤标记跑到错误位置。
- 料表文字标记偏移。
- 图纸上横向内容和竖向内容的位置不一致。

### 3.2 重复文字候选被错误占用

例如新图中存在两处：

```text
4 打透明UV胶
```

旧逻辑选中一个 OCR 候选后，会把与该候选高度重叠的其他候选一起标记为已使用。这些候选实际上可能是同一段 OCR 生成的不同长度短语，或者是图中另一处真正独立的文字。

结果是：

- 第 6、7、9 项重复指向同一位置。
- 后续差异找不到可用候选。
- 某些差异被错误隐藏。

### 3.3 OCR 找不到文字时直接清空坐标

对于“第六步:包装”和“适量”等文字，语义识别阶段已经能够得到 PDF 原始坐标，但渲染 OCR 阶段未必能够再次识别到。

旧逻辑在渲染 OCR 找不到候选时直接返回 `None`，覆盖掉原先有效的语义坐标，因此差异列表有记录，但图上没有标记。

### 3.4 历史任务坐标已经被污染

历史任务的 `差异数据.json` 保存的是旧定位逻辑生成的最终坐标。仅修改代码后重新打开历史 HTML，仍然会读取旧坐标，因此无法自动恢复。

## 4. 本次核心更新

### 4.1 修正旋转坐标转换

文件：

`backend/app/services/wire_harness_annotation.py`

函数：

`_display_bbox`

处理规则：

```text
显示旋转角度 = (360 - PDF 页面旋转角度) % 360
```

也就是说：

- PDF 页面旋转 `0°`：不转换。
- PDF 页面旋转 `90°`：使用反向 `270°` 转换。
- PDF 页面旋转 `270°`：使用反向 `90°` 转换。
- PDF 页面旋转 `180°`：使用 `180°` 转换。

这样可以把 PDF 文字层坐标正确映射到最终显示图片坐标。

### 4.2 增加语义坐标备用机制

新增函数：

`_display_fallback_bbox`

定位时同时保留两套坐标：

1. 语义识别阶段得到的原始坐标。
2. 渲染图片 OCR 得到的显示坐标。

选择规则：

- 渲染 OCR 找到可信且距离合理的候选：使用渲染 OCR 坐标。
- 渲染 OCR 没有识别到文字：使用转换后的语义坐标。
- 两者均不存在：该侧不显示标记。

这样即使 OCR 漏识别，差异也不会完全失去定位。

### 4.3 重复文字按位置分配

函数：

`_select_rendered_box`

新的匹配优先级：

1. 候选文字必须与目标文字具有有效文本匹配关系。
2. 如果有语义坐标，优先选择距离语义坐标最近的候选。
3. 如果候选距离语义坐标过远，则放弃该 OCR 候选，保留语义坐标。
4. 只将实际选中的候选索引加入 `used`。
5. 不再把与选中框重叠的其他候选全部标记为已使用。

这样可以保证同一文字出现多次时：

- 第一条差异使用第一处位置。
- 第二条差异使用第二处位置。
- 后续差异不会因为前一个候选的重叠短语被误占用。

### 4.4 历史任务重新生成定位结果

函数：

`refresh_legacy_interactive_report`

刷新历史报告时，重新执行：

1. 读取历史任务目录中的原始旧图纸和原始新图纸。
2. 重新提取 PDF 文字和 OCR 文字。
3. 重新进行语义差异比对。
4. 使用修正后的 PDF 坐标转换。
5. 使用修正后的渲染 OCR 定位。
6. 重新写入 `差异数据.json`。
7. 重新生成交互式 HTML 报告。

如果历史文件损坏或无法重新读取，则保留原有差异记录，避免刷新操作直接失败。

## 5. 本次示例问题的处理结果

针对 `123456` 示例任务，本次更新处理了以下差异：

| 差异内容 | 处理结果 |
|---|---|
| `6.第六步:包装` | 恢复图上定位 |
| `适量` | 恢复图上定位 |
| 第一处 `4 打透明UV胶` | 使用独立坐标 |
| 第二处 `4 打透明UV胶` | 使用独立坐标 |
| 重复差异被指向同一位置 | 改为按位置分配 |
| 竖向流程文字位置错误 | 修正旋转坐标映射 |

刷新后的两个历史任务均满足：

- 每条有新图文字的差异都有 `new_bbox`。
- 各差异坐标互不重复。
- 点击差异列表后可以显示对应标记。

## 6. 交互报告行为

交互报告继续使用按需显示模式：

1. 页面加载时不显示全部标记。
2. 用户点击差异列表中的某一条。
3. 只显示该差异对应的旧图红色标记和新图蓝色标记。
4. 页面自动滚动到对应图纸位置。
5. 切换另一条差异时，隐藏上一条标记，显示当前差异标记。

这种方式可以避免多个编号同时覆盖图纸，降低误判概率。

## 9. 后续优化方向

当前方案已经解决本次暴露的定位问题，但后续还可以继续增强：

1. 将 PDF 原始文字框、OCR 文字框和最终采用坐标同时保存，方便问题追溯。
2. 给每个差异保存定位来源，例如：
   - `pdf_text`
   - `rendered_ocr`
   - `semantic_fallback`
3. 对同一页面的重复短语做全局最优匹配，而不是按差异顺序逐条匹配。
4. 对低置信度 OCR 候选增加“需人工确认”提示。
5. 增加图纸截图级回归样例，自动检查标记是否落在目标文字附近。
6. 将历史任务刷新入口集成到平台任务管理界面，避免手工刷新文件。

## 10. 结论

本次更新将差异定位从“单纯依赖渲染 OCR”调整为：

```text
语义识别坐标
        +
渲染图片 OCR 坐标
        +
页面旋转坐标修正
        +
按差异位置分配候选
        ↓
最终交互标记坐标
```

核心原则是：

- 文字差异先按语义识别。
- 图上位置再按显示图片进行校正。
- OCR 漏识别时保留语义坐标。
- 重复文字必须按空间位置区分。
- 历史报告必须重新生成最终坐标，不能继续使用旧定位结果。
