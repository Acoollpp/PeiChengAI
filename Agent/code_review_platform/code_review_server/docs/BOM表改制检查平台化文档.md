# BOM表改制检查平台化文档

更新时间：2026-07-29

## 目标

将本地 Codex Skill `bom-change-check` 接入现有代码审查平台，形成可在 Web 页面提交、后台执行、下载报告、查看任务状态和统计结果的任务模块。

平台模块名称：`BOM表改制检查`

页面路由：

- 用户提交页：`/tasks/bom-change-check`
- 管理页：`/tasks/bom-change-check-manage`

后端接口前缀：

- `/api/v1/bom-change-check-tasks`

## 平台化原则

本模块复用现有平台框架，不新建独立系统：

- 前端：React/Vite/TanStack Router
- 后端：FastAPI/SQLModel/Alembic
- 鉴权：沿用平台登录态和当前用户权限
- 存储：按任务 ID 创建输入、日志、报告目录
- 执行：后端调用本机 Codex，要求 Codex 使用 `$bom-change-check` skill

后端只负责调度、文件存储、解压、日志、状态和报告归档；BOM 检查业务逻辑由 Codex 按 skill 规则执行。平台不能直接绕过 Codex 完成业务判断。

A档执行策略：

- 后端仍调用 Codex。
- Codex 必须使用 `$bom-change-check` skill。
- Codex 必须调用 skill 内固定批处理脚本 `check_bom_change.py --batch-input ... --output-dir ...`。
- Codex 不重新生成临时批处理脚本，不手工逐个 Excel 分析。
- 固定脚本复用公司物料表索引，生成每个项目报告后立即写批量汇总和 `timing.jsonl`。
- 批量汇总统计直接来自内存检查行，不在同一批处理中重新打开大报告统计，避免重复耗时。

## 输入结构

用户在提交页上传一个项目压缩包，并可选上传一份新的替代料汇总表。项目压缩包支持：

- `.zip`
- `.rar`
- `.7z`

压缩包解压后放到：

```text
<task_dir>/input/projects/
```

资料按固定分类文件夹组织。完整改制检查模式下，项目压缩包至少包含：

```text
projects/
  改制前BOM/
    BOM-SST26-1101-1.0-备货-006.xlsx
    ...
  改制后BOM/
    BOM-SST26-1629-1.0-瑞能-001.xlsx
    ...
  改制表/
    改制单-616291001.xlsx
    ...
```

允许的同义文件夹名：

- `改制后BOM` 或 `更新后BOM`
- `改制表` 或 `改制单`

替代表由平台按“全平台最新版本”统一管理：

- 提交页新增 `关键物料替代表（可选，有更新时上传）` 和 `无关键物料替代表（可选，有更新时上传）` 两个上传项，支持 `.xlsx`、`.xlsm`。
- 用户本次上传其中一类替代表时，本次任务立即使用该文件，并保存为全平台对应类别的最新替代表；未上传的类别继续复用平台上一次保存的最新版本。
- 用户本次两类都未上传时，后端使用平台上一次保存的最新关键物料替代表和无关键物料替代表。
- 如果平台从未保存过替代表，且本次也未上传，后端在任务开始前拒绝提交，提示 `请先上传关键物料/无关键物料替代表`。
- 平台提交页分别显示当前生效关键物料替代表、无关键物料替代表信息：文件名、上传人、上传时间、文件大小。
- 网页上传或平台保存的最新替代表优先级最高。即使项目压缩包里包含 `公司物料表`、`公司总料表`、`总料表` 或 `替代料汇总表` 文件夹，后端也会忽略或移除压缩包内版本，并把网页最新版本复制到任务输入目录中供 Codex 检查。
- 后端会在任务输入目录写入说明文件 `网页替代表优先.txt`，该文件只作为人工说明，不是 Excel 输入。

同时支持只审查替代料是否合规的两类文件模式：

```text
projects/
  更新后BOM/
    BOM-SST26-1629-1.0-瑞能-001.xlsx
    ...
```

该模式下不需要 `改制前BOM` 和 `改制表/改制单`。每个更新后 BOM 生成一个项目报告，只核对更新后 BOM 中的替代料关系和客户限制。

完整改制检查资料中也可以额外放一个 `更新后BOM/` 文件夹，用于检查替代料组是否齐全：

```text
projects/
  改制前BOM/
  改制后BOM/
  改制表/
  更新后BOM/
```

这种情况下，原来的改制检查照常执行；同时对 `更新后BOM/` 或 `更新BOM/` 中每个 BOM 反查替代表，检查替代料组是否齐全。只要 BOM 中出现某个非 K 关系组的任一物料，就要求该组所有应加入物料都出现在 BOM；O 列包含当前 BOM 客户的物料不要求加入，备货不按客户排除。该报告只输出缺失项，正常项不输出。

`替代料组齐全差异.xlsx` 的缺失项只从 `总替代料汇总表` 生成。`取消替代关系物料` 不用来要求 BOM 补齐一整行物料，只作为兜底放行：如果 `更新后BOM` 中某个物料没有出现在 `总替代料汇总表`，但出现在 `取消替代关系物料`，不算异常，也不要要求把该取消关系行里的其它料号全部加入 BOM。

`替代料组齐全差异.xlsx` 必须给 `更新后BOM` 里的每个 BOM 都保留一个 sheet。该 BOM 有缺失项时列缺失项；没有缺失项时也保留 sheet，并写一行 `备注=无缺失项`，其它明细列留空。

新的压缩包也支持按日期提交更新 BOM：

```text
projects/
  更新BOM/
    2026-9-7/
      BOM-xxx匹配关键物料表.xlsx
      BOM-xxx匹配无关键物料表.xlsx
      BOM-xxx.xlsx
    2026-9-8/
      ...
```

这种日期目录模式按日期生成报告：每个日期文件夹输出一个 `BOM表改制检查报告-日期.xlsx`，每个 BOM 一个 sheet。文件名含 `匹配关键物料表` 的 BOM 用关键物料替代表；含 `匹配无关键物料表` 的 BOM 用无关键物料替代表；两个关键词都没有的 BOM 不检查，但必须保留 sheet 并写 `备注=跳过`。有关键词的 BOM 还要扫描所有真实 BOM sheet 的自检异常，包含分层错误、用量与位号数量不一致、位号重复和 BOM 字段缺失，并在对应 BOM sheet 用简短备注标识。日期目录模式不再额外生成 `替代料组齐全差异.xlsx`。

如果 `总替代料汇总表` 中同一个归一化关系编号被重复用于不连续的多块物料，`更新后BOM` 替代料组齐全检查不能跨块合并。每次再次出现基础关系编号时都视为新的替代关系块。例如前面 LCD 的 `T1005/T1005-1` 和后面电容的 `T1005/T1005-1` 不能互相要求齐全。

## 匹配规则

完整改制检查模式下，每个改制表生成一个项目报告。

改制表中按 `归属` 列识别前后版本：

- `归属=保护板1` 这一行的 `规格型号` 是改制前
- `归属=保护板2` 这一行的 `规格型号` 是改制后
- `接口板1`、`显示板1`、`LED彩灯条1` 和标题行不参与前后 BOM 匹配

匹配重点是“项目号 + 版本号”。

示例：

```text
BOM-SST26-1101-1.0-备货-006  -> 匹配键：1101-1.0
P8S150A-61101-1.0             -> 去掉项目号前导业务前缀 6 后：1101-1.0

BOM-SST26-1629-1.0-瑞能-001  -> 匹配键：1629-1.0
P8S150A-61629-1.0             -> 去掉项目号前导业务前缀 6 后：1629-1.0
```

只有 `更新后BOM` 额外生成的 `替代料组齐全差异.xlsx` 的 sheet 名使用 5 位项目号，例如 `BOM-SST26-1629-1.0-瑞能-001.xlsx` 对应 sheet `61629-1.0`。其它 BOM 匹配和项目报告命名继续使用上面的 4 位匹配规则。

对每个改制表：

1. 从改制表读取 `归属=保护板1` 行的规格型号，提取改制前匹配键。
2. 从改制表读取 `归属=保护板2` 行的规格型号，提取改制后匹配键。
3. 在 `改制前BOM` 文件夹中查找唯一匹配的改制前 BOM。
4. 在 `改制后BOM` 文件夹中查找唯一匹配的改制后 BOM。
5. 使用匹配到的两份 BOM、当前改制表、平台最新替代料汇总表执行检查。
6. 如果缺失或匹配到多份，批量汇总记录失败原因，并继续处理其他改制表。

## 改制单删除核对规则

改制单删除项填写了位号时，`位号` 和 `物料代码` 同等有效。

- 只要指定删除位号在改制后 BOM 中已经不存在，就按正常处理。
- 即使改制单物料代码空白、写错，或改制前 BOM 已经没有该位号，也按正常处理。
- 如果指定删除位号仍在改制后 BOM 任意物料下存在，则判异常。
- 没有填写位号时，仍按物料代码和数量变化核对。
- 如果改制单某行的类别/归属包含 `PCBA`，该改制项和它覆盖到的 BOM 差异都不在报告中体现。

只审查替代料是否合规模式下，不读取改制表，也不执行改制前后 BOM 匹配。每个更新后 BOM 直接与公司物料表核对：

1. 检查更新后 BOM 中 `用量=替代料` 的行是否与上一行主料属于公司总料表同一替代关系组。
2. 检查 K 列单向替代限制。
3. 检查 `取消替代关系物料`：替代关系先查 `总替代料汇总表`；如果没匹配，再查 `取消替代关系物料`。如果上方主料和替代料两个料号出现在该 sheet 同一行的 `旧料号`、`新料号`、`对应替代料为` 等字段中，该替代关系按正常放行，不输出到 `替代料关系核对` 明细；如果两个 sheet 都没有匹配关系，备注写 `替代料汇总表未找到该替代关系`。
4. 检查 `总替代料汇总表` K/O 列客户限制一致性。
5. 根据更新后 BOM 文件名识别客户，命中限制则输出异常。

公司物料表目录可以同时提供两个替代表，而不是一个旧的 `替代料汇总表`：

- 文件名含 `关键物料` 的替代表。
- 文件名含 `无关键物料` 的替代表。
- 每个 BOM 按文件名选择替代表：BOM 文件名含 `无关键物料` 时用无关键物料表，含 `关键物料` 时用关键物料表。判断顺序必须先判断 `无关键物料`，避免被 `关键物料` 子串误判。
- 如果同时存在两个替代表，但普通替代料合规检查的 BOM 文件名不含 `关键物料` 或 `无关键物料`，不能随机选表；在 `更新BOM/日期文件夹` 替代料组齐全检查中，这类 BOM 不判失败，输出 `跳过`。
- 关键物料表只读 `总替代料汇总表有关键物料`，缺失时读 `替代料表匹配工具用关键物料`；无关键物料表只读 `总替代料汇总表无关键物料`，缺失时读 `替代料表匹配工具用无关键物料`。
- 同一个 workbook 中可能同时有“有关键物料”和“无关键物料”sheet，单个 BOM 不能同时扫描两套总表，否则会把两套规则混在一起。
- `取消替代关系物料` 仍从被选中的同一个 workbook 读取。

替代关系组先按 `T759`、`T759-1`、`T759-2` 这类前缀归一化。若两个不同关系组的 `类型=主料` 行使用同一个主料物料代码，也视为同一个替代族。例如 `K187` 和 `T715` 都以 `1.03.01.000005` 为主料时，两个组下的替代料互相替换按正常处理。

## 执行流程

1. 用户在前端提交任务名称、项目压缩包；如果替代表有更新，同时上传新的关键物料/无关键物料替代表，或在压缩包公司物料表目录内提供这两个文件。
2. 后端创建 `BomChangeCheckTask` 记录，状态为 `preparing`。
3. 后端保存上传的项目压缩包到：

```text
<task_dir>/input/<原始压缩包名>
```

4. 如果本次网页上传了替代表，后端保存为全平台最新版本；如果本次未上传，则优先保留压缩包公司物料表目录内的替代表，压缩包未提供时再读取平台已保存的最新版本。
5. 如果任务既没有在压缩包公司物料表目录提供替代表，也没有可用的最新替代表，后端返回 `400`，提示先上传替代表，不启动 Codex。
6. 后端解压项目压缩包到：

```text
<task_dir>/input/projects/
```

7. 若压缩包内已经提供 `公司物料表/` 替代表且本次网页没有上传替代表，后端保留压缩包内文件；若本次网页上传了替代表，后端把网页上传表复制到识别出的项目批次根目录下的 `公司物料表/`；若压缩包和本次网页都没有提供，则复制平台保存的最新替代表。
8. 后端将任务状态改为 `queued`，启动后台线程。
9. 后台线程将任务状态改为 `running`。
10. 后端生成 Codex prompt，调用：

```text
codex exec --dangerously-bypass-approvals-and-sandbox --skip-git-repo-check -C <task_dir> -
```

11. Codex 使用 `$bom-change-check` skill，并调用固定批处理脚本识别资料、匹配 BOM、生成报告。
12. 固定脚本生成每个项目报告、批量汇总和 `timing.jsonl`。
13. 后端读取所有项目报告中的 `summary` sheet，汇总异常统计；BOM 自检异常输出在 `BOM差异核对` 并计入 BOM 差异异常。
14. 后端将输入、报告和日志打包为 zip。
15. 任务状态更新为 `success` 或 `failed`。

## 输出文件

每个项目输出一个报告：

```text
reports/<改制表文件名、BOM文件名或项目名>/BOM表改制检查报告-项目号.xlsx
```

同一项目目录只允许保留带项目号后缀的报告。不要生成、保留、统计或打包无项目号副本 `BOM表改制检查报告.xlsx`；如果历史任务或兼容逻辑留下同内容副本，保留 `BOM表改制检查报告-项目号.xlsx`，删除或忽略无编号副本。

整批任务最终下载一个 zip：

```text
BOM表改制检查报告.zip
```

如果上传压缩包名为 `616291001.zip`，下载包名优先使用：

```text
616291001.zip
```

zip 内包含：

```text
input/
  原始压缩包
  projects/
reports/
  <项目>/BOM表改制检查报告-项目号.xlsx
  替代料组齐全差异.xlsx
  BOM表改制检查报告-2026-9-7.xlsx

reports/

```

## 单项目报告要求

报告工作簿名称：

```text
BOM表改制检查报告-项目号.xlsx
```

示例：

```text
BOM表改制检查报告-515451301.xlsx
```

完整改制检查模式必须包含 sheet：

- `改制单核对`
- `BOM差异核对`
- `替代料关系核对`
- `客户限制核对`
- `summary`

只审查替代料是否合规模式必须包含 sheet：

- `替代料关系核对`
- `客户限制核对`
- `summary`

并在 `summary` 元数据中写入：

```text
检查模式 = 只审查替代料是否合规
```

明细 sheet 输出规则：

- `BOM差异核对` 输出所有 BOM 对比差异，包含 `结论=正常` 的差异行。
- `改制单核对` 按改制单物料明细逐行输出正常和异常行，不合并多条改制单内容；它是改制单执行清单，不是只列异常。正常增加项也必须显示，例如 `1.02.01.000002 / 增加 / RA54 / 1 / 0603WAJ0000T5E`；该 sheet 只有异常行在 `备注` 展示具体异常原因，正常行备注留空。
- 改制单类别/归属包含 `PCBA` 的改制项不输出到 `改制单核对`；它覆盖到的 BOM 差异也不输出到 `BOM差异核对`。
- 先在改制单 `改制内容` 区域识别软件分界行：只要文本表达烧录/升级软件含义即可，例如 `烧录/升级程序`、`烧录程序`、`升级程序`、`PLM取程序`、`工程助理提供软件`。只有分界行以上的改制物品才归类为 `产品非电子物料`，不要因为某行缺少物料代码或位号就直接归类。这个归类只作为 BOM 对比匹配依据，不能直接从改制单抽取成报告行，也不能输出到独立 sheet。分界以上有位号的行按普通电子物料一样去改制前 BOM 和改制后 BOM 里对比；分界以上没有位号的标签/PE袋/二维码等物料，即使有物料代码，也用规格型号去改制前 BOM 和改制后 BOM 里对比。没有在对应 BOM 侧找到时，输出到 `BOM差异核对` 并判 `异常`。
- 产品非电子物料差异统一输出到 `BOM差异核对`，正常和异常都显示；不生成 `产品非电子物料` sheet。
- `BOM差异核对` 中被改制单覆盖的位号差异，改制单为 `增加` 时备注写 `已按改制单添加`，改制单为 `删除` 时备注写 `已按改制单删除`。
- `BOM差异核对` 遇到 `IC-烧录程序`/烧录 IC/MCU 程序差异时，不再只写 `跳过`。必须拆成两条差异：改制前项目的 MCU 写 `删除`，改制后项目的 MCU 写 `增加`，位号、用量、规格型号分别取对应 BOM 侧，备注写 `烧录IC按改制前后MCU拆分显示`。这两条 MCU 行必须挨在一起，且 `增加` 行排在 `删除` 行前面。
- `BOM差异核对` 中被改制单覆盖的行，`变更内容` 直接写 `增加` 或 `删除`，不写笼统的 `变更`。
- 同一位号前后料号不同且需要在 `BOM差异核对` 显示时，不管是否被改制单同时覆盖删除和增加，都拆成两行输出：旧物料写 `删除`，新物料写 `增加`，两行都要写清楚料号和规格型号，并且普通换料按 `删除` 在前、`增加` 在后挨在一起。
- `BOM差异核对` 中前后料号在公司替代料表存在有效替代关系时，视为只是替代料变化，不输出该替代料差异；新增的 BOM 替代料行如果和它绑定的上一行主料存在有效替代关系，也不输出该替代料差异，即使位号同时被改制单覆盖；但改制单明确删除的位号不能因为删除的是替代料行而隐藏，必须按正常删除输出，备注写 `已按改制单删除`，并用该替代料绑定的上一行主料信息显示；如果差异命中 `取消替代关系物料`，必须输出，备注写 `取消替代物料，可以忽略`，同一位号旧料换新料时仍按 `删除`/`增加` 拆两行，不是这种换料拆行的替代料显示行才写 `变更内容=替代料`。
- 如果同一个位号同时出现在 BOM 的主料行和替代料行，`BOM差异核对` 的位号对比优先使用主料行，不能让下方替代料行覆盖主料行。例如 RA54 同时在主料 `1.02.01.000002 / 0603WAJ0000T5E` 和替代料 `1.02.01.000539 / RS-03000JT` 上，改制单要求增加 RA54 主料时，必须输出主料增加行，不能因为替代料关系有效而隐藏。
- `BOM差异核对` 中被改制单覆盖的 `增加`/`删除` 行，`用量` 列填写改制单用量：增加写增加了多少个，删除写删除了多少个。
- `BOM差异核对` 中未被改制单覆盖但需要显示的行，`用量` 也尽量从 BOM 行填写；替代料行用量为 `替代料` 时，按位号数量填写。
- 完整改制检查模式下，对改制前 BOM 和改制后 BOM 执行 BOM 自检。自检扫描同一 workbook 内所有符合 BOM 表头的 sheet，不只扫描用于前后差异对比的 `总表` 或第一个 sheet。正常 BOM 行有位号时，`用量` 必须等于位号数量，一个位号对应一个数量；同一个 BOM 的同一个 sheet 内，同一位号不能出现在多个非替代料行。发现用量与位号数量不一致或同 sheet 位号重复时，输出到 `BOM差异核对` 并判 `异常`，`变更内容` 写 `BOM自检`，备注写清楚 BOM 侧、sheet 和行号。`用量=替代料` 的替代料行允许和上方绑定主料共用位号，不按重复位号异常处理；位号格写有 `配套` 的配套物料行，例如 `配套D5,D6,D7,D8,D9,D10`，允许和 LED/主料共用这些位号，不按重复位号异常处理；不同 sheet 之间不要互相判重复位号，因为 `总表` 和 SMT sheet 可能本来就包含同一批物料。
- `替代料关系核对` 中，`变更内容` 留空；`用量` 尽量从 BOM 行填写，替代料行用量为 `替代料` 时按位号数量填写。
- `替代料关系核对` 中，若 `总替代料汇总表` 未匹配但 `取消替代关系物料` 匹配，按正常放行，不输出明细；若两个 sheet 都未匹配，输出备注 `替代料汇总表未找到该替代关系`。
- 报告可见 `备注` 只写简短明确的问题类型，不写行号、已有组内物料、查找过程等证据。例如 `BOM缺少该物料`、`替代料汇总表未找到该替代关系`、`位号重复`。
- 其它明细 sheet 只输出需要人工处理的行；`BOM差异核对` 和 `改制单核对` 是例外，`BOM差异核对` 需要显示正常和异常 BOM 差异，`改制单核对` 需要显示正常和异常改制单明细：

- `结论=异常`
- `结论=人工复查`
- `结论=跳过`

除 `BOM差异核对` 和 `改制单核对` 外，其它明细 sheet 不输出：

- `结论=正常`

明细 sheet 固定列顺序：

```text
物料代码、变更内容、位号、用量、规格型号、备注
```

映射关系：

- `物料代码`：物料代码、改制后物料代码、替代料代码或主料代码。
- `变更内容`：改制单操作值 `删除`/`增加`；同一位号从旧料号变成新料号且需要显示时，拆成 `删除` 和 `增加` 两行，不要只写一行 `变更`；只有无法表示成旧料删除加新料增加的 BOM 普通差异才写 `变更`；BOM 替代料相关差异写 `替代料`；BOM 自检异常写 `BOM自检`；跳过行写 `跳过`；替代料关系核对留空；客户限制写 `客户限制异常` 或 `客户限制人工复查`。
- `位号`：位号。
- `用量`：用量；BOM 差异被改制单增加/删除覆盖时，填写改制单用量；其它显示行从 BOM 行兜底，替代料行按位号数量兜底。
- `规格型号`：规格型号。
- `备注`：具体异常说明或人工复查原因；`改制单核对` 正常行备注留空，异常行显示具体异常原因。

异常行规则：

- `结论=异常`：整行黄色
- `结论=人工复查`：整行黄色
- `结论=跳过`：输出但不标黄
- 不保留行号、证据、检查类、结论等额外明细列；人工根据物料代码、位号和备注自行回查原始文件。

- `replacement_and_customer_checks_finished`
- `before_bom_loaded`
- `change_order_parsed`
- `change_checks_finished`
- `report_written`

如果任务超时，后端会保留可读的中间报告和报告 zip；任务状态仍为失败，但前端可下载已生成的报告包进行复查。

2026-07-22 A档真实数据验证：

- 输入任务：`d34fc1bc-cd69-4f61-aad9-2848181656c1`
- 项目数：3
- 公司物料表索引加载：约 11.6 秒
- 每个项目规则检查：小于 1 秒
- 每个项目报告写入：约 23-24 秒
- 批量总耗时：约 82 秒

常见失败原因：

- 压缩包为空
- 压缩包格式不是 `.zip/.rar/.7z`
- 服务器缺少 7-Zip 或 RAR 解压工具
- 分类文件夹缺失
- 未上传替代料汇总表且平台没有历史最新替代料汇总表
- 改制表无法读取上下规格型号
- BOM 匹配不到
- BOM 匹配到多份
- 平台最新替代料汇总表复制失败，导致任务输入中缺少可用公司物料表
- Codex 命令不存在
- Codex 执行超时
- Codex 未生成任何 `BOM表改制检查报告*.xlsx`
