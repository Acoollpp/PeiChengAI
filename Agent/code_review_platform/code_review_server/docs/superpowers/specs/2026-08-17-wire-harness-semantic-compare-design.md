# 线束图语义对比与交互批注设计

## 1. 背景与目标

在现有“线束图对比”任务模块上增加语义文字识别、差异报告和交互批注能力。用户上传 ZIP 或 RAR 压缩包，压缩包内可以包含多个文件夹，每个文件夹包含一套旧图纸和新图纸。

目标：

1. 优先读取 PDF 内置文字，读取不到或不完整时自动 OCR。
2. 按文字内容、页面和空间位置匹配新旧图纸内容。
3. 识别新增、删除、修改，以及型号、尺寸、线号、物料号、版本等变化。
4. 生成差异文档和结构化差异数据。
5. 生成旧图红色编号、新图蓝色编号的批注副本。
6. 提供左右联动的浏览器审阅页，点击任意编号显示对应差异详情并同步定位两张图。
7. 保留原始 PDF，不对用户上传文件做原地修改。

## 2. 用户流程

1. 用户在“线束图对比”页面上传 ZIP 或 RAR。
2. 后端校验压缩包并解压到任务专属目录。
3. 每个子目录识别一对旧图和新图；旧、新无法判断时沿用现有文件名排序兜底，并在报告中提示。
4. 任务进入“文字识别”“语义比对”“生成批注”“打包结果”阶段。
5. 用户在任务列表中查看状态、失败原因和结果文件。
6. 用户打开 `差异报告.html`，左右查看旧图与新图，点击红色或蓝色编号查看同一条差异。

## 3. 处理架构

沿用现有 FastAPI + React/Vite + SQLModel/PostgreSQL + 任务目录存储结构，不新建独立平台。

### 3.1 后端模块

- 任务 API：沿用现有创建、列表、删除和报告下载接口，扩展结果统计和报告入口。
- 处理服务：负责解压、配对、调度语义识别、渲染、批注和打包。
- PDF 文本提取器：使用 PyMuPDF 提取页面、文本块、坐标、页码和基础字体信息。
- OCR 适配器：对无内置文字或文字覆盖率不足的页面渲染图片后执行 OCR，保留文字框坐标。
- 语义比对器：输入两侧文本块，输出稳定的差异记录；实现为可替换接口，便于接入本地 Codex/语义模型和规则兜底。
- 批注生成器：在 PDF 副本和页面图片上绘制编号标记，旧图使用红色，新图使用蓝色。
- HTML 报告生成器：生成带页面图片、标记定位、差异列表和点击联动逻辑的独立报告。

### 3.2 前端模块

- 任务列表保留现有上传和状态轮询。
- 结果区域增加“打开交互报告”和“下载结果包”。
- 交互报告优先作为结果包中的独立 HTML 打开，不依赖平台登录态。
- 平台内可增加“在线审阅”入口；若浏览器无法直接访问任务目录，则使用后端报告预览接口。

## 4. 语义识别与匹配

### 4.1 文本获取

每个文本块保存：

- `text`
- `page`
- `bbox`（左、上、右、下）
- `source`（`pdf_text` 或 `ocr`）
- `confidence`
- 可选字体大小和方向

PDF 内置文字优先。页面文字数量过少、文字框覆盖率异常或提取结果明显不完整时，启用 OCR；OCR 结果只补充缺失内容，避免重复计数。

### 4.2 归一化

只做不改变业务含义的归一化：去除多余空白、统一安全范围内的全角/半角符号、统一换行和大小写比较形式。型号、料号、数字、单位、正负号、版本号和日期作为敏感内容保留原文。

### 4.3 匹配与分类

先按页码和空间邻近关系生成候选，再按归一化文字、数字片段和相似位置匹配。语义比对器输出以下类型：

- `added`：新图新增
- `removed`：旧图存在、新图删除
- `modified`：文字或数值修改
- `dimension_changed`：长度、间距、直径等尺寸修改
- `part_number_changed`：物料号、端子号、型号修改
- `revision_changed`：版本、日期、标题栏修改
- `graphic_only`：无文字对应的图形变化，由像素差异补充

每条记录包含：差异编号、类型、页码、旧文本、新文本、旧坐标、新坐标、置信度和说明。编号在单套图纸内从 1 开始，并同时写入旧图和新图。

### 4.4 低置信度

无法可靠配对、OCR 质量低或只有图形变化的记录标记为“需人工确认”，不静默丢弃。报告显示识别来源和置信度，方便用户区分文字识别问题与真实图纸差异。

## 5. 批注与交互报告

### 5.1 批注颜色

- 旧图：红色圆形编号。
- 新图：蓝色圆形编号。
- 相同差异使用相同数字，例如旧图红色“3”和新图蓝色“3”。

批注绘制在生成副本上，原始 PDF 保持不变。PDF 副本保证可打印和离线查看；点击弹窗交互由 HTML 报告提供，避免依赖不同 PDF 阅读器对自定义 JavaScript 或注释动作的支持差异。

### 5.2 左右联动页面

页面结构：

- 顶部：任务名称、图纸名称、识别统计和筛选条件。
- 左侧：旧图页面，红色批注。
- 右侧：新图页面，蓝色批注。
- 底部或侧边：差异列表和当前差异详情。

交互行为：

1. 点击任意红色或蓝色编号，两侧切换到对应页并滚动到对应坐标。
2. 当前差异在两侧使用高亮边框，详情显示旧文本、新文本、差异类型和置信度。
3. 点击差异列表中的编号，执行同样的双侧定位。
4. 支持上一条、下一条差异导航。
5. 支持按差异类型筛选，默认显示全部差异。

报告使用内嵌 JSON 数据和本地页面资源，结果包解压后可离线打开；不依赖外部 CDN。

## 6. 输出文件

每套图纸结果包包含：

```text
差异报告.html
差异明细.md
差异数据.json
旧图纸_红色批注.pdf
新图纸_蓝色批注.pdf
旧图纸_红色批注.png
新图纸_蓝色批注.png
```

批量任务下载包保留每套图纸的独立目录，并在根目录增加汇总信息，例如总套数、差异数、低置信度数和失败套数。

## 7. 失败处理与兼容性

1. RAR 解压沿用现有 UnRAR 检测和安全解压逻辑；找不到解压工具时返回明确安装提示。
2. 子目录不是恰好一对 PDF 时，该套单独失败，不影响其他套。
3. PDF 损坏、密码保护、页面渲染失败或 OCR 不可用时记录具体原因。
4. 单套失败不阻塞其余套，任务汇总显示成功、失败和低置信度统计。
5. 语义模型不可用时使用规则匹配和像素差异兜底，并在报告中标记识别模式。
6. 所有路径使用任务专属目录，文件名经过安全处理，禁止压缩包路径穿越。

## 8. 数据与接口变化

扩展现有任务结果元数据，不改变现有上传协议。结果文件增加类型标识，至少支持：

- 交互报告
- Markdown 差异文档
- 批注 PDF
- 批注 PNG
- JSON 差异数据

任务公开信息增加：语义差异数、低置信度数、OCR 页面数、报告入口和结果模式。若现有数据库字段不足，新增 Alembic 迁移；旧任务仍可下载原有并排 PNG 结果。

## 9. 测试与验证

### 后端

1. 内置文字 PDF 提取和坐标保存。
2. 扫描 PDF OCR fallback 和重复文字去重。
3. 新增、删除、修改、尺寸和料号差异分类。
4. 同一编号同时落在旧图和新图。
5. 红蓝批注位置、页码和编号一致。
6. HTML 报告中的差异记录与 JSON 一致。
7. ZIP/RAR 多目录处理、坏包、路径穿越和单套失败隔离。
8. 旧任务结果兼容性和下载权限。

### 前端与视觉

1. 前端构建通过。
2. 交互报告可离线打开。
3. 点击左右任一标记能显示对应详情并同步定位。
4. 在桌面和窄屏下检查左右图纸、编号和详情不重叠。
5. 生成 PDF 重新渲染为 PNG，检查批注不遮挡关键文字，页面边缘不裁切。

## 10. 明确不纳入本阶段

- 不修改用户原始 PDF。
- 不要求在所有 PDF 阅读器内实现点击弹窗。
- 不把人工确认结果自动回写为训练数据。
- 不在本阶段新增在线多人协同批注、权限细分或版本回滚。
