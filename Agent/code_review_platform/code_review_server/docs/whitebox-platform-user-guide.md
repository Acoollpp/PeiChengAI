# 白盒测试平台使用说明

## 1. 平台用途

白盒测试平台用于提交代码白盒测试任务。工程师只需要在网页上填写 SVN 路径和版本号，平台会把任务发送给白盒测试电脑执行 QAC 和 TESSY 测试。

测试完成后，工程师可以在平台上查看任务状态，并下载白盒测试电脑上传的报告包。

## 2. 使用前准备

使用前请确认你已经具备以下信息：

| 项目 | 说明 |
| --- | --- |
| 平台地址 | 本地或局域网中的白盒测试平台网页地址 |
| 登录 Key | 用于登录平台的 API Key |
| SVN 路径 | 需要测试的项目代码 SVN 地址 |
| 版本号 | 需要测试的 SVN revision |

示例：

| 输入项 | 示例 |
| --- | --- |
| SVN 路径 | `https://192.168.0.233/svn/src_home/PCB_61630V100` |
| 版本号 | `46924` |

## 3. 登录平台

1. 打开白盒测试平台网页。
2. 在登录界面输入自己的 API Key。
3. 点击登录。
4. 登录成功后，进入平台首页。

如果输入 API Key 后没有进入平台，请检查：

| 问题 | 处理方式 |
| --- | --- |
| Key 输入错误 | 重新复制完整 Key，注意不要多复制空格 |
| Key 已失效 | 联系管理员重新生成或确认账号状态 |
| 平台无响应 | 刷新页面，或联系平台维护人员检查服务是否启动 |

## 4. 提交白盒测试任务

1. 进入左侧菜单中的“白盒测试平台”。
2. 在任务提交区域填写 SVN 路径。
3. 填写 SVN 版本号。
4. 点击提交任务。

提交时只需要填写：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| SVN 路径 | 必填 | 项目代码所在 SVN 地址 |
| 版本号 | 必填 | 需要测试的 SVN revision |

提交后，平台会生成一条任务记录。任务会等待白盒测试电脑领取并执行。

## 5. 查看任务状态

任务提交后，可以在任务列表中查看状态。

| 显示项 | 含义 |
| --- | --- |
| 状态 | 当前任务执行状态 |
| 测试时长 | 白盒测试电脑实际执行任务所用时间 |

常见状态说明：

| 状态 | 含义 |
| --- | --- |
| 等待中 | 任务已提交，等待白盒测试电脑领取，此时测试时长通常为空 |
| 执行中 | 白盒测试电脑已经领取任务，正在执行测试，测试时长会持续增加或在完成后显示 |
| 成功 | QAC 和 TESSY 均执行完成，并上传了结果 |
| 失败 | 至少有一项测试失败，或测试报告存在缺失 |

任务失败不一定代表平台异常。常见情况是代码本身、QAC 环境、TESSY 用例或白盒测试电脑工具配置导致失败。

测试时长只统计白盒测试电脑领取任务后的执行时间，不包含任务排队等待时间。如果任务长时间处于等待中，说明白盒测试电脑可能未在线、正在执行其他任务，或没有及时领取任务。

## 6. 下载测试报告

任务完成后，如果任务列表中出现下载入口，可以点击下载报告。

报告通常是一个压缩包，例如：

`final_report.zip`

报告包内常见内容包括：

| 文件或目录 | 说明 |
| --- | --- |
| `whitebox_task_summary.md` | 本次任务摘要 |
| `agent.log` | 白盒测试电脑执行日志 |
| `qac_report` | QAC 相关日志和结果 |
| `tessy_report` | TESSY 相关日志和结果 |

建议优先查看 `whitebox_task_summary.md`。如果需要进一步定位失败原因，再查看 `agent.log`、`qac_report` 和 `tessy_report`。

## 7. 失败原因怎么看

任务失败时，先看任务列表中的失败提示，再下载报告查看详细信息。

常见失败类型如下：

| 失败提示 | 含义 | 建议处理 |
| --- | --- | --- |
| SVN checkout failed | SVN 路径、版本号、账号权限或网络存在问题 | 确认 SVN 路径和版本号是否正确，确认白盒测试电脑是否能访问该仓库 |
| QAC 执行失败 | QAC 分析代码时出现错误 | 下载报告查看 `qac_report` 中的日志 |
| TESSY 没有正式执行用例 | 只生成了模板，没有找到正式用例文件 | 补充或确认 `*_cases.yml` 用例文件 |
| 报告文件缺失 | 工具执行后没有生成平台需要收集的报告 | 联系白盒测试电脑维护人员检查工具输出路径 |
| Unexpected token | QAC 解析某个 C 文件失败 | 查看日志中对应文件和行号，确认代码或 QAC 编译配置 |
| Unknown target | QAC 没有正确识别芯片、编译器或 CMSIS 目标宏 | 联系白盒测试电脑维护人员补齐 QAC 环境配置 |

示例失败说明：

```text
QAC 应用工程 114 个源文件中，109 个成功，5 个失败。
失败文件包括 UartGPRS.c、UartGPRS_Upgrade.c、Lcd_Comm.c、UartRS232.c、UartRS485.c。
TESSY 只生成模板，没有正式执行测试用例。
因此本次任务判定失败。
```

## 8. 重新提交任务

如果确认问题已经处理，可以重新提交任务。

常见需要重新提交的情况：

| 场景 | 是否需要重新提交 |
| --- | --- |
| SVN 路径填错 | 需要 |
| 版本号填错 | 需要 |
| 白盒测试电脑环境修复后 | 需要 |
| QAC/TESSY 用例补充后 | 需要 |
| 只是想重新下载报告 | 不需要 |

重新提交时，请使用修正后的 SVN 路径和版本号。

## 9. 使用注意事项

1. SVN 路径必须填写完整路径。
2. 版本号必须填写明确的 revision，不要填写分支名或日期。
3. 同一个项目可以多次提交不同版本号。
4. 不要重复快速提交同一个任务，避免白盒测试电脑排队过多。
5. 任务失败后，先下载报告查看原因，再决定是否重新提交。
6. 如果失败原因是白盒测试电脑工具环境问题，需要联系维护人员处理后再重跑。

## 10. 问题反馈时需要提供的信息

如果任务失败后需要别人协助排查，请提供以下信息：

| 信息 | 示例 |
| --- | --- |
| 任务 ID | `67bfe6a6-a7aa-4141-ba18-a6803397647d` |
| SVN 路径 | `https://192.168.0.233/svn/src_home/PCB_61630V100` |
| 版本号 | `46924` |
| 任务状态 | 失败 |
| 测试时长 | 例如 `2分45秒` |
| 失败提示 | QAC 执行失败，TESSY 未正式执行 |
| 报告包 | `final_report.zip` |

提供这些信息后，维护人员可以更快判断是代码问题、工具环境问题，还是平台问题。
