# 通用-代码变更审查

## 概述

本 skill 用于两类任务：

1. 基于 `SVN` 两个版本之间的代码差异生成代码变更审查报告。
2. 根据工程师上传或提供的规则文档，维护代码审查规则库。

代码审查目标不是简单列出 diff，而是结合嵌入式固件常见风险点、产品检查表、自检项和架构约束，输出可交付的 Markdown 审查报告。

## 使用边界

适用于：

- 用户要求比较 `SVN` 两个 revision。
- 用户提供项目路径、旧版本号、新版本号，并要求生成代码变更审查报告。
- 用户上传规则文档，希望加入代码审查规则库。
- 用户要求优化现有审查规则、报告模板或输出要求。

不适用于：

- 只审查 Git 工作区临时改动。
- 只查看单个文件差异，不需要正式报告。
- 只执行 SVN 提交或更新，不需要变更审查。

## 规则分层目录

详细规则统一维护在 `references/`，按输入、规则、输出三大模块组织：

| 模块 | 职责 | 位置 |
|---|---|---|
| 输入模块 | 收集项目路径、版本号、输出路径，获取 SVN 差异材料 | `references/10-输入模块/` |
| 规则模块 | 按产品、AI、架构三类规则执行审查判定 | `references/20-规则模块/` |
| 输出模块 | 规定报告结构、输出格式和完成后反馈要求 | `references/30-输出模块/` |

规则模块继续拆分：

| 子模块 | 职责 | 位置 |
|---|---|---|
| 产品相关规则 | 需求一致性、功能影响、检查表、自检项 | `references/20-规则模块/10-产品相关规则/` |
| AI规则 | 代码差异解释、潜在 Bug、边界条件、性能风险、可读性建议 | `references/20-规则模块/20-AI规则/` |
| 架构规则 | 模块边界、依赖关系、团队规范、协议字段、数据落点、状态链路 | `references/20-规则模块/30-架构规则/` |

## 代码审查执行流程

严格按以下顺序执行：

1. 读取并执行 `references/10-输入模块/10-输入收集规则.md`。
2. 读取并执行 `references/10-输入模块/20-SVN获取策略.md`。
3. 读取 `references/20-规则模块/00-规则模块总览.md`。
4. 读取产品相关规则：先读 `references/20-规则模块/10-产品相关规则/README.md`，再按变更内容读取对应规则文件；如果有检查表或自检表，必须读取 `20-检查表审查规则.md` 和 `30-自检项判定规则.md`。
5. 读取 AI 规则：先读 `references/20-规则模块/20-AI规则/README.md`，再读取相关规则文件。
6. 读取架构规则：先读 `references/20-规则模块/30-架构规则/README.md`，必须覆盖协议字段、数据落点与截断、状态链路等强规则。
7. 对自检表点名文件、变更清单中的 `.c/.h` 文件、diff 最大的前 10 个文件完成重点审查。
8. 读取并执行 `references/30-输出模块/10-报告模板规则.md`。
9. 读取并执行 `references/30-输出模块/20-输出反馈规则.md`。

## 规则文档维护流程

当用户上传或提供规则文档，并要求加入代码审查规则库时，不要求工程师手动选择目录。必须由 Codex 自动完成：

1. 读取 `references/20-规则模块/00-规则模块总览.md` 和 `references/20-规则模块/01-规则新增规范.md`。
2. 读取用户提供的规则文档内容；如果是 Word、Excel、PDF、Markdown、文本或图片，应提取可用文本、表格、标题和规则条目。
3. 将规则文档拆分为独立规则条目。
4. 提取每条规则的规则意图、适用场景、判定依据、审查方法和输出要求。
5. 判断规则属于输入模块、规则模块还是输出模块。
6. 如果属于规则模块，继续判断属于产品相关规则、AI规则还是架构规则。
7. 在目标目录中优先选择已有子规则文件追加内容。
8. 如果已有子规则文件无法准确承载，按编号新增子规则文件，并同步更新该目录下的 `README.md`。
9. 完成后反馈来源文档、规则归类、修改文件、新增或追加内容摘要。

如果用户没有上传文档，而是直接在对话中补充单条规则，也按同一流程处理。

只有在规则文档无法解析、关键语义缺失，或同一条规则明显跨多个模块且会造成冲突时，才向用户补问。

## 维护要求

- 不要在 `SKILL.md` 中追加大段具体规则。
- 新增输入获取、参数确认、SVN 数据准备相关内容，放入 `references/10-输入模块/`。
- 新增审查判断规则，放入 `references/20-规则模块/` 下对应子目录。
- 新增报告模板、输出格式、反馈要求，放入 `references/30-输出模块/`。
- 新增规则文件必须包含适用场景、判定依据、审查方法、输出要求和不适用场景。
- 新增子规则文件后，必须同步更新对应目录的 `README.md`。

## 总体质量要求

执行代码变更审查时，默认目标是帮助用户提前发现回归风险，而不是仅列出改动。

必须做到：

- 先收集完整输入，再执行审查。
- 先确认变更范围，再深入重点文件。
- 以行为风险、兼容性风险、协议风险和数据链路风险为中心。
- 检查表和自检项是审查结论组成部分，不是附加参考材料。
- 报告落盘后必须反馈输出路径。
