# 规则模块总览

规则模块承载审查过程中的判定逻辑，按三类维护：

| 子模块 | 关注点 | 典型规则 |
|---|---|---|
| 产品相关规则 | 变更是否符合需求、功能场景、检查表和自检项要求 | 需求一致性、功能影响、检查表符合性、自检项判定 |
| AI规则 | 需要 AI 归纳、推理、补全或生成的审查动作 | 代码差异解释、潜在 Bug、边界条件、性能风险、可读性建议 |
| 架构规则 | 代码结构、模块边界、依赖关系、团队规范和嵌入式链路风险 | 模块边界、不合理依赖、团队规范、协议字段、数据落点、截断、状态链路 |

新增规则时由 Codex 根据用户提供的规则文档自动完成归类，不要求工程师手动选择目录。

## 必查强规则

每次代码审查必须覆盖：

- 自检表或检查表点名的所有代码文件
- 变更清单中的 `.c/.h` 文件
- diff 最大的前 10 个文件
- 协议解析、结构体赋值、状态字更新、持久化读写、初始化和定时器链路

## 规则文档维护入口

工程师上传规则文档后，Codex 必须：

1. 读取规则文档。
2. 拆分独立规则条目。
3. 判断规则属于产品、AI、架构或其他模块。
4. 优先追加到已有子规则文件。
5. 无合适子规则文件时新增编号文件。
6. 新增文件后更新对应 `README.md`。
7. 反馈规则来源、归类和修改文件。
