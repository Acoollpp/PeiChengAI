# 规则新增规范

新增规则前，先判断它属于输入、规则还是输出。只有“审查判断类规则”放入本模块。

## 一眼判断

| 要新增的内容 | 放哪里 |
|---|---|
| 参数收集、SVN 命令、版本导出、diff 获取 | `references/10-输入模块/` |
| 产品需求、功能影响、配置项、检查表符合性、自检项 | `references/20-规则模块/10-产品相关规则/` |
| 代码差异解释、潜在 Bug、边界条件、性能风险、可读性建议 | `references/20-规则模块/20-AI规则/` |
| 模块边界、不合理依赖、团队规范、接口兼容、协议链路、数据落点、长度截断、初始化、状态机 | `references/20-规则模块/30-架构规则/` |
| 报告结构、字段格式、结论表达、反馈路径 | `references/30-输出模块/` |

## 规则文档自动添加流程

新增审查判断类规则时，工程师优先上传或提供规则文档。Codex 必须自动解析文档并维护规则库：

1. 读取规则文档内容；如果是 Word、Excel、PDF、Markdown、文本或图片，应提取可用文本、表格、标题和规则条目。
2. 将文档拆分为独立规则条目。
3. 提取规则意图、适用场景、判定依据、审查方法和输出要求。
4. 判断每条规则归属。
5. 进入对应目录后，优先选择已有子规则文件追加内容。
6. 如果现有子规则无法承载，新增编号递增的子规则文件，例如 `40-xxx规则.md`、`60-xxx规则.md` 或 `70-xxx规则.md`。
7. 新增子规则文件后，必须同步更新对应 `README.md`。
8. 完成后反馈规则来源文档、规则分类、修改文件、追加或新增摘要。

## 新增规则文件模板

```markdown
# 规则名称

## 适用场景

- 什么情况下必须使用这条规则

## 判定依据

- 看哪些文件、字段、diff、检查表条目或代码链路

## 审查方法

- 怎么判断符合或不符合
- 需要注意哪些例外

## 输出要求

- 报告中怎么描述
- 是否需要区分已确认问题和待验证问题

## 不适用场景

- 哪些情况不要使用这条规则
```

## 禁止事项

- 禁止在 `SKILL.md` 中直接追加大段规则。
- 禁止把输入获取规则放进产品、AI 或架构目录。
- 禁止一个规则文件同时覆盖多个无关主题。
- 禁止只写结论，不写判定依据。
- 禁止把“字段落点、长度截断、同字段覆盖”这类强规则只写成泛泛风险提示。
