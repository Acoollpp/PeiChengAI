# 数据落点与截断规则

## 适用场景

- diff 中包含结构体赋值、协议解析、类型转换、容量/电流/电压/状态字段写入。
- diff 中包含 `uint8_t`、`uint16_t`、`uint32_t`、`int16_t`、`int32_t` 相关字段变化。

## 判定依据

- 源数据长度
- 目标字段类型
- 字段语义
- 连续赋值位置
- 注释和协议文档

## 审查方法

必须检查：

- 是否存在 32 位数据写入 16 位字段。
- 是否存在同一字段被不同含义的数据连续赋值覆盖。
- 是否存在注释语义和目标字段语义不一致。
- 是否存在协议解析落点错误。
- 是否存在高字节丢失、符号位错误或单位错配。

重点风险示例：

- “累计充电容量”和“累计放电容量”都写入 `DesignCap`。
- 32 位累计容量写入 `uint16_t` 字段。
- 解析注释写的是电流，落点却是容量字段。

## 输出要求

报告中必须写清：

- 源字段
- 目标字段
- 类型长度
- 是否截断
- 是否覆盖
- 影响范围

明确问题写入 `五、代码质量问题`，不得只写成泛泛提示。

## 不适用场景

- 类型转换有明确范围限制且已经完成边界校验。
