# SVN 获取策略

## 优先获取顺序

代码审查时优先使用远端 SVN 信息：

1. `svn diff --summarize -r 旧版本:新版本 项目路径`
2. `svn log -v -r 旧版本:新版本 项目路径`
3. `svn diff -r 旧版本:新版本 项目路径`

## 远端 diff 异常兜底

如果远端正文 diff 失败，例如出现：

```text
E200003: Delta source ended unexpectedly
```

必须切换为双版本导出后本地离线比对：

1. 导出旧版本到英文临时目录。
2. 导出新版本到英文临时目录。
3. 本地比较两份目录差异。
4. 报告中说明远端正文 diff 异常和兜底方式。

## 重点文件范围

必须重点审查：

- 自检表或检查表点名的文件
- 变更清单中的 `.c/.h` 文件
- diff 最大的前 10 个文件
- 协议解析、结构体赋值、状态字更新、持久化读写、初始化、定时器链路

如果某个大 diff 文件未完成逐段审查，必须在报告中说明原因。
