## 三、主要功能变更分析

本次变更从 1.07D 演进到 1.07E/1.07E-001，核心是客户定制通信和干接点能力：

1. 新增干接点控制模块。干接点支持 2 路输出，条件源包括平均 SOC、SOC、总压、充放电电流、低电量、充放电保护、过流报警、短路保护、故障状态、告警状态；支持无延时、断开延时、闭合延时、通用延时、最短间隔延时。
2. 232 协议改为客户定制协议 `OT040-LS-UART-HS001-V1.0`，新增干接点配置读写、协议编码/名称读写、当前协议读写、ROM 读写占位命令。
3. 新增 232 到 485 转发机制。主机收到非本机地址命令时，将请求复制到 485 临时缓冲区，并通过 485 主从轮询状态机发送给目标从机；收到从机响应后再转发回 232。
4. 扩展模拟量和告警字段。新增独立总压 `Vpack`、独立电流 `Current2`、SOH、认证故障占位、`Status11` 等字段。
5. 通过 `User_Timer` 新增毫秒计数接口，干接点处理函数以 100ms 节流执行。

## 五、代码质量问题

### 高风险：干接点读命令未校验索引，可能越界访问

位置：

- `source/UartRS232.c:2344-2379`
- `source/UartRS485.c:2534-2569`

`READ_DRYCONTACT_CURRENT` 从报文中解析 `Index` 后直接访问 `DryContact_Parameter[Index]`，没有判断 `Index < DRYCONTACT_NUM`。当前 `DRYCONTACT_NUM` 为 2，非法索引会越界读取内存并通过 232/485 返回，轻则返回错误配置，重则破坏通信稳定性。

建议：读命令和写命令都统一在协议入口校验 `Index < DRYCONTACT_NUM`，读失败返回 `Rtn_Code = 0x09`。

### 高风险：`Uart485_SetTransData()` 声明返回 `uint8_t`，成功路径没有返回值

位置：`source/UartRS485.c:3138-3141`

函数在长度超限时 `return 0`，但成功复制后没有 `return 1`。调用方 `UartRS232.c:2831` 未检查返回值，但该问题仍会造成未定义返回行为，后续维护或编译优化可能引出隐蔽问题。

建议：成功路径补 `return 1`，调用方检查失败后返回错误码。

### 高风险：485 侧 ROM 命令从发送缓冲区解析请求字段，疑似读错数据源

位置：

- `source/UartRS485.c:622-631`
- `source/UartRS485.c:677-686`

`GET_ROMDATA` 和 `SET_ROMDATA` 在 485 侧使用 `UartRS485_TxBuffer[13...]` 解析请求参数，但请求报文应在 `UartRS485_RxBuffer` 中。发送缓冲区此时已开始组响应帧，字段 13 之后未必是原始请求内容，可能导致 ROM 类型、地址、长度解析错误。

232 侧同类逻辑使用 `UartRS232_Buffer`，因为收发共用同一缓冲区，风险较小；485 侧收发缓冲区分离，这里需要重点修正。

### 中风险：干接点过流报警判断使用 `(BIT4 & BIT5)`，条件恒为 0

位置：`source/DryContact_Ctrl.c:167`

代码为：

```c
if (PackData[0].Status1 & (BIT4 & BIT5))
```

如果 `BIT4` 和 `BIT5` 是不同 bit，`BIT4 & BIT5` 等于 0，该条件永远不成立，干接点主参数 `OVER_CURRENT_WARNING` 无法触发。

建议改为 `PackData[0].Status1 & (BIT4 | BIT5)`，并确认 Status1 中过流告警实际位定义。

### 中风险：干接点参数写入缓冲区长度写死为 20，结构变化后容易溢出

位置：`source/DryContact_Ctrl.c:54-60`

当前 `DRYCONTACT_DataTypeDef` 注释为 8 byte，`DRYCONTACT_NUM` 为 2，保存长度为 `8 * 2 + 2 = 18`，暂时小于 `buff_write[20]`。但一旦结构体对齐、字段增加或干接点数量增加，`memcpy` 会越界。

建议改为按计算长度定义缓冲区，或增加编译期/运行期长度检查。

### 中风险：`DryContact_Parameter_Set()` 部分参数未做枚举范围校验

位置：`source/DryContact_Ctrl.c:94-112`

当前校验了 `Index`、`Main_Parameter` 和部分 `Sub_Parameter`，但没有校验：

- `Default_State` 是否仅为 `DC_OPEN/DC_CLOSE`
- `Delay_Type` 是否小于等于 `SHORTEST_INTERVAL_DELAY`
- `Delay_Time * TIMER_TICK_S` 是否可能溢出或超出业务允许范围

非法配置可通过 232/485 写入 Flash，并在周期处理中影响输出状态。

### 中风险：主从转发状态机缺少明确超时恢复

位置：

- `source/UartRS232.c:2824-2835`
- `source/UartRS485.c:2710-2718`
- `source/UartRS485.c:3068-3075`

当转发单播消息后进入 `UART485_WAITRESP`，若从机无响应，当前审查范围内未看到基于超时将状态恢复到 `UART485_IDLE` 的逻辑。状态可能长期占用，后续转发请求会被 `UartRS485_SetTransMsgStatus()` 拒绝。

建议增加等待响应超时计数，超时后返回通信失败并清除状态。

### 低风险：协议字段扩展复用了 `DesignCap` 存储累计充/放电容量

位置：

- `source/UartRS485.c:2841`
- `source/UartRS485.c:2851`

保存从机模拟量时，两段 32 位累计容量均写入 `PackData[Slave_Pack_Addr].DesignCap`，后写入会覆盖前写入。若协议语义确实是累计充电容量和累计放电容量，应拆分为两个字段；若只是占位，应在协议文档和代码注释中明确。

## 七、结论

本次变更具备明确的产品功能目标，主要围绕客户定制 232 协议、485 转发、SOH 显示和干接点控制展开。代码链路基本完整，但存在几处应在发布前处理的确认问题。

建议发布前优先处理：

1. 修复 `READ_DRYCONTACT_CURRENT` 的索引越界风险。
2. 修复 `Uart485_SetTransData()` 成功路径无返回值。
3. 核查并修复 485 侧 ROM 命令从 `TxBuffer` 解析请求字段的问题。
4. 修复干接点过流报警 `(BIT4 & BIT5)` 判断。
5. 为 232 转 485 单播转发增加等待响应超时恢复。

发布建议：当前不建议直接发布量产版本。完成上述代码修正后，应至少补做 232 客户工具全命令回归、485 主从转发单播/广播/无响应测试、干接点两路输出实测、断电后干接点参数保持测试，以及 SOH 字段偏移验证。
