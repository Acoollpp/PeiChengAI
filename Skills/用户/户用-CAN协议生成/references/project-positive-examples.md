# 项目正例索引

> 用途：`can-codegen-v1` 提供“可参考、但不得无条件照搬”的项目内正例索引。
> 本文件是白名单 / 灰名单 / 黑名单的唯一主表。
> 使用方式：先完成协议类型判定，再按“同类型优先、同结构优先、同字段优先”的顺序选择参考文件。

---

## 1. 使用原则

1. 先判协议类型，再查正例索引；不要反过来先看代码再猜协议类型。
2. 优先选择与当前协议同类型的正例文件。
3. 只能参考索引中明确标注的“适用点”，不能把整份文件无差别照搬。
4. 若当前协议与正例在架构上不同，只能借鉴局部风格，不得借鉴发送骨架。
5. 若同一个问题已有多个正例，优先选择更接近当前协议文档定义的那一个。
6. 白名单可作为骨架候选；灰名单只能局部参考；黑名单只可用于理解该协议，不得进入默认模板选择。

## 5. 字段写法正例

### 5.1 现成参数优先

| 文件 | 适用点 |
|------|------|
| `@InverterCANProtocol/Can_Aiswei_V100.c` | 总容量直接使用 `InverterData.FccAll` |
| `@InverterCANProtocol/Can_Pylon.c` | `Gmin/Gmax/Tmin/Tmax/FccAll` 等现成字段直接取值 |
| `@InverterCANProtocol/Can_Wow_V100.c` | 32 位容量字段直接拆分写 4 字节 |
| `@InverterCANProtocol/Can_Zlpower_V100.c` | 总容量优先用 `FccAll`，不先回退到推导值 |
| `@InverterCANProtocol/can_Growatt_V109.c` | `DeltaV`、`GmaxAddr / GminAddr`、`TmaxAddr / TminAddr` 等现成字段直接取值 |

| `@InverterCANProtocol/Can_CanadianSolar_V101.c` | `PackNum` / 保护包数等 `uint8_t` 字段映射 2 字节协议槽位 |

## 7. 推荐筛选顺序

1. 先看 `A/B/C/D` 协议类型是否一致。
2. 再看是否属于“基础轮询 / 系统级轮询 / 功能帧扩展 / 扩展帧命令”中的同一子类。
3. 再看命中的是白名单、灰名单还是黑名单。
4. 最后再看字段层面是否同类，例如地址编码、容量字段、极值字段、字符串字段。

## 8. 使用输出格式

当引用本索引中的项目正例时，建议在生成摘要中写清楚：

```text
项目正例参考：
- 参考文件：Can_Pylon.c
  名单级别：白名单
  参考范围：基础轮询骨架、极值帧、容量帧
- 参考文件：Can_Pylon_V130.c
  名单级别：灰名单
  参考范围：V1.3 版本差异点、有符号字段、0x1001 心跳差异
```

## 9. 维护规则

1. 新增正例前，先确认该文件属于白名单、灰名单或黑名单中的哪一类。
2. 每条正例必须写清楚“适用点”和“限制条件”，不能只列文件名。
3. 如果一个文件只适合局部参考，必须显式写为灰名单或黑名单条件例外。
4. 若某文件后续被认定含有较多历史兼容或不推荐写法，应从白名单降级到灰名单，或直接移入黑名单。
