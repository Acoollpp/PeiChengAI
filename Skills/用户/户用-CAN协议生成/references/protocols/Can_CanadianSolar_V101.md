# CANADIANSOLAR V1.0.1

> 协议来源：`264-CANADIANSOLAR CAN V1.0.1.pdf`
> 项目参考实现：`assets/examples/Can_CanadianSolar_V101.c`
> 协议类型：`D. 混合型（基础轮询 + 系统级轮询分组）`
> 参考级别：`灰名单`

---

## 1. 协议概览

| 项目 | 内容 |
|------|------|
| 通信方向 | BMS→逆变器 |
| 帧格式 | 标准帧，DLC = 8 |
| 发送机制 | 基础轮询 + 系统级轮询段 |
| 接收机制 | 无明显独立命令应答层 |
| 版本特征 | 混合型、多层次、地址 ASCII 编码明显 |

---

## 2. 使用边界

- 适合作为“基础轮询之后继续发送系统级分组帧”的参考。
- 可直接参考：
  - 基础轮询段与系统级轮询段的拆分实现
  - `0x35A` 系统状态分组帧
  - `0x374~0x377` 地址 ASCII 编码
  - `tmp / wtmp / lwtmp` 在字段复用较多场景中的使用方式
- 不可无条件外推：
  - 完整状态流
  - 固定品牌字符串与补位字符
  - 所有系统级扩展帧的数量和顺序

## 3. 报文结构

### 3.1 基础发送帧

| CAN ID | 方向 | 说明 |
|------|------|------|
| `0x351` | BMS→逆变器 | 充放电限值 |
| `0x355` | BMS→逆变器 | SOC / SOH |
| `0x356` | BMS→逆变器 | 模拟量 |
| `0x359` | BMS→逆变器 | 保护 / 告警 |
| `0x35C` | BMS→逆变器 | 控制请求 |
| `0x35E` | BMS→逆变器 | 品牌 ASCII |

### 3.2 条件发送帧

| CAN ID | 条件 | 说明 |
|------|------|------|
| `0x35A` | 协议定义 | 系统状态分组帧 |
| `0x374` | 协议定义 | 地址 / 节点 ASCII 信息 |
| `0x375` | 协议定义 | 地址 / 节点 ASCII 信息 |
| `0x376` | 协议定义 | 地址 / 节点 ASCII 信息 |
| `0x377` | 协议定义 | 地址 / 节点 ASCII 信息 |

### 3.3 接收 / 应答帧

无。

---

## 4. 关键差异与特殊处理

- 保护、告警、系统状态被拆到多个独立函数中，再组合到不同报文。
- 地址字段不是直接数值发送，而是转成 ASCII 数字并结合空格补位。
- 16 位、32 位字段在确有复用和拆包需求时使用 `wtmp / lwtmp`。
- 与基础轮询模板相比，本文件更适合参考“如何拆层”，而不是直接做默认骨架。

---

## 5. 关键数据源

- 地址类字段
- 多组状态位来源
- 需要拆分发送的 16 / 32 位字段

## 6. 生成提示

- 只有在协议文档明确要求系统级扩展帧时，才参考 `0x35A`、`0x374~0x377` 这一层。
- 如果目标协议只是普通轮询型，不应被本文件复杂的分层结构带偏。
- 若只是借风格，优先借“拆层思路”和 ASCII 地址编码，不要借整套状态机制。
