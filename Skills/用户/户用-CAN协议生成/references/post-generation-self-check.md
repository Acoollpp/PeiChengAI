# 生成后自检清单

用于在协议代码生成完成后做一轮快速人工复核，确保协议正确性、数据源选择和代码风格都符合 `can-codegen-v1`。

---

## 1. 协议完整性

- [ ] 协议文档中所有 TX 报文均已在 `SendCycleMsg` / `switch(SendMsgIndex)` 中体现。
- [ ] 协议文档中所有 RX 报文在 `ReceiveIRQ` 中均有对应处理入口；即使暂未实现，也要有空桩 `TODO[未实现]`。
- [ ] 每个报文的 `StdId` / `ExtId`、DLC、方向、周期与协议文档一致。
- [ ] 报文发送顺序与协议文档定义一致，最后一帧能正确将 `SendMsgIndex` 置回 `0`。

## 2. 字段与数据源

- [ ] 协议文档需要的数据，优先使用 `InverterData` / 逆变器参数表中的现成字段。
- [ ] `InverterData` 中已有现成字段时，没有再用推导值去替代。
- [ ] 若协议字段已定义但数据源缺失，已明确标注 `TODO[未实现]`，没有静默省略。
- [ ] `uint8_t` 字段映射到 2 字节协议槽位时，高字节直接写 `0`，没有写 `value >> 8`。
- [ ] 单个表达式即可直接得到结果的字段，已直接写入 `Data[x]`，没有多余临时变量。

## 3. 字节拆分与类型

- [ ] `uint16_t` / `uint32_t` 字段按 Intel 小端正确拆分。
- [ ] 需要按 `int16_t` 发送的字段已按有符号 16 位补码写入。
- [ ] 强制类型转换统一写成 `(uint8_t)(expr)` 形式。
- [ ] ASCII / 字符串字段直接写字符字面量，如 `'P'`，未做多余 `(uint8_t)` 强转。

## 4. 风格与结构

- [ ] 每个 `case` 中 `Can_msg_Tx.StdId = 0xXXX;` 都放在最上面。
- [ ] 报文轮询索引变量统一命名为 `SendMsgIndex`。
- [ ] 临时变量只使用 `tmp` / `wtmp` / `lwtmp` 等既有风格命名，不使用 `flags`。
- [ ] 保留字节逐个显式写出，未使用 `memset` 批量清零。
- [ ] `Can_msg_Tx.Data[x]` 默认直接在 `case` 中展开填写，没有额外封装单帧辅助函数。

## 5. 安全性与可维护性

- [ ] `default` 分支已做异常保护，不会因错误索引误发旧帧。
- [ ] 所有位操作统一使用 `BIT` 宏，没有 `0x05`、`0x0A` 这类魔法数位掩码。
- [ ] 未使用的变量、参数、分支已清理，不引入明显编译告警。
- [ ] 协议中的特殊功能（握手、心跳、超时、地址、版本协商、扩展帧触发）均已实现或显式标记 `TODO[未实现]`。
