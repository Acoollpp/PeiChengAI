# 生成流程与落点

## 1. 输入协议文档后先做什么

先从文档里提取：
- 帧方向
- 报文 ID
- 标准帧 / 扩展帧
- 周期 / 应答 / 事件触发
- 数据长度
- 字节映射
- 校验与分包

然后对照当前工程，判断它落在哪条链路：
- 发送链路
- 接收链路
- 上层命令链路

## 2. 三类典型落点

### A. 发送链路

命中条件：
- 文档主要定义 BMS 往外发哪些帧
- 给了 ID、周期、字节映射

默认落点：
- `User/Can_Manage.c`

常见动作：
- 补帧头字段
- 补 `Identifier`
- 补 `DLC`
- 补 `Data[0..7]`
- 必要时补周期调度

### B. 接收链路

命中条件：
- 文档定义外部设备回传给 BMS 的帧
- 需要组包、校验、状态更新

默认落点：
- `User/Can_Manage.c`

常见动作：
- 在接收重组逻辑中识别帧类型
- 解析 ID 和序号
- 拼接数据到 `Can_ParseBuffer`
- 触发上层响应

### C. 上层命令链路

命中条件：
- 文档定义某些命令、查询或返回字段
- 最终要从 EM 协议口对外暴露

默认落点：
- `User/Protocol/EM_Uart_Protocol.c`

常见动作：
- 新增命令处理分支
- 修改返回字段
- 补协议编码、版本、数量等对外内容

## 3. 何时允许新建文件

只有同时满足以下条件才建议新建独立 `.c/.h`：
- 协议文档对应的是一整块相对独立逻辑
- 现有 `Can_Manage.c` 已明显不适合继续承载
- 新文件最终仍能被现有真实入口调用

如果只是新增几帧、几个命令、一个解析分支，默认不要拆新文件。

## 4. 输出时必须写清楚

每个改动点都要写：
- 触发条件
- 修改动作
- 参考来源
- 禁止事项

不要只列文件名。
