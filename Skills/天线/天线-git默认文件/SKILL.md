# 天线-git默认文件

## 概览

这个 skill 的默认目标不是只分析规则，而是直接在当前项目根目录生成一份可用的 `.gitignore`。
生成内容要按并集规则融合当前工程根目录规则和 `bms_protocol_V109` 局部规则，也就是文件1和文件2里出现过的规则都要保留到最终模板里，只去掉完全重复项。

## 快速入口

优先读取这两份来源文件：

- `ql-application/threadx/project_general/.gitignore`
- `ql-application/threadx/project_general/User/bms_protocol_V109/.gitignore`

如需直接复用已经整理好的合并模板，再读取：

- `references/默认gitignore模板.md`

## 默认行为

当用户调用这个 skill，且没有额外说明其他目标路径时，默认执行下面动作：

1. 读取当前工作区里的两份来源 `.gitignore`
2. 按并集合并规则，并只去掉完全重复项
3. 在当前项目根目录生成 `.gitignore`
4. 向用户说明最终文件已经包含文件1和文件2的全部规则，以及哪些条目来自各自独有规则

这里的“当前项目根目录”指用户当前正在操作的项目根，不是固定写死到某个历史目录。

## 合并规则时的要求

### 1. 先明确并集原则

最终模板必须满足下面原则：

- 文件1里有的规则必须保留
- 文件2里有的规则必须保留
- 两份文件共同拥有的规则当然也必须保留
- 只允许删除完全重复的同一条规则
- 不允许因为“兼容”“精简”或“看起来没用”而删掉任何一边独有规则

### 2. 再识别共同规则

优先识别两份文件都已有的规则，例如：

- 补丁和冲突文件
- 临时编辑文件
- 编译中间产物
- 调试历史
- `core` 与 `!core/` 这一组成对例外规则

### 3. 再补双方特有规则

合并后要补齐下面这些差异项：

- 来自工程根目录规则：`*.bin`、`*.json`、`threadx/ota_tool/a/customer_app.bin`
- 来自 V109 目录规则：`out_arm`、`Debug`、`settings`、`EWSTM32`

如果最终模板里缺少这些差异项中的任何一条，就说明合并结果不合格。

### 4. 去重但不破坏语义

允许删除完全重复的规则。
不要为了“整洁”破坏下面这些语义：

- 分组结构
- 空行分隔
- `core` 与 `!core/` 的配对关系
- 明确指定的单文件路径规则

### 5. 生成位置默认是项目根目录

如果用户没有特别说明输出到别处，默认在当前项目根目录创建：

- `.gitignore`

不要默认写到 `User/bms_protocol_V109/` 下面，也不要只修改现有某一份来源文件，除非用户明确要求。

## 生成文件时的输出要求

生成后优先向用户说明：

- 文件生成位置
- 合并了哪两份来源规则
- 最终文件是否满足“文件1和文件2规则并集全部保留”
- 新文件里额外保留了哪些当前项目特有目录
- 是否发现来源文件之间存在重复项或差异项
