## 快速判断模板

### 用户说“新增一个命令/功能”

先检查：

1. 是否已有类似命令可以复用
2. 是否需要新增 `group_id`
3. 是否需要新增 request/response
4. 是否已经挂到路由表
5. 是否需要新增 parse
6. 是否写回管理结构

如果用户进一步要求“直接生成骨架”，继续检查：

7. 是否需要同时补 `conver` 与 `handle`
8. 是否能复用现有 parse 入口
9. 是否需要保留 `TODO[待补协议细节]`

### 用户说“代码写了但没生效”

先检查：

1. 入口是否真的执行
2. 状态判断是否拦截
3. 路由表是否漏挂
4. response 是否拿错 `data` 起始位置
5. 解析结果是否落库
6. 上层读取是否读到这份数据

### 用户说“不知道该改 conver 还是 handle”

快速判断：

- 改命令流程、验包、收发、分发，优先看 `conver`
- 改字段拆解、字节序、单位换算、管理结构落点，优先看 `handle`

## 常见漏改点

- 只新增函数，没有挂路由表
- response 里数据偏移取错
- 只判断 `len == 0`，没有做最小长度判断
- 解析后没有写入正确管理结构
- 有协议模式差异，但没有同步处理分支
- 只生成了 request/response，没有补声明和路由表
- 只补了解析函数，没有补管理结构落点说明
