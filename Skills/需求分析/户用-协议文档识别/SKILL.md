# 户用-协议文档识别

## 目标

将历史协议文档转成可检索、可比对、可复用的结构化知识库，并在收到新文档时快速判断：
- 属于旧协议迭代（可复用）
- 属于全新协议（需新建实现）

## 执行流程

1. 先建立或更新知识库  
执行 `scripts/build_protocol_kb.py`，默认扫描项目根目录下 `485_doc` 与 `can_doc`。  
输出：
- `references/protocol_kb.json`
- `references/protocol_summary.md`

2. 再识别新输入文档  
执行 `scripts/identify_protocol.py --doc <新文档路径>`。  
输出：
- 是否判定为新协议
- 最相似历史协议 TopN
- 证据特征（厂家、协议类型、版本、CAN ID/寄存器关键词）
- 推荐参考协议路径

3. 给出编写建议  
基于最相似协议，输出“优先复用协议”和“需要新增/变更点”。

## 命令模板

```bash
python scripts/build_protocol_kb.py --project-root "E:/户用项目/21939-V300-公版/工程文件（032）/SST22-1939-V3.00"
python scripts/identify_protocol.py --doc "E:/path/to/new_protocol.pdf"
```

## 判定规则

- 若相似度最高 `>= 0.78`，且关键厂家/协议类型一致，优先判定为旧协议分支。
- 若相似度最高 `< 0.55`，判定为新协议。
- 中间区间输出“待人工确认”，并列出差异证据。

## 结果输出规范

- 必须给出可落地的参考文档路径（至少 1 份，建议 3 份）。
- 必须列出判断证据，不只给结论。
- 若源文档无法解析正文，必须明确说明并改用“文件名特征 + 元信息”降级判断。
